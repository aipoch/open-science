# 通用研究 Replay 实施计划

本文记录完整实施设计与验收要求。日期：2026-09-29。最初代码核对基线：bda7505bd。

当前状态：实现已提交 [PR #3140](https://github.com/aipoch/open-science/pull/3140)，并纳入上游 f9ab83777。下述阶段与验收门槛保留为设计依据；逐项证据、实际测试结果和验证限制见 [验收记录](research-replay-validation.md)，合并与发布状态以 PR 为准。

本计划以本次讨论确定的交互为准：导入后仍从同一个研究入口进入，左侧可以提问和操作，右侧默认展开 Replay；使用现有 .science 内容，允许展示模拟和材料缺失；从第一期就为未来导出 MP4 保留共用的时间轴和画面渲染能力。

## 1. 本期交付与边界

本期完成可实际使用的“导入—观看—提问—恢复”完整流程。

- 兼容当前可导入的 .science 包，不修改包的 schemaVersion、manifest、归档结构或原始字节，不要求重新导出。
- 提供通用的对话、工具活动、Notebook 代码与输出、文件和图表回放；不编写项目专用实验动画或日志解释器。
- 同一研究入口下组合只读来源与可写讨论，新增消息和产物有独立归属。
- 右侧首次默认展开 Replay，保持暂停；再次进入恢复分支与进度，仍保持暂停。
- 支持播放、暂停、前后步骤、进度拖动、倍速、分支选择、查看证据、询问当前步骤和引用定位。
- 允许压缩等待、模拟面板切换、滚动及渐进展示；真实记录、展示重建和材料缺失可以辨认。
- 实现独立渲染时钟、固定尺寸布局和资源就绪机制，并验证可按指定时间稳定呈现画面。

后续独立交付：MP4 编码与导出任务、音轨或配音、任意时间点的运行环境恢复、专用实验动画、跨设备重建，以及更完整的原始交互采集。第一期不出现不可用的“导出 MP4”按钮。

观看不启动模型、Notebook 内核或复算。用户发送问题才进入正常智能体流程；修改实验或复算采用已有可写副本流程。导入原会话的底层只读保护继续生效。

## 3. 确定的用户流程

### 3.1 导入与首次进入

1. 完成现有校验、导入及只读来源建立。
2. 打开统一研究入口，右侧自动选中“研究回放”，显示来源、可用记录和播放按钮。
3. 左侧显示针对这份研究的讨论草稿，来源引用可见；初始介绍由元数据和可用操作组成，不自动请求模型生成摘要。
4. 观看和浏览不创建空讨论会话；首次发送问题时再建立关联的可写讨论。
5. 若用户在导入完成前已切往其他位置，完成事件不得抢回焦点；沿用导航意图和版本校验。

### 3.2 观看

- 回放画面位于右侧标签内部，包含历史对话、工具记录、代码和结果；播放控件也留在右侧。
- 底部提供上一/下一步、播放/暂停、时间进度与步骤进度、速度和询问此步骤。初始速度 1×，第一期提供 0.5×、1×、1.5×、2×。
- 顶部显示研究名称、选定分支及“根据归档记录重建”。实际事件时间与观看时间分别呈现。
- 手动检查回放内容、拖动进度或切分支时暂停；继续播放时重新对齐当前步骤。播放器自动滚动不触发该暂停规则。
- 右侧可以展开证据详情；打开较大的原始文件可以使用相邻预览标签，Replay 保留位置。切离 Replay 标签时暂停，不关闭左侧讨论。
- 左侧讨论正常运行、接收回答，不由播放时钟驱动，也不会被历史消息替换。
- 回放结束提供查看结果、重新观看和创建副本继续研究。无可播放历史时说明原因，仍允许查看文件和讨论材料。

布局示意：

```text
项目 / 研究入口        当前讨论                         研究回放（默认打开）
                      讨论对象与来源引用               来源 / 分支 / 重建说明
研究 A（选中）         新问题与智能体回答               历史对话与工具活动
研究 B                 已发送的固定步骤引用             当时的代码、输出、文件版本
                      输入框 / 当前步骤引用             播放 / 进度 / 查看证据 / 询问
```

首屏直接提供“播放研究过程”“查看研究材料”“在左侧提问”三个可理解的入口。材料不足时显示可观看范围，例如“包含对话和结果，部分操作过程未保存”，不让用户面对空播放器自行猜测。

“归档记录”“展示重建”“材料缺失”标记应落到具体步骤和材料上。历史记录中的执行中、待确认或错误只表示归档时状态；当时的确认和重试按钮以记录方式展示，不呈现为当前可执行操作。

右侧保留来源详情：导入时间、原项目与原会话、来源指纹和导出时排除的文件清单。“导出时主动排除”“原记录未保存”“本次读取失败”分别说明，不能统称为内容为空。

回放应呈现 Open-Science 的交互内容及其前后联系，采用熟悉的对话、工具活动和工作区展示方式。具体覆盖范围如下：

| 内容                                         | 呈现规则                                             |
| -------------------------------------------- | ---------------------------------------------------- |
| 用户提问、智能体回答、已保存的工具输入与结果 | 使用归档原文，保留原始记录入口；界面摘要明确标识截断 |
| Notebook 代码、输出、图表与文件变化          | 绑定实际运行和确切版本；只有最终版本时不补造编辑过程 |
| 已保存的授权、确认、失败与重试               | 作为当时的交互记录展示；记录没有包含的决定保持未知   |
| 展开面板、滚动、逐步显示文字、等待时间压缩   | 根据统一规则重建，属于观看效果，不声称是原始操作录像 |
| 未保存的鼠标动作、逐键输入、精确窗口布局     | 不承诺还原；必要时说明该部分未记录                   |

### 3.3 提问与操作

- 左侧默认带来源引用。针对当前画面的问题使用清楚可见的步骤引用。
- 点击“询问此步骤”，或启用“引用当前步骤”时开始输入，暂停并捕获步骤。草稿中的引用不再随播放变化；发送时保存该快照。
- 用户可以移除步骤引用，讨论整份研究。已发送问题保留来源、分支、原始条目和确切文件版本，以及必要的有界摘录。
- 回答所关联的步骤引用可以点击定位回右侧；源材料不可用时明确提示，不能打开另一版本顶替。
- 本期支持查看、引用、比较记录，以及通过明确步骤链接定位。若智能体需要直接操纵播放器，另增加仅控制播放/定位/打开证据的受限查看接口，不将实验执行接口接到历史按钮上。
- 修改代码、复算或继续实验进入现有 Fork/验证流程，名称使用“创建副本继续研究”。不提供“恢复这一时刻的环境”。

若左侧处于研究 A、右侧仍显示研究 B，点击 B 的“询问此步骤”先保存 A 的草稿，再进入 B 的关联讨论并附上 B 的引用。导航或加载失败时保留待提问上下文并提示，不向 A 插入或发送 B 的问题。单击一条已发送的步骤引用只定位右侧证据，保留左侧正在阅读的讨论；再次点击“询问此步骤”才切换到该来源的讨论。

### 3.4 重新打开

从同一个研究入口恢复既有讨论与对应 Replay，并保持暂停。普通重新渲染不重复强制打开被用户刚关闭的标签；再次主动打开研究入口时默认选中 Replay。窗口宽度、分栏大小沿用现有布局偏好；窄窗口使用现有预览展开方式，在讨论与回放间切换。

主动进入研究时，同时展开被折叠的右侧预览栏。Replay 提供明确的展开/收起入口，控件使用正常界面字号，不能随固定画布缩成不可操作的小按钮。固定画布只负责历史场景；正文过小时可展开阅读或打开原始证据。窄窗口中点击“询问”应切回讨论并聚焦输入框，再回 Replay 时保留位置和暂停状态。验收包含正常分栏与最小支持窗口尺寸中的可读性、键盘和焦点返回，不能只验 1280×720 独立截图。

## 4. 工作区身份与本地持久化

引入仅作用于导入研究的 SessionReplayController，明确三个身份：

| 身份                | 负责内容                                                     |
| ------------------- | ------------------------------------------------------------ |
| entrySessionId      | 用户打开的研究入口、来源标题、侧栏选中项                     |
| sourceSessionId     | 原始历史、原始文件及右侧 Replay                              |
| discussionSessionId | 新问题、回答、智能体运行、权限、草稿及新产物；首次发送前为空 |

entrySessionId 初期等于 sourceSessionId。保持现有 selectedSessionId 的实际对话目标语义；不能仅替换显示的 activeSession，而让发送、停止、权限确认、附件或草稿仍指向来源。

侧栏将来源与关联讨论呈现为一个研究入口，运行中、错误和未读状态取自讨论；来源只读标识属于来源。关联讨论仍是可检索、可恢复的普通会话，在其他检索结果中标明关系，避免产生不可访问的隐藏记录。

统一入口的菜单必须固定操作对象，不能根据当前内部选中会话而变化：

| 操作                       | 对象与呈现                             |
| -------------------------- | -------------------------------------- |
| 重命名、置顶研究入口       | 来源的组织元数据，不改原始研究内容     |
| 停止当前回答、处理权限     | 关联讨论中的当前运行                   |
| 导出原研究 .science        | 来源，沿用现有导出规则                 |
| 导出当前讨论               | 单独命名的讨论操作，按既有规则处理引用 |
| 归档原研究、删除原研究     | 来源；解释已有讨论会保留               |
| 归档当前讨论、删除当前讨论 | 单独命名的讨论操作，不影响来源         |

侧栏显示状态与菜单能力分别计算，不能把讨论的运行状态复制进来源 Session 后交给现有操作分发器。

新增应用本地数据：

- ResearchDiscussionLink：projectId、sourceSessionId、discussionSessionId、创建/恢复状态和修订号；以项目和来源为唯一键。
- ReplayViewState：来源身份、生成器/展示配置版本、分支、稳定步骤 ID、步骤内位置、速度和修订号。不同窗口各自播放，暂停/退出等检查点保存；不以每帧写数据库或远程更新驱动另一窗口跳转。
- 首次讨论草稿使用来源专属作用域，例如 research:<projectId>:<sourceSessionId>，并以独立 draftId、窗口编辑身份和修订号区分同一来源的多份草稿。复用现有编辑器结构，但不能将内存或 sessionStorage 视为应用重启后的持久保证；研究草稿需有应用本地恢复记录。
- SessionDiscussionSnapshot：以本地草稿标识或已保存消息 ID 关联固定步骤快照；用于既有引用类型无法覆盖的独立 Notebook 步骤及重启后定位，不改变消息或包协议。

这些关系存应用数据库，通过主进程接口读取和更新，不写入 .science 或原始会话内容。新表使用项目归属与显式清理；Session 表是可重建投影，不应为关联添加依赖该投影存活的级联外键。

不同窗口的未发送草稿不相互覆盖。重启发现多份草稿时提供恢复入口，不自动合并或发送；正在编辑的新草稿优先于迟到的恢复结果。来源草稿迁移到讨论时保留 draftId 与修订关系，已提交的发送快照和用户继续输入的新草稿分别保存。

观看检查点通过修订号避免旧窗口覆盖新状态。发生冲突时保留本窗口画面并提示，不盲目重试覆盖另一窗口；下一次明确的用户播放或定位操作可以在重新读取修订后保存。切换来源、重新加载或卸载后，旧保存请求不得更新新播放器的状态或修订号。

会话内容在文件中，关系在数据库中，不能假定一个 SQLite 事务能够原子创建二者。首次发送采用持久化创建意图、预留稳定讨论 ID、现有会话创建入口、关联确认的顺序，并支持幂等恢复。重复提交同一发送意图不能重复发消息；两个不同问题并发提交时复用一个讨论，沿用现有排队规则保留两条问题。

讨论创建与消息接收是两个独立确认点。首次发送先保存带稳定发送意图 ID 的草稿快照，涵盖文字、附件、证据和步骤上下文；讨论建立后向现有运行所有者交接。只有消息或持久队列确认接收后才清除对应快照并完成草稿键迁移。后续输入使用新的草稿修订，迟到的成功或失败不得清除、覆盖新输入。

若既有多窗口发送入口不能接收另一窗口的问题，则在本地发送协调层补持久待发送记录并由当前运行所有者顺序接收；不能仅测试讨论创建幂等，也不能把第二个首问静默丢弃。失败或所有权冲突时，问题和附件保留在来源专属待发送记录并显示重试入口。接收状态不明时展示待核实状态，不自动再次调用模型。

队列确认接收前，临时附件必须转换为具有明确归属的持久资源版本，不能只保存临时路径或上传回执。发送完成后由实际消息引用保留；取消待发送项、丢弃草稿或删除项目时通过现有资源清理协调释放，其他草稿或消息仍引用的附件不得误删。

发送状态至少区分已保存待发送、已由运行所有者认领、已开始派发、已确认接收、明确失败和结果未知。稳定发送意图 ID 与消息 ID 用于核对和去重，但“已有用户消息、没有回答”不足以证明可以重新派发。明确未开始请求的失败允许重试；已经派发而确认丢失的情况先核实，不能自动重复调用模型。核实无果时保留问题并让用户明确选择后续动作。

崩溃恢复只协调本地已保存状态，不自动重放不确定是否已发出的模型请求。源/讨论关联不完整时保留草稿并给出可恢复错误。

## 5. 回放数据模型与生成规则

增加包协议之外的派生 ReplayDocument。它包含来源指纹、生成器版本、分支目录、步骤、资源目录和缺失说明。可以缓存，但缓存可删除重建；原始记录仍是事实来源。

ReplayStep 至少包含：稳定 ID、类型、源会话/Frame/分支、原始记录定位、所属提问或因果关联、记录状态、真实时间、观看时长、相关资源版本以及完整程度。

生成规则：

1. 从现有主进程读取接口加载完整的所选分支索引，保留分页边界；不把当前 UI 已加载的尾部误当完整历史。
2. 沿用现有权威对话顺序及分支祖先关系，再按已记录的执行标识关联 Notebook 与产物。
3. ID 使用记录类型、原始记录 ID 和明确的展示阶段组成，不依赖数组下标、文件名或时间戳。来源、缓存和检查点身份同时使用 projectId、sourceSessionId 和 fingerprint；相同包重复导入也必须隔离，因为本地 ID 会重新映射。第一期保证同一次导入的重开稳定，不跨重新导入合并身份。
4. 同一次执行的工具记录与 Notebook 记录按确切运行标识合并展示，保留双方来源引用。关联不充分时分别展示，不能猜测成同一运行。
5. 父子与并行关系保留；并行活动可作为一组展开，不推导未记录的严格先后。不同分支分别播放，不按时间混成一条历史。
6. 产物绑定确切版本及生产运行。有歧义则标为相关材料；版本缺失时提示缺失，不回退到最新版本。
7. 截断文本、缺失环境、缺少附件及缺少精确时间分别记录，不阻止其他步骤播放。
8. 自定义 JSON/日志作为普通材料预览，不自动生成领域动画。

多个分支可能共享同一提问，promptMessageId 不能独自证明运行所属分支。对于从工具活动处分出的分支，保留其确切截断边界；优先依据已保存的执行关联，仍有歧义的记录进入“未归属材料”，不硬塞进当前分支。

资源读取按需进行，优先加载当前及邻近步骤；设置缓存和并发上限。切换来源、分支或快速拖动后，旧请求的结果不得覆盖当前画面。时间线索引稳定后开始播放，附件后续加载不改变已经确定的步骤 ID 与顺序。

完整索引与大负载分开：现有 Notebook 分页可能返回完整运行内容，索引阶段逐页处理后只保留顺序、关系、状态、长度和摘要，代码与大输出通过已有 runIds 查询按需回读。不要让“完整分页”变成全部历史负载常驻内存。若现有摘要接口不足，再补只读摘要接口，仍不改归档内容。

## 6. 播放引擎、历史画面与 MP4 基础

区分三种时间：真实事件时间、逻辑顺序、观看时间。缺少真实时间时保留未知；观看时长使用版本化的固定规则，根据内容类型和长度计算并设置上下限。默认压缩空白等待，提供真实耗时说明。

时间字段按语义取证：消息 completedAt、Notebook endedAt 可以用于相应完成时间；工具 updatedAt 只证明记录曾被更新，不能直接作为真实完成时间计算执行耗时。

建议划分：

- ReplaySourceReader：读取来源、运行、版本和缺失信息。
- ReplayTimelineBuilder：纯数据生成 ReplayDocument。
- ReplayController：管理准备、暂停、播放、结束与可恢复错误，以及 seek、速度和分支。
- ReplayScene：给定文档、分支、逻辑播放时间及展示配置，生成当前画面状态。
- ReplayStage：使用只读组件呈现该状态。
- ReplayPanel：右侧标签、工具栏、证据检查和提问动作。

核心契约为“同一文档、分支、时间和展示配置得到同一画面状态”。跳转直接求当前投影，不通过反复执行历史动作完成；后退时不能残留未来消息、代码、图表或状态。

合并后的执行步骤仍区分输入/代码、活动过程、保存结果三个展示阶段，仅显示当前阶段已达到的证据；没有中间记录时用明确的展示过渡连接已有输入与结果。阶段时长、文本渐进比例和结果出现位置属于版本化展示规则。询问快照同时保存所选步骤、步骤内位置和当前可见证据；完整步骤的其他记录可作为补充读取，但回答需说明其来源，不能把后续结果说成当时已经可见。

当前可见证据包含整幅场景中保留显示的材料，例如当前对话旁仍可见的上一段 Notebook 代码或图表。快照保留这些材料的真实记录与版本引用，而不只保存当前步骤新增的条目；摘录仍有明确长度上限。跳转回引用时恢复相同时间位置及证据组合，原始材料不可读则明确降级。

渐进文本、面板过渡和自动滚动都由显式播放时钟计算。真实时钟仅用于交互播放器推进逻辑时间；核心画面不读取 Date.now、随机数或未受控的 CSS 动画进度。速度改变时间推进，不重写研究耗时。

复用现有消息、工具、Notebook 输出和文件渲染组件的展示层；有实时环境订阅、执行回调或写入动作的部分必须拆开。ReplayStage 不挂载完整活动 Workspace，不把伪造运行状态写进全局会话 store。历史确认、执行与重试作为已发生记录展示；原始未保存的决定不补造。

允许模拟展示节奏、展开、滚动和面板切换；不生成不存在的提问、实验输出、审批决定或研究结论。原始日志中的指令只是证据内容。

为 MP4 本期必须实现：

- 画面与播放/提问控件分离，Stage 可在独立宿主中装载，不依赖左侧讨论或当前鼠标位置。
- 固定逻辑视口与字体/主题/布局配置，交互窗口可缩放显示同一场景；首期用 1280×720 作为可采帧验证配置，保留可配置能力。
- 展示配置同时冻结语言、时区、数字/日期格式、字体回退与文本换行规则；资源默认来自包内确切版本。外部网页和当前网络响应不参与确定性画面。
- seek(time) 后有明确的资源及布局就绪信号；图像解码、字体和异步预览完成后才能采帧。
- 缺失、损坏和不可稳定预览内容使用确定的占位或冻结预览。就绪等待有超时和诊断，不无限卡住。
- 资源清单记录确切版本、可用校验和及展示方式；同一场景内已确定的缺失处理保持稳定，重试通过显式重新准备完成。
- 对同一构建、字体、浏览器和资源配置，在固定软件栅格化的独立采帧宿主中验证逐帧推进与直接定位的 PNG 逐字节一致。宿主在 Electron ready 前禁用硬件加速，并验证软件合成状态；普通交互工作区保留 GPU 加速。GPU 绘制缓存可能使冷、热帧圆角边缘的抗锯齿像素不同，因此不将实时 GPU 窗口的像素一致性作为此项保证。第一期也不承诺跨操作系统像素完全相同。

就绪信号必须绑定来源身份、分支、时间、展示配置和准备批次，旧批次完成不能解锁新画面。遇到必须等待的资源时冻结交互播放器的逻辑时间，显示准备状态；资源就绪或按规则降级后才继续。采帧宿主同样等待该时间点的就绪结果。资源就绪与采帧就绪分离：交互时钟只等待资源，采帧则在该逻辑帧的布局和降级占位提交后跨越绘制边界；快速 seek 必须取消旧帧的等待，不能由旧位置放行新位置。超时确定的占位在本次准备批次内保持不变；用户显式重新准备才允许替换，并重新计算就绪。就绪结果附带缺失/降级清单，便于后续导出前确认。

普通图像、文本、代码、表格和已保存 Notebook 输出优先支持稳定呈现。PDF/Office/HTML 等复杂预览需要独立验证资源就绪；外链和活动媒体不能默认视为可离线采帧，必要时回退到有说明的静态内容。

科研常用 SVG 图表列入首期：静态化后呈现或生成冻结预览，隔离脚本、动画和外部引用并等待图像解码。过大文本或表格提供有说明的分页/截断及查看原文件入口；不能把被省略的输出标成完整内容。

## 7. 左侧提问与步骤引用

新增 ReplayContextBridge，将选中步骤转为已有来源引用及证据引用。引用至少保存来源会话、分支、原始条目、运行/文件版本和有界摘录；跳转使用稳定来源定位，步骤生成器变化时仍可打开原始证据。

优先复用现有 SessionReference、消息/工具条目注释、文件版本引用和宿主读取接口。若恢复播放器需要额外映射，使用本地消息到步骤的关联记录，不向 .science 强加新字段。

现有注释类型没有独立 notebook-run 来源，因此只在确有消息、工具条目或文件版本关系时复用相应注释。无对应条目的运行使用真实来源会话引用、有界摘录及 SessionDiscussionSnapshot 本地映射；不能将 runId 假装成工具活动 ID。独立运行的“询问此步骤”仍需可用并能在重启后定位。会话引用与注释数量遵守现有限额，超限时给出可调整的提示，不静默截掉当前研究来源。

问题消息本身保留可理解的来源名称、真实记录/运行/版本标识及有界摘录；本地 SessionDiscussionSnapshot 补充精确定位能力，不是理解问题的唯一依据。讨论被单独导出或本地映射丢失后，保留可读内容并提示“此设备无法定位该回放”，不把本地定位保证当作跨设备能力。

提问只读取问题所需证据，不把整个包无条件塞进上下文。读取失败应说明，不能用模拟展示推测原始结果。跨会话引用可读取整份来源，本期不宣称其自动构成“只能知道当前时刻之前”的硬隔离；回答引用后续记录时要明确来源。

发送、停止、模型选择、权限确认、附件和新产物归 discussionSessionId。讨论使用本机正常会话配置，不继承包内账号、运行句柄或自动启动外来环境。播放器无需等待讨论的模型配置完成才能浏览。

问题和回答不写进原始 Replay。未来 MP4 的默认场景范围也只针对选定的原研究回放，不混入观看者的讨论。

## 8. 恢复、删除、导出与错误行为

| 情况                   | 行为                                                                           |
| ---------------------- | ------------------------------------------------------------------------------ |
| 重启、再次打开入口     | 找回同一讨论和播放检查点，校验来源与生成器版本，恢复为暂停                     |
| 生成器升级或步骤不存在 | 用原始记录锚点重新定位；无法定位时提示并回到有效起点，不静默跳错步骤           |
| 来源删除或不可读       | 停止回放并显示原因；已有讨论及保存的摘录保留，引用标记不可用                   |
| 讨论删除               | 来源仍可观看；显式选择开始新讨论后才建立新关联                                 |
| 来源/讨论归档          | 遵守现有归档可读/可写规则，明确恢复入口，不绕过归档保护                        |
| 删除整个项目           | 接入项目删除协调器，覆盖讨论运行静止、关联、观看状态和派生缓存清理             |
| 附件丢失或损坏         | 显示缺失步骤及已保存文本，允许继续播放；不换成同名或最新文件                   |
| 讨论创建/发送失败      | 保留草稿和引用，沿用现有错误恢复与幂等发送机制                                 |
| 用户主动切走           | 旧异步加载、导入或创建完成不能抢导航；退出 Replay 不停止左侧正在运行的正常讨论 |
| 再次导出来源 .science  | 沿用现有原包导出语义，不加入观看状态或本地讨论关系                             |

来源与讨论状态分别决定能力：来源归档但仍按现有规则可读时可观看，已有讨论能否继续输入由讨论自己的归档状态决定；讨论归档时来源继续可看，提供恢复讨论入口。来源被删除时，已有讨论转为可见的普通讨论并保留失联来源提示；没有讨论则不隐式创建。恢复按钮调用现有恢复流程，不通过清除归档字段绕过保护。

来源归档而讨论仍可写时，讨论在正常列表保持可达并标明来源关系；来源恢复后重新合并为一个研究入口，避免把可用讨论藏进归档入口或显示重复项。

用户显式删除优先于中断恢复。即使讨论文件已创建而关系仍在“创建中”，删除后也必须保留权威删除标记或关系终止状态，重启不得按预留 ID 将讨论复活。原文件引用依赖仍由现有清理协调器处理。

删除来源与删除讨论不隐式相互级联；文件保留和已有引用依赖必须经过现有删除协调，不绕过其检查。讨论自身导出沿用既有规则，不承诺自动携带整份被引用研究。

## 9. 分阶段实施与依赖

实施开始时先核对届时基线，使用独立的 codex/research-replay 开发分支，保持此前问题修复的提交范围清楚。建议拆成可审查的提交，开发期开关控制未完成入口；只有完整流程验收后才默认启用。开启或关闭该功能均不删除用户讨论，已有讨论仍能从普通会话入口找回。

| 阶段                     | 主要交付                                                                    | 依赖与完成标准                                                 |
| ------------------------ | --------------------------------------------------------------------------- | -------------------------------------------------------------- |
| P0：契约和测试材料       | 固定身份、播放脚本、资源、时间和引用契约；建立可公开的最小测试包与预期步骤  | 不实现新协议；明确稀疏、分支、并行、多个文件版本案例           |
| P1：本地关系与工作区协调 | 本地迁移/仓库/IPC、幂等首次创建、来源专属草稿、导航和侧栏投影、生命周期处理 | 来源保持只读；两个研究、多窗口与重启不会串消息或重复建讨论     |
| P2：数据投影和时间引擎   | SourceReader、TimelineBuilder、稳定锚点、资源索引、纯时间投影               | 同一位置直接定位与顺序推进一致；无未来状态残留；版本和分支正确 |
| P3：右侧播放器           | Replay 工具标签、独立 Stage、只读展示组件、控制条、证据检查、默认打开       | 能播放现有包；缺失材料可降级；单纯观看不启动执行或模型         |
| P4：边看边问             | ContextBridge、可见步骤引用、左侧发送与返回定位、新结果标签                 | 第 N 步问题在继续播放后仍引用第 N 步；草稿及操作身份正确       |
| P5：持久化与渲染验证     | 检查点恢复、资源缓存/取消、固定视口、字体与资源就绪、可采帧宿主验证         | 选定时刻截图和连续推进状态一致；长记录/慢资源无重排序与错配    |
| P6：集成验收与交付       | 真实桌面流程、现有导入/Fork回归、八语言、键盘交互、文档与发布说明           | 下节所有发布门槛通过，再默认开放                               |

P1 与 P2 在 P0 契约确定后可并行；P3 依赖 P2，入口集成依赖 P1；P4 依赖 P1/P3；P5 的渲染基础从 P2/P3 开始建设，不能最后补换引擎。P6 验证完整集成。

第一期需更新应用本地 schema/IPC 和 renderer，不改 .science 协议。新增数据库结构接入现有迁移与 schema 生成检查，不手动只改生成产物。若公共桥接接口受 Web API 映射覆盖，同步更新并校验；桌面入口优先发布，其他入口保持明确能力判断，不产生缺失 API 崩溃。

- A4：左侧 A 与右侧 B 同时存在时提问、点击跨来源引用、画面保留上一步图表、讨论单独导出后缺少本地映射；验证去向、草稿保存和降级文案。
- A5：共享提问的分支、工具活动内截断分支、同一个包重复导入；版本、缓存和进度不串。
- A7：跨多个分页的长历史、大运行输出和多版本图表；记录有界缓存/内存、取消行为、首次就绪与 seek 响应，不仅测试几条短消息。
- A8/A9：讨论文件创建成功但关系确认失败，之后用户删除，再重启；不得恢复被删讨论。
- A9：来源与讨论分别处于归档、缺失状态；菜单的停止、导出、删除操作始终指向明确对象。
- A10：SVG、字体迟到、资源失败和超时；同一画面身份的资源屏障生效，旧批次结果不能提前完成新画面。
- A12：右侧原本折叠、正常窄栏、预览展开后提问及返回；验证内容可读、输入框可达，焦点和暂停位置可恢复。

测试分层：纯投影/时钟/分支单元测试；本地关联和迁移集成测试；组件交互和迟到资源测试；真实 Electron 桌面导入、播放、提问、退出重开与 Fork 路径。智能体响应可使用现有测试替身，断言传入的步骤引用与会话归属；不为验证播放器运行收费实验。

真实试点材料可使用已验证的历史复算包，包含 7 条消息、19 项工具活动、2 次 Notebook 运行和 17 个产物版本，只用于本机验收，不提交到仓库。它不能替代分支、稀疏历史和缺失材料测试，也不能代表最初完整研究对话已被保存。

## 11. 后续 MP4 导出工作包

在本期渲染契约稳定后再实施，直接消费相同 ReplayDocument 和 ReplayStage：

1. 选择来源、分支、起止范围、展示节奏、画布尺寸与帧率，冻结文档版本、资源版本和字体配置。
2. 在固定软件栅格化的专用离屏宿主中准备资源，按固定帧时间 seek，并等待画面就绪后采帧；沿用第一期采帧验证的渲染条件，不录制用户正在操作的整张应用窗口。
3. 对复杂预览和媒体实施明确的冻结/栅格化/占位策略；必要时提供导出前可预览的降级说明。
4. 后台编码与封装 MP4，支持进度、取消、磁盘空间/失败处理、临时文件清理和原子发布文件。
5. 视频默认包含原研究场景、步骤说明与重建标识，不含当前讨论、输入框或播放按钮；默认无音轨。
6. 验证时长、帧数、尺寸、首尾步骤、缺失占位和选定关键帧。相同环境可复验渲染，不承诺编码文件或跨平台字体栅格逐字节一致。

导出任务在本地保留渲染清单：来源指纹、生成器与展示版本、分支/范围、资源版本、字体/语言/时区配置和降级说明；可随视频另存清单，视频内保留来源与重建标识。该清单属于视频导出产物，不扩充 .science 协议。

编码器、打包方式及平台兼容性在该阶段选择和验证；本期不安装视频依赖或提前承诺所有预览格式均可完整导出。
