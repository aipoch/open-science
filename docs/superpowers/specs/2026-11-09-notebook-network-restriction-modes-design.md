# Notebook 网络限制模式设计

状态：设计与高保真交互稿已通过评审，按本方案实施。

## 背景

PR #4098 将 Notebook 网络访问改为按请求类型处理：HTTPS 主机名默认放行（包括解析到私网或回环地址的主机名），HTTP 和直连 IP 进入授权流程；“信任的不安全地址”用于持久化特定协议、主机名和端口的授权。后续提交主要修复了打包、运行时警告、E2E 夹具和进程生命周期问题，没有改变这套网络策略。

本次需求增加两种模式：

- **宽松模式**：保持 PR #4098 的现有行为，作为默认模式。
- **严格模式**：只允许命中手工维护的白名单；未命中的请求直接拒绝，不能申请授权。

严格模式的白名单不检查 DNS 解析结果。策略只比较请求中的协议、主机名和端口；命中后允许连接，不比较、不按解析出的地址做公共/私有地址过滤。建立连接所需的普通 DNS 解析仍保留，解析失败按连接错误处理，不影响白名单匹配语义。

## 目标与非目标

目标：

1. 在不改变宽松模式既有行为的前提下，引入可切换的严格白名单模式。
2. 预置 PR #4098 之前的 Open Science 内置域名，并允许编辑、删除和新增规则。
3. 让严格模式的拒绝在运行时和主进程授权入口都不可配置，避免任何路径弹出授权卡或写入持久化授权。
4. 保留宽松模式已有的 `destinationGrants` 和 `trustedPrivateDestinations`，切换回宽松模式后继续生效。
5. 通过版本化迁移和并发合并，避免升级或多窗口编辑丢失用户设置。

非目标：

- 本次不重写宽松模式的 HTTPS 自动放行规则。
- 本次不把链接预览域名策略与 Notebook 网络白名单合并。
- 本次不引入面向所有网络场景的通用规则语言。

## 已确定方案：独立严格白名单

增加 `mode` 和独立的 `strictWhitelist`，宽松策略和严格策略在运行时明确分支。

该方案能够保持旧字段的语义，保留宽松模式授权，并且能让严格模式的“命中即允许、未命中即拒绝”成为可测试的独立契约。采用此方案。

## 配置模型

在 `src/shared/notebook-network-settings.ts` 增加：

```ts
type NotebookNetworkMode = 'relaxed' | 'strict'

type NotebookStrictWhitelistEntry = {
  id: string
  protocol: 'http' | 'https'
  hostnamePattern: string
  port: number
  groupId?: string
  origin: 'builtin' | 'manual'
}

type NotebookWhitelistGroup = {
  id: string
  name: string
}
```

`NotebookNetworkSettings` 增加：

```ts
mode?: NotebookNetworkMode
strictWhitelist?: readonly NotebookStrictWhitelistEntry[]
strictWhitelistGroups?: readonly NotebookWhitelistGroup[]
```

归一化规则：

- 缺少 `mode` 时使用 `relaxed`。
- 严格规则的主机名统一小写、去除末尾点；协议统一小写；端口必须是有效 TCP 端口。
- `hostnamePattern` 支持精确主机名、精确 IP、`localhost` 和 `*.example.com`。通配符只匹配子域，不匹配 `example.com` 本身。
- 同一协议、规范化主机名和端口的重复规则在保存前去重。
- `groupId` 只用于逻辑分类，不参与网络匹配或权限判断；新增规则可以选择已有分组或创建自定义分组。
- 严格规则的 `origin` 只用于展示来源：`builtin` 表示迁移预置，`manual` 表示在设置页手动添加，不参与权限匹配。宽松列表的“Agent 请求”标签由既有授权记录推导，不接受前端填写来源。
- 规则 ID 必须稳定，不能以数组位置作为身份。

现有的 `allowedDomains`、`disabledOpenScienceDomainGroups`、`disabledOpenScienceDomains` 继续保留，用于现有链接预览和兼容逻辑；不直接把它们当作严格白名单。

## 初始化与迁移

网络设置实际持久化在 `settings.json`，因此使用该存储的一次性版本迁移，不新增 SQLite 表。首次配置存储迁移为缺少 `strictWhitelist` 的旧配置生成内置规则快照，来源为 PR #4098 之前的六组 Open Science 域名目录：软件包与源代码、NIH/NCBI、基因组与通路、蛋白质组与结构、科学文献、临床与转化研究。

预置条目统一使用 HTTPS / 443；该值是新模式的初始规则，不代表恢复旧版运行时的全部行为。首次配置存储迁移同时写入六个逻辑分组和对应规则，并应用旧的禁用分组和禁用单域名设置，避免把用户明确关闭的内置项重新打开。迁移完成后不做目录自动对账：用户编辑或删除的内置分组/规则永久生效，后续启动不会重新添加，也不提供“恢复内置项”操作。未来新增官方内置项必须通过新的显式配置存储迁移处理，并以稳定 ID 和删除记录避免复活用户删除的规则。

现有 `destinationGrants` 和 `trustedPrivateDestinations` 不迁移为严格规则，也不因切换到严格模式而撤销。它们只在宽松模式使用。

当前 `allowedDomains` 同时可能服务于链接预览，因此不自动转换成严格授权。严格白名单不提供导入或导出；除首次迁移预置目录外，新增放行地址由用户手工填写。

## 运行时策略

`buildNotebookNetworkPolicy` 按模式生成不同策略：

### 宽松模式

- 保持 PR #4098 的现有 HTTPS 主机名自动放行。
- HTTP、直连 IP 和其他需要确认的请求继续产生 `ask`，由现有授权卡处理。
- 继续传入 `trustedPrivateDestinations`，允许已保存的私有目标规则生效。
- “信任的不安全地址”继续可以新增、撤销和持久化。

### 严格模式

- 只传入 `strictWhitelist`，不传入宽松模式的私有地址授权规则。
- 在 DNS 解析之前完成协议、主机名和端口匹配。规则命中后直接允许连接，不调用 DNS 解析结果检查，不比较地址是否为私网、回环或公网，也不按地址集合重新授权。
- 未命中规则返回不可配置的拒绝结果，不产生 `ask`，不显示授权卡，不调用 `request_network_access`，不写入 `destinationGrants` 或其他“始终允许”记录。
- 通配符只作用于请求主机名的字符串匹配；解析出的别名或地址不会改变规则结果。

策略匹配必须同时在运行时策略层和主进程的授权决策入口设防。这样即使存在旧的阻断记录、排队中的请求或已打开的权限卡，严格模式也不能被旧流程放行。

模式切换通过现有串行设置 owner 应用。应用新策略时增加策略代次或等价失效标记，取消/失效待处理的宽松模式授权请求；切回宽松模式时重新读取并使用之前保留的授权规则。

## 设置界面

`NotebookNetworkDomainsForm` 顶部采用固定横向、圆角矩形的双段滑块：**宽松 / 严格**。选中背景随模式平移，窄窗口不改为上下卡片；支持鼠标点击与方向键操作。缺省仍为宽松。

滑块下方以默认收起的可展开区域解释当前模式规则，标题与规则随切换即时更新。点击标题或通过键盘可展开/收起；同一页面内切换模式保留用户当前的展开状态。收起时只显示当前模式说明标题：

- **宽松**：HTTPS 主机名直接放行，包括 localhost 和解析到私网/回环地址的主机名；HTTP 与直连 IP（包括 HTTPS IP）需要授权；已信任地址按精确协议、主机和端口放行；可手动添加，也可在符合条件的请求中授权；严格白名单不生效。
- **严格**：协议、请求主机名/IP、端口必须匹配白名单；未命中直接拒绝且不能申请授权，只能手动添加；不检查 DNS 解析地址；通配符只匹配子域不含根域；宽松模式信任记录不能绕过白名单。

不再另设重复的规则摘要或决策路径侧栏，主区采用单列布局。

宽松模式列表仅在总条目数超过 10 项时显示搜索框（10 项隐藏、11 项显示），按主机名/IP 过滤；搜索阈值按完整列表计算，不随搜索结果数量变化。删除至 10 项时隐藏并清空查询。严格模式保留搜索框。两种模式的添加按钮始终靠右。

宽松模式列表继续命名为 **信任的不安全地址**（英文源文案 `Trusted unsafe networks`），支持手动添加、编辑、删除。新增必须明确填写协议、精确主机名/IP 与端口，不支持通配符；这类记录只在宽松模式有效。实现时由 `NotebookNetworkAccessEditor` 统一呈现两种模式，并复用现有信任地址合法性校验，不增加 DNS 地址检查。

严格模式界面包含：

- 六类内置目录的可折叠列表及搜索。
- 规则行展示协议、主机名/通配符、端口、逻辑分组和来源标签；来源标签为“内置”“手动”或“Agent 请求”。
- 搜索框右侧提供“添加规则”；表单支持选择已有分组或创建新分组。分组只是逻辑分类名称，不改变规则匹配。
- 按需显示的新增表单和重复校验；不提供导入导出或恢复内置项。
- 不单独展示信任地址停用提示块，该语义仅在可展开的模式说明中介绍，原数据继续保留。

两种模式的编辑器默认隐藏。点击工具栏最右侧的“添加地址”或“添加规则”后，在该工具栏下方展开表单并聚焦主机输入；原添加按钮原位变为“确定”，表单内不再重复放置添加按钮。填写完整后点击“确定”或按 Enter 校验并立即保存，成功后收起表单、恢复原按钮；校验或保存失败时保留表单。点击“取消”收起且不创建记录。严格模式新增时可选择已有逻辑分组或创建分组，未选归入“未分组”。

来源隐式自动记录，新增及编辑表单均不展示来源字段。设置页新增记为“手动”；宽松模式通过 Agent 请求授权后新增的信任地址记为“Agent 请求”；严格模式不提供请求授权入口。既有条目编辑保留原始来源，列表继续展示来源标签。

点击行内“编辑”时，在被编辑条目的原位置展开已填充的表单，顶部按钮保持“添加”。表单提供“取消”和“确认”；取消丢弃本次草稿，确认或 Enter 校验并立即保存，成功后恢复列表行。编辑过程中失焦和切换字段不写入设置，校验或保存失败时在表单内显示错误并保留草稿。切换模式时关闭编辑器并清空搜索，不将未确认的草稿写入配置。

**取消页面底部的保存/放弃栏，所有有效操作逐项立即保存。** 新增在完整填写并点击“确定”后立即持久化；既有条目点击行内“确认”或按 Enter 后立即持久化，无需再点整页保存；“取消”不写入本次编辑。输入中的半成品与非法值不写入策略。模式切换与删除在操作完成时立即提交；内置规则删除后不提供恢复按钮。

每个操作区域显示轻量的保存中/已保存/失败反馈。失败时回到最后生效的模式或规则，保留输入以便重试，不能显示错误的成功状态。

新增文案遵循现有 i18n 约束，补齐八个 renderer locale。

高保真设计稿位于 [`notebook-network-settings.html`](../ui/notebook-network-settings.html)。默认宽松；演示横向滑块、可折叠的两种模式说明、搜索框旁的添加入口、点击添加后在按钮下方展开表单、原按钮变为确定、宽松列表超过 10 项显示搜索、逻辑分组选择/新建、来源标签、手动信任地址、严格规则编辑与逐项自动保存。预览保存到专用浏览器 localStorage 键，不读取或修改应用配置；初始信任地址为示例数据。刷新可验证预览修改仍在。

视觉约束：保持深色工作台和青绿色选中态；阅读顺序为“标题 → 横向滑块 → 当前规则说明 → 地址列表”。取消大型模式卡片、摘要侧栏与整页保存栏。不再设置额外的信任记录停用提示；不将宽松模式本身表现为错误。

## 保存与并发

沿用串行 settings owner 的事务和回滚路径，调整 renderer 为逐项提交，不再维护整页待保存草稿。

- 模式变更携带基线模式；白名单及信任条目变更携带稳定 ID 和对应基线，扩展 `SetNotebookNetworkRequest` 与 store 适配层。后端基于最新快照只合并本次变更，避免覆盖其他窗口的新记录。
- 不同条目的并发修改可以合并；同一条目或模式发生基线冲突时报告冲突并获取最新状态，不静默覆盖。
- 同一窗口的自动保存串行提交，响应按操作序号处理，旧响应不能覆盖较新的修改。未完成的模式切换期间暂时禁用切换，防止策略与视图错位。
- 只在配置持久化和运行时应用都成功后显示“已保存”。应用失败沿用现有回滚；失败的条目保留待重试输入并在所属区域展示错误。
- 关闭窗口时，已提交的操作由 owner 完成；未完成或非法输入不能意外写成放行规则。删除正在编辑的条目时清理其编辑状态。


## 测试计划

共享层：

- 默认模式为宽松。
- 旧配置迁移出完整内置快照，并正确应用旧禁用状态。
- 规则规范化、重复去重、协议/端口校验和通配符边界。

运行时层：

- 宽松模式现有 HTTPS、HTTP、直连 IP、私有目标和授权路径保持不变。
- 严格模式覆盖精确主机名、子域通配、协议和端口不匹配。
- 严格模式命中规则时不执行 DNS 地址检查，命中解析到公网、私网、回环或多个地址的情况都使用同一规则结果。
- 未命中返回不可配置拒绝，且不会生成授权请求。
- 严格模式忽略宽松模式遗留的授权记录，切回宽松后这些记录恢复可用。

主进程与设置 owner：

- 严格模式不弹权限卡、不调用授权 API、不持久化始终允许。
- 模式切换使待处理授权失效。
- 并发编辑严格规则时能合并增删改；运行时应用失败能回滚。

界面与端到端：

- 默认显示宽松模式，横向滑块在窄窗口仍并排显示，键盘可操作。
- 模式说明默认收起且可用鼠标/键盘展开；编辑器默认隐藏，工具栏下方在添加或行内编辑时打开，取消/新增成功/完成后收起。
- 两种模式均支持手动新增与编辑；严格模式另覆盖分组选择/新建、搜索和来源标签，确认无导入/导出或恢复入口。
- 添加按钮始终靠右；表单位于工具栏下方；原按钮切换为“确定”；来源字段不显示且自动记录，编辑保留来源；宽松列表搜索覆盖 10/11 项阈值及过滤后仍可搜索。
- 无整页保存栏；模式切换、有效编辑与增删立即持久化；非法/重复输入不落库。
- 保存失败、连续修改、乱序响应和多窗口冲突都有明确反馈且不会错误放行。
- 严格模式下阻断请求不出现授权卡；手工添加后同一请求可以通过。
- 切换回宽松后原有“信任的不安全地址”恢复作用。
- 运行 i18n guard，并执行真实 Notebook 网络阻断/放行路径，不能只用合成的主进程事件代替。
