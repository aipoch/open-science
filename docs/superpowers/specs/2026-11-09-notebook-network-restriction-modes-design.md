# Notebook 网络限制模式设计

状态：待评审

## 背景

PR #4098 将 Notebook 网络访问改为按请求类型处理：HTTPS 主机名默认放行，HTTP、直连 IP 和私有地址进入授权流程；“信任的不安全地址”用于持久化特定私有目标的授权。后续提交主要修复了打包、运行时警告、E2E 夹具和进程生命周期问题，没有改变这套网络策略。

本次需求增加两种模式：

- **宽松模式**：保持 PR #4098 的现有行为，作为默认模式。
- **严格模式**：只允许命中手工维护的白名单；未命中的请求直接拒绝，不能申请授权。

严格模式的白名单不检查 DNS 解析结果。策略只比较请求中的协议、主机名和端口；命中后直接放行，不读取、不比较、也不按解析出的地址做公共/私有地址过滤。

## 目标与非目标

目标：

1. 在不改变宽松模式既有行为的前提下，引入可切换的严格白名单模式。
2. 预置 PR #4098 之前的 Open Science 内置域名，并允许编辑、删除和新增规则。
3. 让严格模式的拒绝在运行时和主进程授权入口都不可配置，避免任何路径弹出授权卡或写入持久化授权。
4. 保留宽松模式已有的 `destinationGrants` 和 `trustedPrivateDestinations`，切换回宽松模式后继续生效。
5. 通过版本化迁移和并发合并，避免升级或多窗口编辑丢失用户设置。

非目标：

- 本次不重写宽松模式的 HTTPS 自动放行规则。
- 本次不把链接预览域名策略与 Notebook 网络白名单合并。
- 本次不引入面向所有网络场景的通用规则语言。

## 方案选择

### 方案 A：复用现有字段

在现有 `allowedDomains`、`disabledOpenScienceDomainGroups` 和 `disabledOpenScienceDomains` 上增加 `mode`。

优点是字段和迁移较少。缺点是这些字段仍被链接预览策略使用，严格白名单和预览域名会共享数据但拥有不同安全语义；删除、导入和并发保存也难以解释。此方案不采用。

### 方案 B：独立严格白名单

增加 `mode` 和独立的 `strictWhitelist`，宽松策略和严格策略在运行时明确分支。

该方案能够保持旧字段的语义，保留宽松模式授权，并且能让严格模式的“命中即允许、未命中即拒绝”成为可测试的独立契约。采用此方案。

### 方案 C：统一规则引擎

把允许、询问、拒绝、私有地址授权统一成一套可组合规则。

长期扩展性最好，但会扩大迁移、运行时和 UI 的改造范围。本次需求不需要承担这项风险，暂不采用。

## 配置模型

在 `src/shared/notebook-network-settings.ts` 增加：

```ts
type NotebookNetworkMode = 'relaxed' | 'strict'

type NotebookStrictWhitelistEntry = {
  id: string
  protocol: 'http' | 'https'
  hostnamePattern: string
  port: number
  source: 'builtin' | 'custom'
}
```

`NotebookNetworkSettings` 增加：

```ts
mode?: NotebookNetworkMode
strictWhitelist?: readonly NotebookStrictWhitelistEntry[]
```

归一化规则：

- 缺少 `mode` 时使用 `relaxed`。
- 严格规则的主机名统一小写、去除末尾点；协议统一小写；端口必须是有效 TCP 端口。
- `hostnamePattern` 支持精确主机名、精确 IP、`localhost` 和 `*.example.com`。通配符只匹配子域，不匹配 `example.com` 本身。
- 同一协议、规范化主机名和端口的重复规则在保存前去重。
- `source` 只用于展示、迁移和恢复内置项，不改变匹配权限。
- 规则 ID 必须稳定，不能以数组位置作为身份。

现有的 `allowedDomains`、`disabledOpenScienceDomainGroups`、`disabledOpenScienceDomains` 继续保留，用于现有链接预览和兼容逻辑；不直接把它们当作严格白名单。

## 初始化与迁移

首次读取缺少 `strictWhitelist` 的旧配置时，生成内置规则快照，来源为 PR #4098 之前的六组 Open Science 域名目录：软件包与源代码、NIH/NCBI、基因组与通路、蛋白质组与结构、科学文献、临床与转化研究。

生成快照时应用旧的禁用分组和禁用单域名设置，避免把用户明确关闭的内置项重新打开。快照写回配置后，用户删除的内置项不会因为下一次读取而自动出现；“恢复内置项”才会重新加入缺失项目。

现有 `destinationGrants` 和 `trustedPrivateDestinations` 不迁移为严格规则，也不因切换到严格模式而撤销。它们只在宽松模式使用。

当前 `allowedDomains` 同时可能服务于链接预览，因此不自动全部转换成严格授权。严格设置页可以提供一次性“导入现有自定义域名”操作，导入时明确显示将要添加的协议和端口，避免隐式扩大网络访问范围。

## 运行时策略

`buildNotebookNetworkPolicy` 按模式生成不同策略：

### 宽松模式

- 保持 PR #4098 的现有 HTTPS 主机名自动放行。
- HTTP、直连 IP 和其他需要确认的请求继续产生 `ask`，由现有授权卡处理。
- 继续传入 `trustedPrivateDestinations`，允许已保存的私有目标规则生效。
- “信任的不安全地址”继续可以新增、撤销和持久化。

### 严格模式

- 只传入 `strictWhitelist`，不传入宽松模式的私有地址授权规则。
- 在 DNS 解析之前完成协议、主机名和端口匹配。规则命中后直接允许连接，不调用 DNS 解析结果检查，不比较地址是否为私网、回环或公网，也不按地址集合重新授权。
- 未命中规则返回不可配置的拒绝结果，不产生 `ask`，不显示授权卡，不调用 `request_network_access`，不写入 `destinationGrants` 或其他“始终允许”记录。
- 通配符只作用于请求主机名的字符串匹配；解析出的别名或地址不会改变规则结果。

策略匹配必须同时在运行时策略层和主进程的授权决策入口设防。这样即使存在旧的阻断记录、排队中的请求或已打开的权限卡，严格模式也不能被旧流程放行。

模式切换通过现有串行设置 owner 应用。应用新策略时增加策略代次或等价失效标记，取消/失效待处理的宽松模式授权请求；切回宽松模式时重新读取并使用之前保留的授权规则。

## 设置界面

`NotebookNetworkDomainsForm` 顶部增加模式选择：

- **宽松**：显示“HTTPS 主机通常可直接访问，其他请求可能申请授权”的说明。
- **严格**：显示“只允许白名单命中项，未命中不会申请授权”的说明。

严格模式界面包含：

- 按内置分组折叠展示规则。
- 规则表格：协议、主机名/通配符、端口、来源、编辑、删除。
- 新增规则表单，输入时即时规范化并检查重复。
- 恢复内置项和导入现有自定义域名操作。
- 明确提示严格模式不提供“申请授权”入口。

宽松模式继续展示 `TrustedPrivateServices`。严格模式下保留这部分配置但显示为停用状态和解释：“这些规则仅在宽松模式生效”；不自动删除数据。

新增文案遵循现有 i18n 约束，补齐八个 renderer locale，并覆盖模式说明、白名单编辑、未命中阻断、授权不可用和停用的宽松规则等文案。

## 保存与并发

扩展 `SetNotebookNetworkRequest`，增加严格白名单的基线快照，例如 `baseStrictWhitelist`。settings owner 在合并草稿时按规则 ID 计算增删改，避免设置窗口或多个 renderer 同时保存时用旧快照覆盖别人的规则。

模式、严格规则、宽松授权规则和现有域名设置仍由同一个串行 commit 流程写入；运行时应用失败时沿用现有回滚路径，不能留下“磁盘配置和运行时策略不一致”的状态。

## 测试计划

共享层：

- 默认模式为宽松。
- 旧配置迁移出完整内置快照，并正确应用旧禁用状态。
- 规则规范化、重复去重、协议/端口校验和通配符边界。

运行时层：

- 宽松模式现有 HTTPS、HTTP、直连 IP、私有目标和授权路径保持不变。
- 严格模式覆盖精确主机名、子域通配、协议和端口不匹配。
- 严格模式命中规则时不执行 DNS 地址检查，命中解析到公网、私网、回环或多个地址的情况都使用同一规则结果。
- 未命中返回不可配置拒绝，且不会生成授权请求。
- 严格模式忽略宽松模式遗留的授权记录，切回宽松后这些记录恢复可用。

主进程与设置 owner：

- 严格模式不弹权限卡、不调用授权 API、不持久化始终允许。
- 模式切换使待处理授权失效。
- 并发编辑严格规则时能合并增删改；运行时应用失败能回滚。

界面与端到端：

- 默认显示宽松模式。
- 严格模式可以新增、编辑、删除、恢复和导入规则。
- 严格模式下阻断请求不出现授权卡；手工添加后同一请求可以通过。
- 切换回宽松后原有“信任的不安全地址”恢复作用。
- 运行 i18n guard，并执行真实 Notebook 网络阻断/放行路径，不能只用合成的主进程事件代替。

## 实施顺序

1. 增加共享类型、校验、默认值和迁移。
2. 改造运行时策略和主进程授权入口，先锁定严格模式的安全边界。
3. 扩展 settings owner 的并发合并和回滚。
4. 实现设置页的模式选择与严格白名单编辑器。
5. 补齐八种语言和测试，最后执行真实 Notebook 网络路径验证。

## 需要评审确认的约束

本设计已经按以下明确约束编写：严格白名单不对 DNS 解析结果做任何检测；命中只由请求协议、主机名和端口决定；未命中不可申请授权；宽松模式为默认；“信任的不安全地址”只在宽松模式生效但不会被删除。
