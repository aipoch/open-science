# Sensitive data detection and redaction in Open-Science

At revision `3d4cf469b`, the strongest credential checks are on the way **out** of the application, particularly session exports, logs and diagnostic reports. Ordinary ACP prompt preparation passes the user's text to the selected model. A clean export scan does not establish that research data is anonymous or that every model request was screened. ## Optimization decisions

1. **Start with a local comparison of credential rules.** Reuse the [redaction cases](../packages/diagnostics/src/diagnostic-redaction.test.ts), [package cases](../src/main/session-package/sensitive-content.test.ts) and [privacy canaries](../src/main/diagnostics/privacy-canary.test.ts). For each genuine discrepancy record the expected action per sink: mask in a log, keep a safe metric, omit an unsafe lock or interrupt an export. First compare Reviewer plain text and common redaction, then compare package match spans against their rendered evidence. The package scanner and evidence formatter use different rules. Verify the matched value is absent from the displayed snippet. Add a regression only where the existing cases miss that boundary.
2. **Make rule changes conditional on measured benefit.** Count missed synthetic credentials, benign records blocked and sensitive values surviving in output, separately by rule and workflow. Include representative Notebook code, paper citations, hashes, token counts, encoded URLs and split file reads. Measure latency and peak memory on short messages and large text artifacts. Adopt an upstream rule only when it improves the target sink with acceptable false positives. Retaining current behavior costs less if the comparison finds no actionable difference.
3. **Decide the destination and action before adding input PII detection.** A local warning on external sharing preserves original text and allows review. Masking the provider-bound copy reduces disclosure but can break quotations, code, identifiers and tool arguments. Hard blocking also delays legitimate research. Evaluate with synthetic, labeled examples in the languages and research domains actually used. Score precision and recall by entity, end-to-end exposure and user-visible latency. A hosted detector adds a recipient for the original text. Before implementing, map every configured framework and route, including attachments, active-branch history, replay, scenario models and tool results. Decide what happens on timeout or unavailable models.
4. **Pay for reversibility only with a demonstrated need.** Deletion or a fixed marker is adequate for most diagnostics. Partial masking preserves recognizable fragments. A per-export keyed identifier preserves equality within a report at the cost of linkability. Reversible tokenization requires a protected key or mapping and authorization to restore it. File-level OCR, recognition of visible identifiers and review of binary archives would each extend coverage beyond today's text scanner.

### Historical data

New rules at a display or export boundary could protect newly generated views of old records while leaving originals intact. A historical rewrite would need a separate decision covering backups, branch replay, package checksums and receipts. Existing shared archives cannot be recalled by changing a local scanner. No migration is part of this assessment.

### States and enums

This assessment adds none. The existing export evidence rule values are `field`, `assignment`, `url` and `token`. A future PII category or scanner-unavailable result exposed through IPC would need a contract decision, including how older readers handle it. An offline comparison needs no new public state. [Session package contract](../src/shared/session-package.ts)

### Persistence

The assessment creates no runtime records. Findings today can include redacted surrounding text, offsets, value length and a SHA-256 fingerprint of the raw value. A diagnostic export can store that evidence. An unkeyed digest permits equality comparison and guessing of short values. Decide whether support needs either the snippet or the hash before extending collection. A request-local placeholder map could expire when the request finishes. Supporting re-identification after restart would require a separately owned persistent secret store, retention period and deletion policy. [Evidence construction](../src/main/session-package/sensitive-content.ts) · [Archive writer](../src/main/session-diagnostics/collector.ts)
