Open Science は、[AIPOCH](https://aipoch.com/open-science) が科学者と研究者向けに開発した、オープンソースかつローカルファーストでモデル非依存の AI 研究ワークベンチです。科学 AI エージェント、Python と R の実行、科学データコネクタ、macOS・Windows・Linux のクロスプラットフォーム対応により、再現可能で検証可能な研究を実現します。1 つのワークスペースでプロジェクトを作成し、研究目標を自然言語で説明するだけで、エージェントがファイルの読み取り、ウェブ検索、コード実行、科学データソースへの問い合わせを行い、追跡可能な来歴を備えたレポート、表、図を生成します。

Open Science は、機械学習、統計学、生命科学、化学、材料科学、物理学、環境科学など、幅広い分野の計算集約型・データ集約型研究を支援します。文献レビューと仮説構築から、コード実行、データ分析、シミュレーション、可視化、追跡可能な研究成果の作成まで、研究プロセス全体を支えます。

## 🚀 クイックスタート

3 つの手順で Open Science を実行できます。使用するプラットフォームのインストーラーをダウンロードし、初回起動ガイドを完了して、研究プロジェクトを作成します。

### 1. アプリをダウンロードする

[最新リリース](https://github.com/aipoch/open-science/releases/latest)を開いて **Assets** を展開し、コンピューターに合うインストーラーを選択します。

| コンピューター                   | 選択するもの                                |
| -------------------------------- | ------------------------------------------- |
| macOS — Apple Silicon（M1 以降） | Apple Silicon / ARM64 用 macOS DMG          |
| macOS — Intel                    | Intel / x64 用 macOS DMG                    |
| Windows x64                      | Windows x64 インストーラー                  |
| Linux x64                        | Linux x64 AppImage または Debian パッケージ |

リリースページに掲載されたアセットと検証情報を確認してください。インストール前にパッケージを検証する場合は、[ダウンロードの検証](../../SECURITY.md#verifying-your-download)を参照してください。

> macOS または Windows に未確認の開発元や不明な発行元の警告が表示された場合は、続行前にパッケージが公式 Releases ページから取得されたことを確認してください。

### 2. 初回設定を完了する

初回起動には 5 つのガイド付き手順があります。

1. **環境**で、互換性、アプリのストレージ、安全な認証情報ストレージ、ネットワークアクセスを確認します。
2. **データの場所**で、大きなアーティファクト、Notebook、アップロード、環境の保存先を選択します。
3. **エージェントランタイム**で Claude Code、OpenCode、Codex のいずれかを選択して準備します。アプリ管理ランタイムのインストールには Node.js、npm、管理者パスワードは不要です。
4. **モデルプロバイダー**で使用するモデルに接続してテストします。組み込みプロバイダー、カスタムゲートウェイ、既存の Claude または Codex サブスクリプションログインを選択できます。
5. **Notebook ランタイム**では、アプリ管理の Python・R 環境を任意で準備するか、検出または手動登録した各言語のインタープリターを有効にします。

Notebook の実行は任意です。必要な環境チェックとエージェントランタイムチェックがすべて成功すると `Continue` が有効になり、モデル接続が成功すると設定を完了できます。Notebook とデータの場所はデフォルトのままにして、後から設定で変更できます。

### 3. 研究プロジェクトを始める

1. **New project** をクリックし、プロジェクトに安定した研究名と任意の説明を付けます。
2. セッションを開き、目標、入力データ、制約、必要な出力、結果の確認方法を説明します。
3. ソースファイルを添付し、検証済みモデルと承認モードを選択します。
4. タスクを送信します。エージェントのツールアクティビティを確認し、機密性の高い操作を承認して、生成されたアーティファクトをプレビューパネルで開きます。
5. 別の方向を検討するには、以前のユーザーメッセージを編集して新しいブランチで再送信します。メッセージのリビジョンコントロールからどちらの経路にも戻れます。
6. アーティファクトの **Provenance** ビューを開き、バージョンと選択結果の根拠を確認します。
7. 後のセッションでも作業を続けられます。`@` で既存のプロジェクトファイルを参照し、`/` で有効なスキルを明示的に選択します。

> この README のスクリーンショットはワークフローの例です。ラベル、カタログ、その他のインターフェースの詳細は、インストールしたバージョンと異なる場合があります。

## 製品ツアー

Open Science は研究をプロジェクトとセッションに整理し、すべての結果をその根拠に結び付けます。以下では、ワークスペース、アーティファクトの来歴、プレビュー、科学スキル、データコネクタを紹介します。

### タスクから追跡可能なアーティファクトまでを扱う 1 つのワークスペース

プロジェクトには、関連するセッション、アップロード、生成ファイル、プレビュー状態がまとめて保存されます。会話にはエージェントの回答に加え、その回答を生成したコマンド、ファイル読み取り、編集、検索、コネクタ呼び出しが記録されます。生成された各アーティファクトは、チェックサム付きの不変バージョンとして保存されます。**Provenance** ビューには、作成時に Open Science が検証できた生成コードと実行履歴、参照入力、観測された環境インベントリ、生成元の会話ブランチ、バージョン固有のレビュー結果が表示されます。欠けている根拠は推測で補われず、利用不可と明示されます。

生成されたレポート、図、表はセッションに関連付けられたまま、プロジェクトのファイルライブラリにも集約されます。パネルの大きさが変わってもプレビュータブはアクティブな結果を表示し、長い名前では識別に必要な末尾と拡張子が保たれます。Open Science は一般的な科学データ、PDF、Office ドキュメント（DOCX、XLSX、PPTX）、画像（ズームとパン対応）、シンタックスハイライト付きソースコード、分子構造と反応、Notebook 履歴をプレビューします。プレビュー制限によって基のファイルが切り詰められることはなく、完全なアーティファクトをエージェントや外部ツールから利用できます。`Cmd/Ctrl+F` でワークスペース全体のトランスクリプト、Notebook 出力、レンダリング済みページを検索し、`Cmd/Ctrl+K` でプロジェクトスコープのコマンドパレットを開けます。**Settings → General** でテーマを切り替えると、シェル、トランスクリプト、レンダラーの配色がちらつかずに切り替わります。インターフェースは設定のランタイム言語切り替えにより、ドイツ語、簡体字中国語、繁体字中国語、日本語、韓国語、フランス語、ロシア語、スペイン語でも利用できます。

### 元の内容を失わずに会話を分岐する

完了したユーザーメッセージを編集し、その時点から変更したプロンプトを再送信できます。Open Science は後続ターンを削除せずに新しいメッセージブランチを作成し、リビジョンコントロールで元の経路と別の経路を切り替えられます。ブランチ選択、ツールアクティビティ、添付ファイル、生成アーティファクトは、プロジェクトの切り替えや再起動後も保持されます。来歴は各アーティファクトバージョンを生成した正確なブランチに結び付いたままなので、別の仮説を検討しても以前の結果の記録が曖昧になりません。

### 科学スキルとデータコネクタ

Open Science には、増え続ける **18 個の注目**ファイルベース研究スキルがあります。AlphaFold2、Boltz、Borzoi、Chai-1、DiffDock、Environment & Packages、ESM-2、ESMFold2、Evo 2、Indication Dossier、LigandMPNN、Literature Review、OpenFold3、ProteinMPNN、scGPT、scvi-tools、SolubleMPNN、およびリモート HPC クラスターで長時間ジョブを送信・回収する **Remote Compute (SSH)** です。個人スキルの作成、`SKILL.md`/ZIP/`.skill` パッケージのアップロード、任意の認証を使った GitHub からの互換スキルのプレビューとインポート、グローバルエージェントディレクトリにインストール済みのスキルのインポートができます。エージェントがセッション添付ファイルや公開 GitHub URL からパッケージのインポートを要求することもでき、アプリが管理するプレビューと確認を経てから書き込まれます。有効なスキルはコンポーザーで `/` から直接選択できます。

また、**24 個の組み込み**研究コネクタがあります。Literature Graph、PubMed、bioRxiv、Genes & Ontologies、Genomes、BioMart、Variants、Human Genetics、Clinical Genomics、Structures & Interactions、Protein Annotation、Expression、Omics Archives、CellGuide、Regulation、RNA、Chemistry、ChEMBL、ZINC、Molecule Viewer、Clinical Trials、Drug Regulatory、Cancer Models、Research Resources です。組み込みコネクタとカスタムコネクタは権限システムで保護され、ツールごとに `Always allow`、`Ask each time`、`Block` を設定できます。インストール済みアプリには現在のスキル、コネクタ、ツールのカタログが表示されます。

## Open Science を選ぶ理由

Open Science は、研究タスク、実行、ファイル、根拠を 1 つのローカルで検証可能なデスクトップワークスペースにまとめます。

研究作業は通常、チャットウィンドウ、Notebook、ローカルスクリプト、科学データベース、ファイルブラウザー、レポートツールに分散しています。引き継ぎのたびにコンテキストが失われ、回答と、それを生み出したコードやファイルが切り離されがちです。

Open Science はそれらを 1 つの検証可能なデスクトップワークスペースに統合します。

- **作業を永続化。** プロジェクト、セッション、下書き、ファイル、プレビュー、実行履歴はアプリの再起動後も残ります。
- **提案だけでなく実行。** ユーザーの承認のもと、エージェントはコマンド、Python、R の実行、ファイル編集、検索、コネクタ呼び出し、アーティファクト生成を行えます。
- **作業を失わず別の経路を検討。** 以前のプロンプトを新しいメッセージブランチで変更し、複数の研究方向を切り替えられます。
- **追跡可能な結果。** 不変アーティファクトバージョンは Open Science が検証できる生成根拠を保持し、検証できない根拠も明示します。
- **複数のモデル選択肢。** 組み込みクラウドプロバイダー、互換カスタムゲートウェイ、Claude または Codex サブスクリプションを使用し、コンポーザーでセッションごとにモデルと推論の強度を選べます。
- **ローカルファーストの所有権。** アプリとプロジェクト状態は自分のコンピューターで動作し、外部呼び出しは明示的に設定または承認したサービスだけに行われます。
- **検証可能性。** ソースコード、スキル、コネクタ定義、ツールアクティビティ、生成ファイル、アーティファクトの来歴を確認できます。
- **拡張性。** 閉じたプラグインロードマップを待たずに、スキルと MCP コネクタを追加できます。
- **シートライセンス不要。** Open Science は Apache-2.0 ソフトウェアです。選択したモデルやインフラストラクチャーの料金だけを支払います。

Open Science はゼロから構築した独立製品です。他の AI 研究アプリのプロキシ、非公式クライアント、外観だけを変えた製品ではありません。

## 設計原則

Open Science は、コード、データ、モデル、人による監督の関係を定める 7 つの設計原則に基づきます。デフォルトでオープン、明示的なマルチプロバイダー互換性、ローカルファーストのデータ所有権、ヒューマンインザループの監督、永続的な研究記録、組み合わせ可能な機能、誠実な科学的境界です。

- **デフォルトでオープン。** ソースコード、形式、コネクタ、スキルは検証とフォークが可能であるべきです。
- **互換性を明示するマルチプロバイダー対応。** すべての API プロトコルを交換可能とみなさず、プロバイダー設定を検証してエンドポイント要件を示します。
- **ローカルファーストでデータを意識。** プロジェクト状態をローカルに保ち、外部データフローを示し、自律動作をオプトインにします。
- **ヒューマンインザループ。** ファイル編集、コマンド、ネットワークアクセス、コネクタ呼び出しは明示的な承認プロファイルで制御されます。
- **永続的な研究記録。** セッション、ツールアクティビティ、Notebook 履歴、不変アーティファクトバージョンは実行後も確認でき、利用できない根拠は明記されます。
- **組み合わせ可能な機能。** スキル、コネクタ、モデル、プレビュー、将来のコンピューティングバックエンドは、1 つのブラックボックスではなく交換可能な部品です。
- **誠実な科学的境界。** 生成出力は専門家の判断、統計レビュー、一次資料に基づく検証の代わりにはなりません。

## モデルプロバイダー

Open Science は製品レベルでモデルに依存しません。主要クラウド LLM プロバイダーやカスタムゲートウェイに接続するか、既存の Claude または Codex サブスクリプションを再利用できます。現在利用できるプロバイダーは、選択したエージェントバックエンドとその API プロトコルに依存します。モデルへの接続方法は 4 つあります。

| プロバイダーモード               | 動作                                                                                                                                                                                                                                                                                                      |
| -------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **組み込みクラウドプロバイダー** | インストール済みアプリに表示される一覧から選び、指定されたキーで認証します。                                                                                                                                                                                                                              |
| **カスタムゲートウェイ**         | 互換性のある Base URL、API Key、正確なモデル ID を指定します。デフォルト API 形式（Messages、Chat Completions、Responses）はアクティブなエージェントフレームワークから決まり、新しいゲートウェイをそのまま利用できます。                                                                                  |
| **Codex サブスクリプション**     | Codex エージェントフレームワークを選択し、プロバイダー種別で Codex サブスクリプションを選びます。                                                                                                                                                                                                         |
| **Claude サブスクリプション**    | 2 つのモードでログインできます。**共有**はブラウザーログインの認証情報をデフォルトの `~/.claude` プロファイルに保存します。**分離**はアプリ所有の `CLAUDE_CONFIG_DIR` で `claude setup-token` を実行し、`~/.claude/` から完全に分離して、ブラウザーフローとトークン貼り付けのフォールバックを提供します。 |

以前の **Local Claude** プロバイダーは削除されました。保存済みの Local Claude エントリはアップグレード時に削除されます。**Claude Subscription** を追加し、共有ブラウザーログインまたは分離された `claude setup-token` フローで認証してください。

組み込みクラウドベンダーには、OpenAI、Anthropic、Grok (xAI)、DeepSeek、専用 GLM Coding Plan エンドポイントを持つ Zhipu AI (GLM)、Kimi (Moonshot)、MiniMax、専用 Step Plan サブスクリプションエンドポイントを持つ StepFun、Xiaomi MIMO、SenseNova、Volcengine Ark、専用 Bailian for Plan サブスクリプションエンドポイントを持つ Bailian (Alibaba Cloud)、Tencent TokenHub に加えて専用の Tencent Coding Plan と Token Plan サブスクリプションエンドポイント、OpenCode Go、OpenCode Zen、OpenRouter 集約ゲートウェイなどがあります。一部は地域固有です。

プロバイダー、利用可能なモデル、地域別エンドポイントはこの README とは独立して変わる可能性があります。インストール済みアプリのプロバイダー選択と接続テストを正確な情報源としてください。

## データ、権限、信頼

Open Science はプロジェクトデータ、設定、アーティファクトバージョン、来歴の根拠をローカルコンピューターに保存します。API Key はローカルに保存され、利用可能な場合は OS の安全な認証情報ストレージで保護されます。ログはローカルにあり、自動アップロードされません。

外部へのデータ送信は発生するため、確認が必要です。

- モデルリクエストはプロンプトと必要なコンテキストを選択したモデルプロバイダーへ送信します。
- ウェブ検索とリモートコネクタは表示されたパラメーターを外部サービスへ送信します。
- ローカルコネクタは信頼されたコマンドをコンピューター上で実行する場合があります。
- 添付ファイル、`@` 参照、ログ、生成レポートには機密研究データが含まれる場合があります。

タスクに適した最小限の権限プロファイルを選択してください。

| モード               | 動作                                                                   | 推奨用途                                           |
| -------------------- | ---------------------------------------------------------------------- | -------------------------------------------------- |
| `Ask for approval`   | 編集、コマンド、ネットワーク、コネクタ呼び出しの前に確認               | 新しいワークフロー、機密データ、未確認のスクリプト |
| `Auto-approve edits` | ワークスペース編集を自動許可し、コマンド、ネットワーク、コネクタは確認 | 外部アクセスを制御した信頼できるファイル編集       |
| `Full access`        | 編集、コマンド、ネットワーク、コネクタを自動許可                       | 範囲が明確で完全に信頼できる無人作業               |

承認前にコネクタのパラメーターとツールアクティビティを確認してください。API Key、アクセストークン、患者識別子、未公開データ、機密性の高いローカルパスをスクリーンショットや公開 Issue のログに含めないでください。

## プロジェクトの状況

Open Science は macOS、Windows、Linux で利用できる活発に開発中のデスクトップアプリです。信頼できるローカルファースト研究ワークフロー、拡張可能な科学機能、追跡可能な研究アーティファクト、ユーザーが制御できる実行に重点を置いています。

現在のダウンロードとバージョン固有の変更は[最新リリース](https://github.com/aipoch/open-science/releases/latest)を参照してください。提供済み、一部対応、計画中の機能は[機能マップ](../../ROADMAP.md#capability-map)を参照してください。

Open Science は研究の実行と記録を支援しますが、手法、解釈、プライバシー、科学的妥当性の責任は研究者にあります。

## 開発とパッケージング

Open Science は React、TypeScript、Prisma/SQLite、ACP ベースのエージェントランタイムで構築された Electron アプリです。

ソース開発の前提条件：

- Node.js 22（[`.nvmrc`](../../.nvmrc) を参照）と npm
- Git
- Notebook を実行する場合のみ Python 3

```bash
git clone https://github.com/aipoch/open-science.git
cd open-science
npm install
npm run dev
```

`npm install` は Prisma クライアントを自動生成し、Electron のネイティブ依存関係をインストールします。`npm run dev` は Electron の main/preload バンドルをビルドし、レンダラーを開始してデスクトップアプリを開きます。開発データは `~/.open-science-project` に分離されます。

便利なコマンド：

| コマンド               | 目的                                               |
| ---------------------- | -------------------------------------------------- |
| `npm run dev`          | 開発アプリを開始                                   |
| `npm run dev:web`      | 開発アプリ + localhost Web UI (127.0.0.1)          |
| `npm run dev:headless` | Electron ウィンドウなしの開発バックエンド + Web UI |
| `npm run lint`         | ESLint を実行                                      |
| `npm run typecheck`    | main と renderer のコードを型チェック              |
| `npm test`             | Vitest スイートを実行                              |
| `npm run build`        | 型チェックしてアプリをビルド                       |
| `npm run build:web`    | 任意の localhost Web UI をビルド                   |
| `npm run build:mac`    | macOS ビルドをパッケージ化                         |
| `npm run build:win`    | Windows ビルドをパッケージ化                       |
| `npm run build:linux`  | Linux ビルドをパッケージ化                         |

パッケージ出力は `dist/` に書き込まれます。

### Localhost Web とヘッドレスモード

デスクトップバックエンドは、ローカルコンピューターのブラウザーへ同じレンダラーを任意で提供できます。この機能はデフォルトで無効で、`127.0.0.1` だけにバインドします。

```bash
npm run build:web
npm run dev:web
```

アプリが表示する認証済み URL を開きます。`npm run dev:headless` を使うと、Electron ウィンドウを開かずにバックエンド、トレイ、エージェントランタイム、localhost Web サービスを開始できます。`OPEN_SCIENCE_WEB_PORT` でポートを選択できます（デフォルト `44100`）。アプリを明示的に終了すると、エージェントと Notebook のプロセスも通常どおり終了します。

### モバイルリモートアクセス

Remote.It のペアリングにより、スマートフォンやタブレットから同じ localhost Web UI にアクセスできます。6 桁の Open Science コードでブラウザーをペアリングし、デスクトップで一度承認すると、ループバックサーバーを直接公開せずにワークスペースへ接続できます。ブラウザーの信頼は取り消し可能で、モード変更やサービス停止によりアクティブなリモートセッションは直ちに無効になります。

### ヘッドレス CLI と SDK

ヘッドレス CLI と依存関係のない Node.js SDK は、デスクトップおよび Web インターフェースと同じローカルデーモン、プロジェクト、セッション、認証情報、権限を使用します。詳細な使用方法は公開可能パッケージと一緒に管理され、コマンドリファレンスを 1 つだけ保守します。

- [CLI ガイド](../../packages/open-science/CLI.md) — インストール、サービスライフサイクル、タスク自動化、アーティファクト、出力形式、終了コード
- [SDK パッケージ概要](../../packages/open-science/README.md) — Node.js クイックスタートとパッケージエントリーポイント

## Open Science ではないもの

Open Science は研究実行と記録管理のツールであり、汎用チャットラッパー、非公式クライアント、科学的レビューの代替ではありません。

- **単なるチャット UI ではありません。** 永続プロジェクト、実行、ファイル、アーティファクト、確認可能なツールアクティビティを中心に構成されています。
- **他製品の非公式クライアントではありません。** 独自のコードベース、データモデル、インターフェース、ロードマップを持つ独立実装です。
- **科学的判断の代替ではありません。** 出力には分野の専門家によるレビュー、統計的検証、一次資料との照合が必要です。

## よくある質問

### Open Science を初めて開いたときは何をすればよいですか？

回答：**Environment**、**Data location**、**Agent runtime**、**Model provider**、**Notebook runtime** の 5 つの設定を完了してください。`Action needed` と表示された必須項目を解決し、選択したエージェントのインストールまたは修復が提示された場合は実行して、モデル接続をテストします。Notebook の設定とカスタムデータの場所は任意です。

### API Key とは何ですか？どこで取得できますか？

回答：API Key はモデルプロバイダーが発行する秘密の認証情報です。プロバイダーの開発者/API コンソールで作成またはコピーします。このキーによるリクエストには料金が発生する場合があります。パスワードと同様に扱い、共有したりリポジトリにコミットしたりしないでください。

### API Key は必要ですか？

回答：既存のサブスクリプションログインを再利用する場合は不要です。共有ブラウザーログインまたはアプリ管理の分離された `claude setup-token` フローによる Claude サブスクリプション、あるいは Codex バックエンドの ChatGPT/Codex サブスクリプションログインを利用できます。組み込みクラウドプロバイダーとカスタムゲートウェイには、それぞれのキーが必要です。

### どのモデルプロバイダーを使用できますか？

回答：設定中または `Settings → Model` でプロバイダー選択を開き、インストール済みアプリと選択したエージェントバックエンドが対応する選択肢を確認してください。組み込みクラウドプロバイダー、互換 Custom Gateway、共有または分離ログインの Claude サブスクリプション、Codex バックエンドの Codex サブスクリプションを利用できます。

### モデル接続テストが失敗するのはなぜですか？

回答：API Key に文字抜けや空白がないか、Base URL と地域が正しいか、プロバイダーの正確なモデル ID を使用しているかを確認し、ネットワーク接続とアカウント残高も確認してください。Claude サブスクリプションでは、選択モードに応じて共有ブラウザーログインを再試行するか、分離された `claude setup-token` 認証情報を更新してください。

### 設定中に `Continue` が無効なのはなぜですか？

回答：現在の手順の必須条件を満たしていません。手順に応じて、`Action needed` の環境項目を解決する、選択したエージェントランタイムをインストールまたは修復する、モデルプロバイダーを検証する、のいずれかを行ってください。Notebook 設定は任意で、Notebook の実行だけに影響します。

### 設定が完了しました。研究タスクを始めるにはどうすればよいですか？

回答：プロジェクトを作成または開き、セッションを開始して、ソースファイルを添付し、目標、制約、必要な出力、検証基準を説明します。`@` でプロジェクトファイルを参照し、`/` で有効なスキルを選択します。

### リモート HPC クラスターでジョブを実行するにはどうすればよいですか？

回答：**Settings → Skills** で **Remote Compute (SSH)** スキルを有効にし、**Settings → Compute** でクラスターを登録します。セッションを開始して `/remote-compute-ssh` でスキルを選択してください。ホスト登録、SSH による短いコマンド、完全非同期のジョブ送信をスキルが処理します。ジョブ完了時にアプリが分析ターンを自動開始するため、ポーリングループは不要です。

### コマンドラインインターフェースはありますか？

回答：あります。**Settings → General → Command line tool → Install command** からワンクリックでインストールできます（`open-science` を PATH に追加し、別途 Node.js は不要です）。CLI はブラウザーを開かずにローカルサービスを制御し、研究タスクを送信します。

```bash
# サービスをバックグラウンドで開始
open-science start --no-open

# プロジェクトを作成し、正確な名前でタスクを実行
open-science project create "Systematic review"
open-science run --project "Systematic review" \
  --prompt-file ./task.md \
  --approval-profile auto \
  --skill literature-review \
  --wait --json

# 生成されたアーティファクトをダウンロード
open-science artifacts list <session-id> --json
open-science artifacts download <artifact-id> --output ./report.md
```

完全なコマンドリファレンス、JSON/JSONL 出力形式、終了コード、ヘッドレスサービスの選択肢は [CLI ガイド](../../packages/open-science/CLI.md)を参照してください。

### 生成結果の出所を確認するにはどうすればよいですか？

回答：生成されたアーティファクトを開き、**Provenance** を選択します。バージョンを選択し、コンテンツ ID と、利用できる生成コード、実行履歴、入力、環境インベントリ、生成元の会話コンテキスト、レビュー根拠を確認します。Open Science が検証できなかった根拠は利用不可と表示されます。

### 後続の会話を失わずに以前のリクエストを変更できますか？

回答：できます。完了したユーザーメッセージを編集して再送信すると、その位置から新しいブランチが作成されます。元の後続ターンは残り、メッセージ横のリビジョン矢印で別の経路に切り替えられます。

### 研究データは自分のコンピューターに残りますか？

回答：プロジェクト、セッション、ファイル、設定、構成済み認証情報はデフォルトでローカルに保存されます。モデルリクエスト、ウェブ検索、コネクタ呼び出しに必要な内容は、選択した外部サービスへ送信される場合があります。タスク実行前に機密入力とプロバイダーのポリシーを確認してください。
