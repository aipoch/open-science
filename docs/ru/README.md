## 🚀 Быстрый старт

### 1. Скачайте приложение

Откройте [официальную страницу загрузки](https://aipoch.com/open-science/download) и выберите установщик для своего компьютера:

| Ваш компьютер                            | Что выбрать                                     |
| ---------------------------------------- | ----------------------------------------------- |
| macOS 12+ — Apple Silicon (M1 или новее) | DMG для macOS на Apple Silicon / ARM64          |
| macOS 12+ — Intel                        | DMG для macOS на Intel / x64                    |
| Windows 10/11 x64                        | Установщик для Windows x64 (с кодовой подписью) |
| Linux x64                                | AppImage или пакет Debian для Linux x64         |
| Linux ARM64                              | AppImage или пакет Debian для Linux ARM64       |

Проверки перед установкой описаны в разделе [проверки загрузки](../../SECURITY.md#verifying-your-download).

Архивы автономного CLI для macOS, Linux и Windows включают Node.js и работают без Homebrew и npm.

В macOS приложение также можно установить через [Homebrew](https://brew.sh):

```bash
brew install --cask open-science
```

Для автономного CLI в macOS или Linux используйте отдельный [tap AIPOCH](https://github.com/aipoch/homebrew-tap):

```bash
brew install aipoch/tap/open-science
```

Формула включает Node и работает без настольного приложения; её версия может отличаться от настольного Cask. Требования и обновления описаны в [руководстве по автономной среде](../standalone-runtime.md).

Для автономного CLI и веб-интерфейса установите опубликованный [пакет npm](https://www.npmjs.com/package/@aipoch/open-science), используя **Node.js 22.13.0 или новее**:

```bash
npm install --global @aipoch/open-science
open-science start --no-open
open-science url
```

Откройте выведенный URL для настройки или следуйте [руководству по настройке в терминале](../../packages/open-science/CLI.md#first-run-setup-codex). npm поддерживает macOS ARM64/x64, Linux ARM64/x64 с glibc и Windows x64; настольное приложение не требуется. Не отключайте необязательные зависимости npm и ознакомьтесь с [требованиями Linux и инструкциями по обновлению](../standalone-runtime.md#install-from-npm). URL содержит токен аутентификации; не передавайте его другим.

Переустановка в Windows сохраняет исследовательские данные. Для полной очистки используйте [инструмент сброса](../../scripts/windows-reset/README.md), который после подтверждения безвозвратно удаляет локальные данные.

### 2. Пройдите первоначальную настройку

Пройдите мастер настройки: **Среда → Расположение данных → Среда выполнения агента → Поставщик моделей → Среда выполнения Notebook**.

Пройдите обязательные проверки среды и среды агента, затем проверьте подключение к модели. Настройка Python/R Notebook необязательна; параметры Notebook и расположение данных можно изменить позже.

Параметры оформления и уведомлений находятся в системных настройках. В разделе **«Общие»** есть ссылка на руководство по ручной установке и обновлению.

Прежняя вкладка «Модель» теперь называется **Локальные возможности** и объединяет извлечение PDF, языковые пакеты OCR и озвучку исследований. Для озвучки нужна локально установленная голосовая модель.

### 3. Создайте исследовательский проект

1. Нажмите **«Новый проект»**, откройте сессию и опишите цель исследования, входные данные и ожидаемые результаты.
2. Прикрепите файлы, выберите модель и профиль разрешений, затем отправьте задачу. Используйте `@` для ссылки на файл проекта или `/` для выбора навыка.
3. Просматривайте действия инструментов и запросы разрешений, изучайте результаты и доступные свидетельства в представлении **«Происхождение»**.

> Снимки экрана в этом README показывают общий рабочий процесс. Надписи, каталоги и другие детали интерфейса могут отличаться от установленной версии.

## Исследовательские пакеты `.science` AIPOCH Open-Science

Завершённую исследовательскую сессию можно экспортировать в переносимый пакет `.science` для проверки, передачи коллегам и архивирования. Выберите ветви диалога, версии файлов, записи Notebook и свидетельства верификации, которые нужно включить, а затем импортируйте пакет в другой проект или на другой компьютер.

Экспорт и импорт доступны в настольном приложении, локальных веб-сессиях и автономном CLI. Удалённые веб-сессии не могут читать и записывать пакеты по произвольным локальным путям.

**Экспортировать → передать → проверить**

1. Экспортируйте завершённую сессию и выберите содержимое пакета.
2. Передайте файл `.science` коллеге или на другой компьютер.
3. Импортируйте файл в проект. Справа **Research replay** показывает записанный процесс; в диалоге слева можно задавать вопросы и ссылаться на фиксированные шаги.

Импортированные записи остаются доступными только для чтения. Просмотр не выполняет код, не вызывает модель и не восстанавливает учётные данные. Первый вопрос создаёт связанный редактируемый диалог; **Fork to continue** создаёт рабочую копию. Для повторного выполнения по-прежнему нужны полный рецепт, необходимые входные данные и доступная среда.

Вопросы из импортированного исследования или шага воспроизведения открывают дочерние обсуждения, связанные с шагом, не изменяя импорт. Они сохраняются при архивации; удаление родителя превращает их в обычные диалоги.

Диалоги Side Chat, личные закладки чтения и учётные данные исключены; состав файлов зависит от выбора при экспорте. Полученные записи проверки описывают действия отправителя, а не повторный запуск на этом компьютере. См. [руководство по пакетам `.science`](https://aipoch.com/docs/guides/research-packages/).

### ASI-Bench — Выполнение плана и выбор методов

Четыре условия требуют от агента выполнить заданный план (B1), организовать рабочий процесс (B2), выбрать методы исследования (B3) или провести исследование при наличии отвлекающей информации (B4). Первые две строки диаграммы сравнивают локальные запуски с одной моделью GPT-6 Astra.

![Результаты AIPOCH Open-Science на ASI-Bench B1–B4 рядом с локальными запусками Codex и опубликованными ориентирами](../images/readme/asi-bench-b1-b4.jpg)

Open-Science получила **79.35, 56.11, 59.67 и 59.46** на B1–B4; локальный ориентир Codex — **74.78, 56.09, 58.12 и 55.45**. Оценки B2 почти совпали. Другие опубликованные запуски отличаются экземплярами задач, настройками или процедурой оценки.

Локальная оценка B1 охватывает 59 задач после исключения одной из-за проблемы с оценщиком. Для B1/B2 сообщалось о трёх локальных повторах. B3/B4 использовали Open-Science v0.32.0 и заменённую модель-судью; каждый балл — среднее трёх запусков по 60 задач.

Диаграмма объединяет записи с разным охватом моделями-судьями. «#1» описывает порядок в этой подборке. Рейтинг по единой процедуре потребовал бы сопоставимой оценки всех записей.

79.05 — средний судейский балл этой внутренней оценки.

</details>

**Границы оценки:** отчёты охватывают локальные или внутренние запуски с августа по ноябрь 2026 года с указанными моделями и разбиениями данных; для текущего выпуска их не повторяли. Эталонные баллы — исторические срезы, а не текущие рейтинги. Баллы разных семейств бенчмарков напрямую несопоставимы, а численные разрывы не устанавливают статистическую значимость.

Подробности доступны в [отчёте AstaBench и ASI-Bench](https://aipoch.com/benchmark/open-science) и [отчёте BiomniBench-DA](https://aipoch.com/blog/open-science-biomnibench-da).

## Зачем использовать AIPOCH Open-Science?

1. **Читайте статьи и анализируйте данные в одном проекте.**
   - Импортируйте публикации из Zotero или вставьте до 100 идентификаторов или ссылок за раз. Настройте модель для отбора статей по вашим критериям включения и исключения. Сравните решения модели со своими и откройте PDF, чтобы проверить вывод в контексте статьи.
   - Просматривайте научные данные, документы, изображения и молекулярные структуры рядом со статьями. Запустите Python или R в блокноте, постройте таблицу или график по данным проекта и сопоставьте результат с исходными файлами.

2. **Проверяйте, как получен результат и чем подкреплён ответ.**
   - Откройте нужную версию рисунка, таблицы или отчёта в **Provenance**, чтобы изучить доступные исходные данные, код и историю выполнения. Если доступны входные данные, порядок действий и среда выполнения, повторите запуск в настольном приложении и сравните результаты.
   - Включите **Reviewer** для отдельной проверки ответа агента по журналам и файлам, доступным для данного шага. Изучите выявленные проблемы и результаты повторной проверки после внесения исправлений агентом.

3. **Передавайте коллегам результат вместе с контекстом.**
   - Выберите ветви диалога, версии файлов, записи блокнота и материалы проверки для пакета `.science`. Коллега сможет открыть его на другом компьютере и проследить, как была получена таблица или рисунок.
   - Импортированная запись доступна только для чтения. При импорте код не выполняется, а учётные данные не восстанавливаются. В записях отражены проверки на компьютере отправителя. Чтобы изучить следующий вопрос, коллега может выбрать **Fork to continue** и работать в редактируемой копии.

4. **Подбирайте инструменты и вычислительные ресурсы для анализа.**
   - Выберите поставщика моделей и используйте **48 встроенных коннекторов** для доступа к научным источникам данных. Некоторые коннекторы нужно предварительно включить.
   - Для регулярных задач доступны **24 встроенных навыка**. В [каталоге навыков](https://github.com/aipoch/openscience-skill-marketplace) можно выбрать для установки **525 навыков**. Чтобы делегировать часть работы, выберите одного из **10 специалистов** в [каталоге специалистов](https://github.com/aipoch/openscience-specialist-marketplace).
   - Запускайте анализ локально или отправляйте задание в управляемую вами среду через SSH, Slurm, Kubernetes, Hugging Face Jobs, Modal или Ray. Перед подтверждением удалённого задания проверьте целевую среду, команду, ресурсы и выходные данные. За облачные задания может взиматься плата с подключённого аккаунта.

## Поставщики моделей

На уровне продукта AIPOCH Open-Science не привязан к конкретным моделям: можно подключить крупного облачного поставщика LLM, пользовательский шлюз или существующую подписку Claude либо Codex. Доступность поставщиков зависит от выбранной среды агента и поддерживаемых ею протоколов API. Доступны следующие способы подключения:

| Режим поставщика                   | Как это работает                                                                                                                                                                                                                                                                                                                                                                                                                              |
| ---------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Встроенные облачные поставщики** | Выберите поставщика из списка в установленном приложении и укажите требуемый ключ.                                                                                                                                                                                                                                                                                                                                                            |
| **Пользовательский шлюз**          | Укажите Base URL, точный ID модели и протокол API, поддерживаемый выбранной средой агента (Messages, Chat Completions или Responses), затем проверьте соединение. Удалённым шлюзам нужны HTTPS и API-ключ. Адреса обратной петли, например `localhost`, `127.0.0.1` или `[::1]`, допускают HTTP без ключа; доступны шаблоны для Ollama, LM Studio, llama.cpp и vLLM. Формат API по умолчанию не гарантирует совместимость сервера или модели. |
| **Подписка Codex**                 | Выберите Open-Science Agent или Codex, затем укажите подписку Codex как тип поставщика. Импортируйте существующий вход Codex или войдите через Open-Science.                                                                                                                                                                                                                                                                                  |
| **Подписка Claude**                | Войти по подписке Claude можно в двух режимах: **общем** (вход через браузер с сохранением учётных данных в стандартном профиле `~/.claude`) или **изолированном** (запуск `claude setup-token` под управлением приложения в собственном `CLAUDE_CONFIG_DIR`, полностью отделённом от `~/.claude/`; доступны вход через браузер и резервная вставка токена).                                                                                  |
| **xAI (Grok) OAuth**               | Используйте встроенный вход по коду устройства xAI (Grok) OAuth. Доступ зависит от учётной записи xAI и протоколов выбранного бэкенда; проверьте соединение в приложении.                                                                                                                                                                                                                                                                     |

Доступно 25 предустановленных вариантов провайдера, включая OpenAI, Anthropic, DeepSeek, NVIDIA Build и другие. Модели и региональные адреса зависят от установленной версии и выбранного бэкенда; проверяйте список и подключение в приложении.

## Данные, разрешения и доверие

AIPOCH Open-Science хранит данные проекта, настройки, версии артефактов и свидетельства происхождения на локальном компьютере. API-ключи также хранятся локально и, если возможно, защищаются системным хранилищем учётных данных. Журналы не загружаются автоматически.

Тем не менее данные могут передаваться внешним сервисам, и это следует учитывать:

- В запросах к модели выбранному поставщику отправляются запрос пользователя и необходимый контекст.
- Поиск в интернете и удалённые коннекторы передают внешним сервисам отображаемые параметры.
- Локальные коннекторы могут выполнять на компьютере доверенные команды.
- Приложение также может обращаться к серверам обновлений, каталогам маркетплейса и сервисам загрузки сред выполнения или моделей.
- Вложения, ссылки `@`, журналы и созданные отчёты могут содержать чувствительные исследовательские данные.

Выбирайте самый ограниченный профиль разрешений, который подходит для задачи:

| Режим                               | Поведение                                                                                                                                                        | Когда использовать                                             |
| ----------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------- |
| `Запросить разрешение`              | Запрашивает разрешение на действия, не покрытые существующими ограниченными разрешениями или политиками доверенных инструментов приложения                       | Новые процессы, чувствительные данные, незнакомые скрипты      |
| `Автоматически разрешать изменения` | Использует автоматическую проверку самой среды агента, если она доступна; иначе автоматически разрешает только явно малорисковые операции в рабочем пространстве | Доверенная работа с файлами при контролируемом внешнем доступе |
| `Полный доступ`                     | Автоматически разрешает изменения, команды, сеть и коннекторы                                                                                                    | Чётко ограниченная и полностью доверенная автономная работа    |

Фактический профиль зависит от среды агента и выданных разрешений. Политики коннекторов, инструментов и вычислительной сети также действуют; проверяйте фактический режим в приложении.

Перед подтверждением проверяйте параметры коннектора и действия инструментов. Не включайте API-ключи, токены доступа, идентификаторы пациентов, неопубликованные данные и чувствительные локальные пути в снимки экрана и общедоступные журналы обращений.

## Разработка и сборка

AIPOCH Open-Science состоит из обычного бэкенда Node и настольного клиента Electron на React, TypeScript, Prisma/SQLite со встроенным Open-Science Agent и дополнительными средами агентов.

Для разработки из исходного кода нужны:

- Node.js 24 (см. [`.nvmrc`](../../.nvmrc)) и npm
- Git
- Выполнение Notebook необязательно: используйте управляемые приложением среды Python/R или настроенный вами совместимый интерпретатор.

```bash
git clone https://github.com/aipoch/open-science.git
cd open-science
npm install
npm run dev
```

Команды сборки и рабочий процесс описаны в [справочнике разработки и упаковки](development-quick-reference.md) и [руководстве для участников](../../CONTRIBUTING.md).

### Локальный веб-интерфейс и автономный режим

```bash
npm run dev:web
npm run pack:backend
```

Веб-интерфейс работает с обычным сервером Node без Electron и графического окружения. `npm run dev:web` и `npm run dev:headless` собирают и запускают сервер и веб-интерфейс, без настольного клиента и значка в трее. `OPEN_SCIENCE_WEB_PORT` выбирает порт (по умолчанию `44100`); Ctrl+C корректно завершает службу переднего плана.

Для разработки нужен Node.js 24. Опубликованный пакет npm и локально собранный автономный tarball требуют Node.js >=22.13.0. Архивы Release, формула Homebrew и настольный запускатель команд содержат собственную среду исполнения.

Настольное приложение и браузер используют одну службу. Подключённые приложения и явный запрос поддержания работы через `open-science start` удерживают службу запущенной. При выходе из последнего приложения служба останавливается только при отсутствии такого явного запроса.

[CLI](../../packages/open-science/CLI.md) · [Node](../standalone-runtime.md)

### Удалённый доступ с мобильного устройства

Отсканируйте QR-код, чтобы открыть текущее рабочее пространство на телефоне или планшете через локальный Wi-Fi или туннель Pinggy. Сопряжение по Wi-Fi остаётся в локальной сети; интернет-туннели направляют трафик через серверы Pinggy, о чём сообщает диалог подключения.

### Автономные CLI и SDK

CLI для автономной работы и Node.js SDK без зависимостей используют тот же локальный демон, проекты, сессии, учётные данные и разрешения, что настольный и веб-интерфейсы. Подробная документация хранится рядом с публикуемым пакетом, чтобы справочник команд оставался единым:

- [Руководство по CLI](../../packages/open-science/CLI.md) — установка, жизненный цикл сервиса, автоматизация задач, артефакты, форматы вывода и коды завершения
- [Обзор пакета SDK](../../packages/open-science/README.md) — быстрый старт Node.js и точка входа пакета

Автономный CLI может предоставить свои исследовательские инструменты внешним MCP-клиентам через `open-science mcp`. Сначала запустите и аутентифицируйте службу выбранного профиля. Адаптер использует существующие разрешения этого профиля; это не отдельная песочница и не режим только для чтения, поэтому подключённые клиенты могут сохранять изменения и вызывать расходы на модели. Произвольный доступ к shell или RPC, управление учётными данными, импорт и экспорт файлов, загрузка по указанному пути и удалённый HTTP MCP-endpoint не предоставляются.

## Частые вопросы

<a id="почему-не-проходит-проверка-подключения-к-модели"></a>

<details>
<summary>Почему не проходит проверка подключения к модели?</summary>

О: Проверьте API-ключ на пропущенные символы и пробелы, убедитесь, что указаны правильные Base URL, регион и точный ID модели поставщика, а также проверьте доступ к сети и баланс учётной записи. Для подписки Claude повторите общий вход через браузер или обновите изолированные учётные данные `claude setup-token` — в зависимости от выбранного режима.

</details>

<a id="почему-кнопка-продолжить-недоступна-во-время-настройки"></a>

<details>
<summary>Почему кнопка «Продолжить» недоступна во время настройки?</summary>

О: Для текущего этапа не выполнено обязательное условие. В зависимости от этапа исправьте строки среды с пометкой «Требуется действие», установите или восстановите выбранную среду агента либо проверьте поставщика модели. Настройка Notebook необязательна и влияет только на выполнение Notebook.

</details>

<a id="как-запускать-задания-на-удалённом-кластере-hpc"></a>

<details>
<summary>Как запускать задания на удалённом кластере HPC?</summary>

О: **Remote Compute (SSH)** всегда включён и не требует включения в настройках. Зарегистрируйте вычислительный SSH-узел в **«Настройки → Подключения → Вычисления»**, сделайте его доступным текущей сессии, затем используйте естественный язык или `/remote-compute-ssh`. Нужны доступный SSH-узел, действующая аутентификация, права на необходимые каталоги, а также требуемые заданием ПО, зависимости и вычислительные ресурсы. Для Direct SSH планировщик не нужен; режим Slurm требует рабочей среды Slurm и права отправлять задания. «Всегда включён» относится к Skill, а не к постоянной доступности каждого зарегистрированного узла.

Для подключённых вами целей также доступны Kubernetes, Hugging Face Jobs, Modal и Ray. Перед каждой внешней отправкой подтвердите цель, команду, ресурсы и выходные данные. Записи восстановления возобновляют сбор результатов после перезапуска; опубликованные результаты открываются в Compute Preview. Учётные записи, ПО, ресурсы и права нужно подготовить самостоятельно; облачные задания могут повлечь расходы.

</details>

<a id="есть-ли-интерфейс-командной-строки"></a>

<details>
<summary>Есть ли интерфейс командной строки?</summary>

О: Да. Установите автономный CLI или воспользуйтесь **«Настройки → Общие → Инструмент командной строки → Команда установки»**, чтобы управлять уже запущенным настольным экземпляром. Для установки через npm требуется Node.js; пакеты Homebrew и автономные пакеты со встроенной средой выполнения уже включают его. Инициализируйте локальный профиль, затем управляйте службой и отправляйте исследовательские задачи, не открывая браузер:

```bash
# Запустить сервис в фоновом режиме
open-science init
open-science start --no-open

# Создать проект и выполнить задачу, указав точное имя проекта
open-science project create "Systematic review"
open-science run --project "Systematic review" \
  --prompt-file ./task.md \
  --approval-profile auto \
  --skill literature-review \
  --wait --json

# Скачать созданный артефакт
open-science artifacts list <session-id> --json
open-science artifacts download <artifact-id> --output ./report.md
```

Полный справочник команд, форматы JSON/JSONL, коды завершения и параметры автономного сервиса приведены в [руководстве по CLI](../../packages/open-science/CLI.md).

</details>

<a id="как-проверить-происхождение-созданного-результата"></a>

<details>
<summary>Как проверить происхождение созданного результата?</summary>

О: Откройте созданный артефакт и выберите **«Происхождение»**. Выберите версию, чтобы изучить идентификатор содержимого и доступные сведения о коде создателя, истории выполнения, исходных данных, составе среды, контексте ветки диалога и результатах рецензирования. Сведения, которые AIPOCH Open-Science не удалось проверить, отмечены как недоступные.

</details>

<a id="можно-ли-изменить-прежний-запрос-не-потеряв-продолжение-диалога"></a>

<details>
<summary>Можно ли изменить прежний запрос, не потеряв продолжение диалога?</summary>

О: Да. Отредактируйте завершённое сообщение пользователя и отправьте его снова, чтобы создать новую ветку с этого места. Последующие сообщения исходной ветки сохранятся, а стрелки версий рядом с сообщением позволят переключаться между вариантами.

</details>
