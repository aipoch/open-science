## Rendering measurements

On the local macOS Electron software-rasterized capture host, the large-record Stage fixture rendered 3,223 DOM nodes and 694,974 displayed characters, paginated 3,000 material versions in 40-item pages, and reached a capture-ready frame after an end-of-record seek in 280.5 ms. These are fixture measurements, not a claim about cold-loading every possible `.science` archive. The test records node count, displayed-character count and seek latency as an attachment, and enforces explicit bounds.

Pixel reproducibility applies to the same build, browser, system-font configuration, viewport, resources and fixed software rasterizer. The isolated capture host disables hardware acceleration before Electron is ready; the normal interactive workspace retains GPU acceleration. GPU cold/warm path rasterization can differ at anti-aliased curved edges, so this guarantee does not cover live GPU-window pixels or different operating systems. Resource readiness lets interactive playback continue without waiting for each capture frame. Capture readiness additionally crosses a paint boundary after the current logical frame commits, cancels superseded seeks, and includes timeout placeholders. The sequential/direct-seek comparison and the font-timeout/late-font native-capture comparison each passed six repeated runs with strict PNG equality; all seven Stage desktop checks passed together. Complex or active formats may use a labeled static fallback. MP4 encoding, audio and video export jobs are outside this release.

The historical pilot publication archive was subsequently located and tested in an isolated desktop profile. The existing 50.2 MiB, schema-version-1 archive passed all 112 inventory checksum/size checks. The production adapter retained all 7 messages, 19 tool activities, 2 Notebook runs, 17 artifact versions and 1 uploaded input archive, with no unassigned records. It produced one branch with 28 steps and 112 seconds of reconstructed presentation time. Both Notebook runs joined their original tool invocations; the 17 publication calls share one step, whose bounded preview points to the complete original evidence.

That real-archive journey exposed and corrected two integration defects: Notebook details incorrectly required a live workspace path even though native import clears it, and material actions treated uploaded files as artifacts. Detail reads now use the existing persisted reference and exact run identity without initializing a runtime. Material previews retain archive membership, owner and immutable-version checks for both resource types.

After correction, the complete Electron journey passed in 44.9 seconds: native import, paused default, play/pause, end seek and rewind, all-materials access from the starting position, the real SVG and analysis-code previews, the uploaded ZIP fallback with enabled download and verified version bytes, full first-Notebook script and saved-output inspection, a question with fixed evidence, and restart into the same discussion and paused step. Both Notebook records and their invocation mapping were checked; detailed UI inspection covered the first run. The source records, Notebook history and original archive checksum remained unchanged. One deterministic test-provider request verified question delivery and persistence, not the quality of scientific answers. Private archive contents, scripts and screenshots remain outside the repository.

This archive records an offline reanalysis/publication of one historical experiment. It does not contain the entire original project or original research conversation, and it reports missing environment lock files. This validation did not execute archived analysis, start new experiments, restore another device or claim a frame-by-frame recording of the original game.

## Persistence and retention boundaries

The current implementation reuses ordinary conversation drafts and sending. Drafts live in window-scoped `sessionStorage`; refresh recovery is supported, but this is not a durable cross-restart draft journal. The former research-specific draft/submission tables and journal are removed. Earlier execution results below describe the implementation at that date, not the current draft storage contract.

Migration 0047 creates only `SessionReplayProgress` and `SessionDiscussionSnapshot`. Source history remains in its existing stores. Checkpoints use revision comparisons and stop automatic writes after a conflict/error; active playback checkpoints every five seconds. An incomplete Notebook index leaves conversation/files visible with retry and does not save an incomplete timeline over the existing checkpoint.

The database names and fields describe two independent responsibilities:

| Table                       | Fields and meaning                                                                                                                                                                                                                                                                                                                                                    |
| --------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `SessionReplayProgress`     | `(projectId, sessionId)` identifies the replayed Session. `stateJson` stores playback position, rate and per-branch positions; `revision` is the compare-and-set version, not a Session revision. `updatedAt` is the last progress write.                                                                                                                             |
| `SessionDiscussionSnapshot` | `id` identifies one immutable capture. `sourceProjectId` and `sourceSessionId` identify the source, not the receiving conversation. `contextJson` contains the validated selection scope, source identity, evidence locators and bounded saved content. `createdAt` is the capture’s persistence time; the content’s `recordedAt` remains the original evidence time. |

Both tables reference Project ownership with cascade deletion and deliberately avoid a foreign key to the rebuildable Session index. Receiving conversations retain their association in `runtimeContext.sessionContext`, rather than in the snapshot table. Migration 0047 creates these final names directly; no rename migration, legacy-table mapping or development-data upgrade path is shipped.

Selection snapshots are immutable and retained when their source Session is removed. Unreferenced snapshots are not yet automatically collected: other windows' unsent drafts must not be mistaken for unused references. Project deletion owns final cleanup. Portable export removes local Session-reading associations and local replay locators, preserving readable labels and quotes; it does not recreate those associations on another machine.

## Discussion use cases and capability boundary

There is one discussion source per receiving conversation. `host.sessions.read()` resolves that source and lists the user's selected records across linked Branches. `host.sessions.read(record.read)` reads content, and `host.sessions.read(response.next)` continues either an index or content page. No Agent-facing snapshot ID, Project ID or mandatory Session ID is needed. Native record IDs are retained; an unambiguous selected ID infers its kind and Branch. Explicit descriptors disambiguate records shared across Branches or selected in different phases.

| User question                                       | Reading route and validation                                                                                                                                                                                                                                                      |
| --------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Explain this code/tool input                        | Selected index → returned `read`; selected input excludes later output by default.                                                                                                                                                                                                |
| What happened afterward / why did it fail?          | Read that record with explicit `part: 'result'`; errors/output are source evidence, not inferred execution.                                                                                                                                                                       |
| Compare selected steps or Branches                  | Read each returned descriptor; tests cover distinct Branches and ambiguous shared IDs.                                                                                                                                                                                            |
| Explain earlier context / summarize this discussion | List `{ kind: 'message' }` for the linked Branch; follow returned `next`. Notebook, file and review kinds allow targeted discovery.                                                                                                                                               |
| Continue after compaction or restart                | Association stays in Session runtime context; each turn includes only a small reading instruction and title/count, not copied evidence.                                                                                                                                           |
| Source Session deleted                              | Selected captured fragments remain readable with `saved-fragments-only`; uncaptured output and surrounding history stay unavailable.                                                                                                                                              |
| Compare historical plots                            | `host.viewImage({ versionId })` opens the exact Version, not its current successor. Pixels require an image-capable backend and a foreground call. Cross-Project image access is not added by Discuss; return an explicit limitation rather than interpreting metadata as pixels. |
| Unlink or choose a different source                 | Reading access follows the current association. Old messages do not silently restore it.                                                                                                                                                                                          |

Service and REPL tests validate the calls and identity boundaries. Deterministic Electron journeys validate selecting, drafting, sending and returning to the source. They do not establish how reliably each actual model chooses calls or the scientific correctness of its answer; that requires separate model evaluation.

### Shared-package learning (2026-10-01)

- The replay header offers **Ask about this research**, independent of the current playback step. It stages an ordinary conversation draft with `scope: session`; **Ask about this step** retains its existing focus. Nothing is sent automatically.
- `host.sessions.read()` returns a branch overview for a whole-research link and selected record descriptors for a step link. Step results include copyable `overview` and `nearby` options. No new MCP server is introduced.
- Overview excerpts cover the first/last three messages only, explicitly labelled as partial. Branch navigation and per-kind browse options allow deeper reading. Whole-research links authorize the source Session's branches; step links retain their selected-branch boundary.
- Nearby context uses native message, activity prompt and Notebook run prompt identities. It returns messages within two positions, with roles, message numbers, bounded excerpts and exact read options. Missing associations are stated rather than guessed.
- Source metadata identifies current saved records versus immutable file versions. Import exclusions are reported as a count when recorded; zero exclusions do not establish completeness or reproducibility. Binary metadata is explicitly not image/PDF/spreadsheet evidence.
- Every discussion turn includes REPL execution/output guidance and learning instructions: purpose before terminology, read both sides of comparisons, distinguish observed facts from inferred intent, identify coverage and missing dependencies.
- Source labels and step/message numbers are available for answers. Inline clickable citations for arbitrary Agent answers are not implemented; the existing linked-source navigation remains available. Live model answer-quality evaluation and PDF/spreadsheet content readers are outside this validation.

## Ordinary Session sources

Replay reads, checkpoints and discussion snapshots accept ordinary readable Sessions as well as imported histories. The sidebar exposes Discuss and View replay through the shared Session action menu. Source capability is separate from destination write permission: imported histories remain read-only. A running source is read from saved records when opened, not live-followed. Empty histories retain the existing disabled playback controls and cannot create a discussion selection. These source-admission changes reuse the two tables above; no additional migration or development-data compatibility path is required.

Regression coverage includes ordinary idle/running source persistence without mutation, whole-session selection when the default branch is empty, shared menu dispatch, and a real Electron journey through both ordinary-source menu actions and snapshot creation.
