# Error and warning surface decisions

This inventory covers renderer pages and application presentations. It records the placement decision,
not merely whether a file imports a shared component. Component fixtures exercise layout with
synthetic failures; they do not simulate every Electron service failure.

## Selection rules

| Situation                                                         | Presentation                                                                                            | Lifetime and recovery                                                                               |
| ----------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------- |
| Invalid field or one control failed                               | Small inline text beside the control; link with `aria-describedby` where the field owns the error       | Until corrected or retried; no modal, timer or brand mark                                           |
| A section cannot load, a save fails, or a retry needs explanation | `ErrorNotice` in the owning region; neutral surface, semantic icon, multiline text and adjacent actions | Until resolved or explicitly dismissed; keep usable content and drafts                              |
| An unavailable preview replaces its content                       | Bounded `ErrorNotice` inside the preview                                                                | Retry/open action when supported; other panes remain usable                                         |
| Database or initial Settings prevents startup                     | `ErrorNotice fullPage`, centered brand flask and recovery column                                        | Blocking until its existing recovery owner succeeds                                                 |
| Irreversible deletion, discard, overwrite, privilege expansion    | `ConfirmActionDialog` or domain dialog using shared dialog chrome                                       | Explicit decision; safe Cancel focus, action-specific verb, original guards and pending state       |
| Submission fails inside a dialog                                  | Inline notice inside that same dialog                                                                   | Preserve inputs; retry there; do not open a second error modal                                      |
| Background event with no suitable active region                   | `ActionToast` in the application notification stack                                                     | Persistent when action is needed; optional timeout only when the result remains available elsewhere |
| Undo or local-file action with an identifiable page               | Inline notice by the relevant content/toolbar                                                           | Preserve original undo deadline and disabled guards; no independent global overlay                  |

Single-line describes the amount of copy, not a forced `nowrap` rule. All errors must wrap at narrow
widths. A long path, translation, or diagnostic must not make buttons unreachable. Do not truncate
failure explanations into a tooltip. Technical diagnostics stay in a closed disclosure outside the
summary's live region. Amber denotes retryable failure; red denotes integrity failure; teal denotes
an update requirement. The flask is reserved for startup blockers, not routine inline errors.

## Notification timing

| Owner                                   | Dismissal                                                                                              |
| --------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| External-session lifecycle              | 6 seconds; session remains in the catalog                                                              |
| Connector reauthentication              | 8 seconds; actionable state remains in Settings / Connectors                                           |
| Missing notification target             | 6 seconds; the original message-center item remains the navigation source                              |
| Storage cleanup / language rollback     | Explicit Close / Dismiss; no automatic disappearance                                                   |
| Session catalog / write / quit recovery | Existing owner decides whether dismissal is allowed; no timer                                          |
| Permission / archive Undo               | Existing receipt deadline, renewal and pending-restore guards; layout does not invent another lifetime |
| Literature Inbox undo                   | Existing page-owned lifetime and reconciliation; inline near page actions                              |

`ActionToast` pauses its optional timer while hovered or keyboard-focused. Errors that are the only
recovery entry remain persistent. No toast appearance steals focus. The global stack remains inside
the application's inert presentation boundary; moving notices does not reactivate controls behind a
modal. Quit-save recovery retains its existing separate emergency presentation.

## Modal contract

Use a title naming the operation, followed by the affected object and the actual consequence. Keep
Cancel before the specific confirm verb and visually emphasize only the dangerous commit action.
Use the shared header/body/footer spacing and viewport-bounded panel. Long copy wraps; the generic
confirmation body scrolls while its buttons remain reachable. Busy dialogs preserve the existing
close/submit guards. Escape during IME composition does not cancel the generic confirmation.
Retain Radix focus trapping and safe cancellation focus. Specialized editors, consent and permission
dialogs retain their rich content and established focus targets instead of being flattened into a
binary generic prompt.

## Compatibility and ownership

- No database, file format, migration, IPC contract or persistence changes.
- No new business state or enum value. New optional component props are presentation-only.
- No historical-data conversion or compatibility shim is required.
- Existing rebase additions, including Skill replacement impact summaries, are preserved.
- ErrorNotice owns layout only; callers retain translation, retries, consent, disabled state and
  diagnostics. ActionToastStack owns geometry only, not a notification queue or event subscription.

## References and verification

Placement follows [Carbon notification guidance](https://carbondesignsystem.com/patterns/notification-pattern/):
use local persistent recovery when users must act and reserve interruption for decisions. Keyboard
behavior follows the [WAI-ARIA modal dialog pattern](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/),
including focus containment and considering the least destructive initial action. These references
support the interaction rules; the colors and spacing use this project's tokens.

`e2e/browser/error-surfaces.spec.ts` verifies real shared components at narrow widths, diagnostic
announcement boundaries, safe dialog focus, reachable buttons and non-overlapping global notices.
Renderer component and consumer suites cover the owner callbacks and state guards. The fixture at
`e2e/browser/fixture/error-surfaces.html` provides reproducible light/dark screenshots. Full portable
and cross-platform verification belongs to PR CI; the local run is a focused impact set.
