## ✨ 亮点

- **更新不再打扰你。** 在 macOS 上，符合条件的更新可在退出应用时自行安装；在 Windows 和 Linux 上，更新可在你工作时预先为下次启动做好准备。后台下载只在网络不受限且本地存储空间充足时才会进行，而手动下载并重启的路径始终保留；在 Linux 上，AppImage 路径在更新后保持不变。更新下载体积也更小，Windows 稳定版更新可以增量包的形式应用。(#4542, #4518, #4586, #4510)
- **内置 Agent 成为全局默认。** 新建项目和会话默认使用内置 Open-Science Agent——包括全新安装的 CLI 和 SDK，在外部 Agent SDK 缺失时不再启动失败。安装外部运行时是始终由你主动做出的明确选择，仅在你需要时进行。(#4531)
- **更轻量的应用。** macOS 和 Windows 上的桌面安装体积更小，内置的离线 npm 运行时已改为基于 Node 22 编译，不再附带一千多个零散包文件。(#4555, #4572, #4563, #4592, #4587)
- **统一的图像编辑。** 编辑指令位于会话输入框内，悬停和键盘操作可从任意预览进入编辑，整个过程中版本导航与对比始终可用。(#4481)
- **失败会说明原因。** 应用中各处含糊的错误现在会说明真正发生了什么——请求失败、文件与来源加载问题、Notebook 执行错误，以及你主动停止的工作与从未应答的工作之间的区别。(#4565, #4571, #4548, #4549, #4545, #4540, #4583, #4593)

## ⚠️ 适用范围与安全

- **自动更新在后台下载。** macOS 仅在退出应用时安装更新；Windows 和 Linux 仅在桌面处于后台空闲时预先准备更新——所有平台都要求有明确的证据表明网络不受限、未按流量计费且本地存储空间充足，Linux 还要求更新缓存可写。按流量计费的受限连接仍保留完全手动的更新路径。(#4542, #4518, #4586)
- **安装外部 Agent 运行时会从 npm registry 下载。** 选择外部框架时，应用托管的安装程序会从 npm registry（或其文档记录的镜像回退源）下载其运行时，并在使用前校验下载内容。部分托管运行时会解析最新发布的版本，另一些则附带固定版本或随代码库检入的锁文件，仅随应用发布更新。内置 Agent 无需此类下载。参见[数据接收方](https://github.com/aipoch/open-science/blob/v1.3.3/docs/security.md#data-recipients)。(#4531)

## 🚀 新功能

- 在官方打包的稳定版 macOS 构建上，符合条件的更新可在退出应用时自动安装；只读卷、App Translocation 和不可写的安装位置仍保留手动路径。(#4542)
- 在打包的稳定版 Windows 安装上，一个默认开启的偏好设置会在工作区就绪、桌面处于后台、网络不受限且存储空间充足时，于启动阶段预先准备下次启动的更新；手动下载始终可用。(#4518)
- 在打包的 Linux 安装上，一个默认开启的偏好设置会在桌面处于后台空闲时预先准备下次启动的 AppImage 更新，前提是网络不受限且更新缓存空间充足；AppImage 路径在更新后保持不变，手动下载路径仍然可用。(#4586)
- Bailian 提供商目录新增 qwen4 模型系列，套餐默认使用 qwen4 预览版。(#4594)
- 设置恢复了 Skills、Specialists 和 Connectors 快捷入口，各自打开已安装类别并返回其在设置中的原有位置。(#4538)
- Windows 稳定版更新可以紧凑、可独立复现的安装器增量包形式应用，生产环境桌面端的 source map 也不再内嵌原始源码文本。(#4510)

## 🔧 改进

- 桌面安装体积更小：macOS 和 Windows 上会清理经审计的 Electron 侧依赖副本，第三方后端依赖得到精简、内部后端包模块被打包合并，离线 npm 运行时已编译为面向 Node 22 的单一 bundle，film 编译器与 web 资源也经过压缩。(#4555, #4572, #4563, #4554, #4592, #4587)
- 新建项目和会话默认使用内置 Open-Science Agent；外部 Agent 运行时通过托管的、带校验的安装器按需安装。(#4531)
- 会话输入框会在详情视图中展示含糊的请求失败，说明排队消息投递失败的原因，预览会说明文件与来源加载失败的原因，会话历史读取失败会得到解释，附件暂存与清理失败也会说明问题所在。(#4565, #4583, #4571, #4548, #4539)
- Notebook 环境将清单保存在 sidecar 文件中，shell 截止时间延长并保留停止原因，历史读取和长输出的布局开销更低，连接器的错误会在宿主工具列表中呈现。(#4547, #4544, #4533, #4551)
- 通过有界的文本分段工作，流式回复在长对话中保持响应速度；图像编辑器在你进入编辑时保持会话消息位置不动。(#4520, #4559)
- 应用会跳过重新读取未更改的内置技能文档，也会为空网络审批跳过分支遍历。(#4534, #4535)

## 🐛 问题修复

- 提供商错误详情保留已分类的失败代码与请求 id，模型失败在重启后仍可据此处理。(#4590)
- 在 Windows 上，Notebook 内存阈值会按已安装的物理内存封顶，被阻止的运行保留其内存读数，同时会显示 macOS 的内存压力与 Linux 的 cgroup 限制。(#4593)
- 在 Windows 上，早期会话遗留的过期文件占用会在冷启动时重新检查并清除，使已预先准备的更新得以完成应用。(#4591)
- 托盘会话条目在持久化投影尚未追平之前，会使用恢复出的摘要进行导航。(#4582)
- PDF 翻译修复：原生提取在分栏处、题注或行内公式处拆开的句子会结合字体、字形和几何证据重新接合，译文不再挤占原生记号、表单标签或相邻图形。(#4560)
- 已停止的工作得到正确标注：用户停止的提示会在清理后落定，已停止的运行会与未应答的续跑区分开，过期的诊断信息不再覆盖取消信息，空闲会话会恢复脱落的运行标记。(#4552, #4545, #4537)
- 模型失败被准确分类：上游失败与格式错误的响应、客户端栈溢出区分开，安全诊断信息得到保留，Responses 流式生命周期不再过早上报完成。(#4540, #4511)
- 在 Windows 上，Notebook 内核在重启后恢复运行时状态，profile key 会在检查缓存更新之前完成初始化。(#4529, #4569)
- 回复文件名正确解析为已保存的构件，记忆类别删除与已确认笔记正确绑定，会话包会先让 Notebook 读取落定再说明导出失败。(#4562, #4512, #4564)
- 图像编辑预览保持稳定，图像详情会展示产生该编辑的 Notebook 内核，当计算设备已准备就绪时更新操作会隐藏。(#4553, #4557, #4558)
- 项目文件读取会说明失败并检查不确定的修复，GitHub 技能导入会说明连接失败，定时会话与认证方面的回归问题得到修复。(#4541, #4532, #4530)
