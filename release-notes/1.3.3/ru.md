## ✨ Основные изменения

- **Обновления, которые не мешают работе.** На macOS подходящее обновление может установиться при выходе из приложения; на Windows и Linux обновление может быть подготовлено к следующему запуску, пока вы работаете. Фоновые загрузки допускаются только в неограниченной сети с достаточным объёмом хранилища, а ручной путь загрузки с перезапуском остаётся всегда; на Linux путь к AppImage сохраняется между обновлениями. Загрузки обновлений стали меньше, а стабильные обновления Windows могут применяться как компактные дельты. (#4542, #4518, #4586, #4510)
- **Встроенный агент — стандарт выбора везде.** Новые проекты и сеансы начинаются со встроенным Open-Science Agent — включая чистые установки CLI и SDK, которые больше не завершаются ошибкой при запуске при отсутствии внешнего агентного SDK. Установка внешней среды выполнения остаётся явным выбором, который делается только при необходимости. (#4531)
- **Более компактное приложение.** Установленный десктоп стал меньше на macOS и Windows, а входящая в комплект автономная среда npm теперь скомпилирована для Node 22 вместо поставки более чем тысячи отдельных файлов пакетов. (#4555, #4572, #4563, #4592, #4587)
- **Единое редактирование изображений.** Инструкции редактирования находятся в композере разговора, действия по наведению и с клавиатуры открывают редактирование из любого предпросмотра, а навигация по версиям и сравнение остаются доступными на протяжении всего процесса. (#4481)
- **Сбои объясняют сами себя.** По всему приложению непрозрачные ошибки теперь называют то, что действительно произошло, — сбои запросов, проблемы загрузки и импорта, ошибки выполнения Notebook и различие между работой, которую вы остановили, и работой, которая так и не ответила. (#4565, #4571, #4548, #4549, #4545, #4540, #4583, #4593)

## ⚠️ Область применения и безопасность

- **Автоматические обновления загружаются в фоне.** macOS устанавливает обновление только при выходе, а Windows и Linux готовят его только пока десктоп находится в фоне и неактивен — все варианты требуют положительных подтверждений неограниченной безлимитной сети и достаточного локального хранилища, включая доступный для записи кэш обновлений на Linux. Лимитные или ограниченные подключения сохраняют полностью ручной путь. (#4542, #4518, #4586)
- **Установка внешней среды агентов загружает данные из реестра npm.** Выбор внешнего фреймворка загружает его среду выполнения из реестра npm — или из документированного резервного зеркала — через управляемый установщик приложения, который проверяет загруженное перед использованием. Некоторые управляемые среды выполнения определяют последнюю опубликованную версию, а другие поставляются с фиксированными версиями или внесённым в репозиторий файлом блокировки и обновляются только вместе с выпуском приложения. Встроенному агенту такая загрузка не нужна. См. [получателей данных](https://github.com/aipoch/open-science/blob/v1.3.3/docs/security.md#data-recipients). (#4531)

## 🚀 Новые возможности

- В официальных собранных стабильных сборках macOS подходящее обновление может установиться автоматически при выходе из приложения; тома только для чтения, App Translocation и незаписываемые установки сохраняют ручной путь. (#4542)
- В собранных стабильных установках Windows включённая по умолчанию настройка готовит обновления к следующему запуску при старте, когда рабочая область готова, десктоп находится в фоне, подключение неограничено и в хранилище есть место; ручная загрузка остаётся доступной. (#4518)
- В собранных стабильных установках Linux включённая по умолчанию настройка готовит обновления AppImage для следующего запуска, пока десктоп находится в фоне и неактивен, — только при неограниченном подключении и наличии места в кэше обновлений; путь к AppImage сохраняется между обновлениями, а ручная загрузка остаётся доступной. (#4586)
- Каталог поставщика Bailian пополняется семейством моделей qwen4, а план по умолчанию использует предварительную версию qwen4. (#4594)
- Настройки возвращают ярлыки Skills, Specialists и Connectors, каждый из которых открывает установленную категорию и возвращается к своей позиции в Настройках. (#4538)
- Стабильные обновления Windows могут применяться как компактные, независимо воспроизводимые дельты установщика, а исходные карты источников продакшен-десктопа больше не встраивают исходный текст. (#4510)

## 🔧 Улучшения

- Установленное десктопное приложение стало меньше: проверенные копии зависимостей на стороне Electron удаляются на macOS и Windows, сторонние зависимости бэкенда сокращены, а внутренние пакетные модули бэкенда собраны в единый бандл, автономная среда npm скомпилирована для Node 22, а компилятор фильмов и веб-ресурсы уплотнены. (#4555, #4572, #4563, #4554, #4592, #4587)
- Новые проекты и сеансы по умолчанию используют встроенный Open-Science Agent; внешние среды агентов устанавливаются по требованию через управляемый, проверенный установщик. (#4531)
- Композер показывает непрозрачные сбои запросов в представлении сведений, объясняет сбои доставки отложенных сообщений, предпросмотры объясняют сбои загрузки файлов и источников, сбои чтения истории разговора объясняются, а сбои подготовки и очистки вложений сообщают, что пошло не так. (#4565, #4583, #4571, #4548, #4539)
- Среды Notebook хранят свои манифесты в отдельных сопутствующих файлах, сроки оболочки продлеваются с сохранением причин остановки, чтения истории и раскладка длинных выводов обходятся дешевле, а ошибки коннекторов отображаются в списке инструментов хоста. (#4547, #4544, #4533, #4551)
- Потоковые ответы остаются отзывчивыми в длинных разговорах благодаря ограниченной работе сегментации текста, а редактор изображений сохраняет сообщения разговора неподвижными, пока вы вводите правку. (#4520, #4559)
- Приложение пропускает повторное чтение неизменённых встроенных документов навыков и обход ветвей для пустых сетевых разрешений. (#4534, #4535)

## 🐛 Исправления ошибок

- Сведения об ошибках поставщика сохраняют классифицированный код сбоя и идентификатор запроса, поэтому сбои моделей остаются разбираемыми после перезапуска. (#4590)
- На Windows пороги памяти Notebook ограничиваются установленной физической памятью, заблокированные запуски сохраняют свои показания памяти, а давление памяти macOS и лимиты cgroup Linux выводятся в интерфейс. (#4593)
- На Windows устаревшие блокировки файлов, оставленные предыдущим сеансом, перепроверяются и снимаются при холодном запуске, чтобы подготовленное обновление могло завершить применение. (#4591)
- Записи сеансов в трее открываются с восстановленными сводками, пока долговечная проекция ещё догоняет. (#4582)
- Исправления перевода PDF: нативное извлечение, разделявшее предложения на границах колонок, подписей или встроенных формул, восстанавливается с использованием доказательств шрифта, глифов и геометрии, а переведённый текст больше не смещает нативные обозначения, метки форм или соседнюю графику. (#4560)
- Остановленная работа маркируется корректно: остановленные пользователем запросы завершаются после очистки, остановленный запуск отличается от неотвеченного продолжения, устаревшая диагностика больше не заменяет сообщения об отмене, а неактивные сеансы восстанавливают отсоединённые маркеры запусков. (#4552, #4545, #4537)
- Сбои моделей классифицируются точно: сбои на стороне сервиса отличаются от искажённых ответов и исчерпания стека на стороне клиента, безопасная диагностика сохраняется, а жизненный цикл потока Responses больше не сообщает о завершении преждевременно. (#4540, #4511)
- На Windows ядра Notebook восстанавливают статус своей среды выполнения после перезапуска, а ключ профиля инициализируется до проверок кэшированных обновлений. (#4529, #4569)
- Имена файлов ответов разрешаются к сохранённому артефакту, удаление категории памяти привязывается к подтверждённым заметкам, а пакеты сеансов дают чтениям Notebook завершиться перед объяснением сбоев экспорта. (#4562, #4512, #4564)
- Предпросмотры редактирования изображений остаются стабильными, сведения об изображении показывают ядро Notebook, породившее правку, а действие обновления скрывается, когда вычислительное устройство уже подготовлено. (#4553, #4557, #4558)
- Чтения файлов проекта объясняют сбои и проверяют неуверенные исправления, импорты навыков GitHub объясняют сбои подключения, а регрессии запланированных сеансов и сертификации исправлены. (#4541, #4532, #4530)
