## ✨ Highlights

- **방해하지 않는 업데이트.** macOS에서는 자격을 갖춘 업데이트가 앱을 종료할 때 스스로 설치될 수 있고, Windows와 Linux에서는 작업하는 동안 다음 실행을 위한 업데이트를 준비할 수 있습니다. 백그라운드 다운로드는 제한 없는 네트워크와 충분한 저장 공간이 있을 때만 허용되며, 수동으로 다운로드한 뒤 재시작하는 경로는 항상 그대로 남아 있습니다. Linux에서는 업데이트를 거쳐도 AppImage 경로가 유지됩니다. 업데이트 다운로드 크기도 줄었고, 안정 Windows 업데이트는 작은 델타로 적용될 수 있습니다. (#4542, #4518, #4586, #4510)
- **어디에서나 내장 Agent가 기본값입니다.** 새 프로젝트와 세션은 내장 Open-Science Agent로 시작합니다 — 깨끗한 CLI와 SDK 설치도 포함하며, 더 이상 외부 에이전트 SDK가 없을 때 시작에 실패하지 않습니다. 외부 런타임 설치는 필요할 때만 내리는 명시적인 선택으로 남습니다. (#4531)
- **더 가벼운 앱.** 설치된 데스크톱은 macOS와 Windows에서 더 작아졌고, 번들된 오프라인 npm 런타임은 천 개가 넘는 개별 패키지 파일을 싣는 대신 이제 Node 22용으로 컴파일됩니다. (#4555, #4572, #4563, #4592, #4587)
- **통합된 이미지 편집.** 편집 지시는 대화 입력기에 있고, 마우스를 올리거나 키보드 동작으로 어떤 미리보기에서든 편집에 들어가며, 버전 탐색과 비교는 계속 사용할 수 있습니다. (#4481)
- **실패가 스스로 설명됩니다.** 앱 전반에서 불투명한 오류는 실제로 일어난 일을 이제 알립니다 — 요청 실패, 로딩과 가져오기 문제, Notebook 실행 오류, 사용자가 멈춘 작업과 응답이 없는 작업의 차이입니다. (#4565, #4571, #4548, #4549, #4545, #4540, #4583, #4593)

## ⚠️ 범위와 안전

- **자동 업데이트는 백그라운드에서 다운로드됩니다.** macOS는 종료 시에만 업데이트를 설치하고, Windows와 Linux는 데스크톱이 백그라운드에서 유휴 상태일 때만 업데이트를 준비합니다 — 둘 다 제한 없는 무제한 네트워크와 충분한 로컬 저장 공간, Linux에서는 쓸 수 있는 업데이트 캐시까지 긍정적 증거가 필요합니다. 미터링되거나 제한된 연결은 완전히 수동 경로를 유지합니다. (#4542, #4518, #4586)
- **외부 에이전트 런타임 설치는 npm 레지스트리에서 다운로드합니다.** 외부 프레임워크를 선택하면 앱의 관리형 설치 프로그램이 npm 레지스트리 — 또는 문서화된 미러 대체 — 에서 해당 런타임을 다운로드하고 사용 전에 다운로드를 검증합니다. 관리형 런타임 중 일부는 게시된 최신 버전을 확인하지만, 다른 일부는 고정된 버전이나 체크인된 락파일을 포함하고 앱 릴리스가 있을 때만 업데이트됩니다. 내장 Agent는 그런 다운로드가 필요 없습니다. [데이터 수신자](https://github.com/aipoch/open-science/blob/v1.3.3/docs/security.md#data-recipients)를 참조하세요. (#4531)

## 🚀 New Features

- 공식 패키징된 안정 macOS 빌드에서는 자격을 갖춘 업데이트가 앱을 종료할 때 자동으로 설치될 수 있습니다. 읽기 전용 볼륨, App Translocation, 쓸 수 없는 설치는 수동 경로를 유지합니다. (#4542)
- 패키징된 안정 Windows 설치에서는 기본적으로 켜진 설정이 워크스페이스가 준비되고, 데스크톱이 백그라운드에 있고, 연결이 제한 없고, 저장 공간에 여유가 있으면 시작 시 다음 실행을 위한 업데이트를 준비합니다. 수동 다운로드는 계속 제공됩니다. (#4518)
- 패키징된 Linux 설치에서는 기본적으로 켜진 설정이 데스크톱이 백그라운드에서 유휴 상태일 때 제한 없는 연결과 업데이트 캐시 공간을 조건으로 다음 실행을 위한 AppImage 업데이트를 준비합니다. 업데이트를 거쳐도 AppImage 경로가 유지되며, 수동 다운로드는 계속 제공됩니다. (#4586)
- Bailian 제공자 카탈로그에 qwen4 모델 패밀리가 추가되고, 플랜은 qwen4 미리 보기를 기본값으로 사용합니다. (#4594)
- 설정에서 Skills, Specialists, Connectors 바로가기를 복원합니다. 각각 설치된 카테고리를 열고 설정의 원래 위치로 돌아옵니다. (#4538)
- 안정 Windows 업데이트는 작고 독립적으로 재현 가능한 설치 프로그램 델타로 적용될 수 있고, 프로덕션 데스크톱 소스 맵은 더 이상 원본 소스 텍스트를 포함하지 않습니다. (#4510)

## 🔧 Improvements

- 설치된 데스크톱 애플리케이션이 더 작아졌습니다. macOS와 Windows에서 감사된 Electron 측 종속성 복사본이 정리되고, 타사 백엔드 종속성은 정리되며 내부 백엔드 패키지 모듈은 번들되고, 오프라인 npm 런타임은 Node 22용 단일 번들로 컴파일되며, 필름 컴파일러와 웹 자산이 압축됩니다. (#4555, #4572, #4563, #4554, #4592, #4587)
- 새 프로젝트와 세션은 내장 Open-Science Agent를 기본값으로 사용합니다. 외부 에이전트 런타임은 관리되고 검증된 설치 프로그램을 통해 요청 시 설치됩니다. (#4531)
- 입력기는 세부 정보 보기에서 불투명한 요청 실패를 표시하고, 대기 중인 메시지 전달 실패를 설명하며, 미리보기는 파일과 소스 로딩 실패를 설명하고, 대화 기록 읽기 실패가 설명되고, 첨부 파일 준비와 정리 실패는 무엇이 잘못되었는지 알립니다. (#4565, #4583, #4571, #4548, #4539)
- Notebook 환경은 매니페스트를 사이드카 파일에 유지하고, 셸 마감 시간은 중지 사유를 유지한 채로 연장되며, 기록 읽기와 긴 출력 레이아웃 비용이 줄고, 커넥터 오류는 호스트의 도구 목록에 표시됩니다. (#4547, #4544, #4533, #4551)
- 스트리밍된 답변은 경계가 있는 텍스트 분할 작업으로 긴 대화에서도 반응성을 유지하고, 이미지 편집기는 편집을 입력하는 동안 대화 메시지를 그 자리에 유지합니다. (#4520, #4559)
- 앱은 변경되지 않은 번들된 스킬 문서를 다시 읽지 않고, 빈 네트워크 승인에 대해서는 브랜치 탐색을 건너뛱니다. (#4534, #4535)

## 🐛 Bug Fixes

- 제공자 오류 세부 정보는 분류된 실패 코드와 요청 id를 유지하므로, 모델 실패가 재시작 이후에도 조치 가능한 상태로 남습니다. (#4590)
- Windows에서는 Notebook 메모리 임계값이 설치된 물리 메모리로 제한되고, 차단된 실행은 메모리 측정값을 유지하며, macOS 메모리 압박과 Linux cgroup 제한이 표시됩니다. (#4593)
- Windows에서는 이전 세션이 남긴 오래된 파일 차단자가 콜드 시작 시 다시 확인되어 만료되므로, 준비된 업데이트가 적용을 마칠 수 있습니다. (#4591)
- 트레이 세션 항목은 영구 프로젝션이 아직 따라잡는 중일 때도 복구된 요약으로 이동합니다. (#4582)
- PDF 번역 복구: 열 경계, 캡션, 인라인 수식에서 문장을 나누던 기본 추출은 글꼴, 글리프, 기하학적 증거를 사용해 다시 연결되고, 번역된 텍스트는 더 이상 기본 표기법, 양식 레이블, 인접한 그래픽을 밀어내지 않습니다. (#4560)
- 멈춘 작업이 올바르게 표시됩니다. 사용자가 멈춘 프롬프트는 정리 후 확정되고, 멈춘 실행은 응답하지 않는 후속 작업과 구분되며, 오래된 진단은 더 이상 취소 메시지를 대체하지 않고, 유휴 세션은 분리된 실행 표시기를 복구합니다. (#4552, #4545, #4537)
- 모델 실패가 정확하게 분류됩니다. 업스트림 실패는 잘못된 형식의 응답과 클라이언트 측 스택 고갈과 구분되고, 안전한 진단은 보존되며, Responses 스트림 수명 주기는 더 이상 완료를 일찍 보고하지 않습니다. (#4540, #4511)
- Windows에서 Notebook 커널은 재시작 후 런타임 상태를 복구하고, 프로필 키는 캐시된 업데이트 확인 전에 초기화됩니다. (#4529, #4569)
- 답변 파일 이름은 저장된 아티팩트로 확인되고, 메모리 카테고리 삭제는 확인된 노트에 연결되며, 세션 패키지는 내보내기 실패를 설명하기 전에 Notebook 읽기가 확정되도록 합니다. (#4562, #4512, #4564)
- 이미지 편집 미리보기가 안정적이고, 이미지 세부 정보는 편집을 만든 Notebook 커널을 표시하며, 업데이트 동작은 컴퓨팅 장치가 이미 준비되면 숨겨집니다. (#4553, #4557, #4558)
- 프로젝트 파일 읽기는 실패를 설명하고 불확실한 복구를 확인하며, GitHub 스킬 가져오기는 연결 실패를 설명하고, 예약된 세션과 인증 회귀가 복구되었습니다. (#4541, #4532, #4530)
