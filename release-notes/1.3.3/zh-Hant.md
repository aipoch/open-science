## ✨ 亮點

- **不打擾你的更新。** 在 macOS 上，符合條件的更新可在你結束應用程式時自行安裝；在 Windows 和 Linux 上，更新可在背景為下次啟動預先準備。背景下載僅在不受限且儲存空間充足的網路下進行，手動下載並重新啟動的路徑始終保留；在 Linux 上，AppImage 路徑在更新後保持不變。更新下載檔案也更小，穩定版 Windows 更新還能以精簡的差量形式套用。（#4542、#4518、#4586、#4510）
- **內建 Agent 成為各處預設。** 新專案與工作階段預設使用內建 Open-Science Agent——包括乾淨的 CLI 與 SDK 安裝，缺少外部 Agent SDK 時不再於啟動時失敗。安裝外部執行階段仍是明確的選擇，僅在你需要時才進行。（#4531）
- **更精簡的應用程式。** macOS 與 Windows 的安裝後桌面應用程式更小，離線 npm 執行階段現在改為針對 Node 22 編譯的單一套件，不再隨附一千多個鬆散的套件檔案。（#4555、#4572、#4563、#4592、#4587）
- **統一的影像編輯。** 編輯指令位於對話輸入框，懸停與鍵盤操作可從任何預覽進入編輯，版本瀏覽與比對功能全程可用。（#4481）
- **失敗會自我說明。** 整個應用程式中，含糊的錯誤現在會指出實際發生的情況——請求失敗、載入與匯入問題、Notebook 執行錯誤，以及你停止的工作與從未回應的工作之間的差異。（#4565、#4571、#4548、#4549、#4545、#4540、#4583、#4593）

## ⚠️ 範圍與安全

- **自動更新在背景下載。** macOS 僅在結束應用程式時安裝更新；Windows 和 Linux 僅在桌面應用程式於背景閒置時準備更新——三者都必須有明確證據顯示網路不受限、非計量連線，且本機儲存空間充足，在 Linux 上還需要可寫入的更新快取。計量或受限連線仍保留完全手動的路徑。（#4542、#4518、#4586）
- **安裝外部 Agent 執行階段會從 npm registry 下載。** 選擇外部架構會透過應用程式受管理的安裝器，從 npm registry——或其記載的鏡像備援——下載其執行階段，安裝器會在使用前驗證下載內容。部分受管理的執行階段會解析最新發布的版本，其他則固定使用特定版本或內含的鎖定檔，僅隨應用程式更新。內建 Agent 不需要此類下載。請參閱[資料接收方](https://github.com/aipoch/open-science/blob/v1.3.3/docs/security.md#data-recipients)。（#4531）

## 🚀 新功能

- 在官方封裝的穩定版 macOS 建置上，符合條件的更新可在你結束應用程式時自動安裝；唯讀磁碟區、App Translocation 與不可寫入的安裝仍保留手動路徑。（#4542）
- 在封裝的穩定版 Windows 安裝上，預設啟用的偏好設定會在工作區就緒、桌面應用程式處於背景、連線不受限且儲存空間充足時，於啟動時為下次啟動預備更新；手動下載仍然可用。（#4518）
- 在封裝的 Linux 安裝上，預設啟用的偏好設定會在桌面應用程式於背景閒置時，為下次啟動預備 AppImage 更新，並以連線不受限與更新快取空間為前提；更新後 AppImage 路徑保持不變，手動下載仍然可用。（#4586）
- Bailian 提供者目錄新增 qwen4 模型系列，方案預設為 qwen4 預覽版。（#4594）
- 設定中還原了 Skills、Specialists 與 Connectors 捷徑，各自會開啟已安裝的類別，並返回其在設定中的位置。（#4538）
- 穩定版 Windows 更新能以精簡、可獨立重現的安裝程式差量套用，正式環境桌面版的 source map 也不再內嵌原始原始碼文字。（#4510）

## 🔧 改進

- 安裝後的桌面應用程式更小：macOS 與 Windows 會裁掉經稽核的 Electron 端依賴複本，第三方後端依賴也予以修剪、內部後端套件模組則改為打包，離線 npm 執行階段編譯為 Node 22 的單一套件，film 編譯器與網頁資源也被壓縮。（#4555、#4572、#4563、#4554、#4592、#4587）
- 新專案與工作階段預設使用內建 Open-Science Agent；外部 Agent 執行階段透過受管理且經驗證的安裝器依需求安裝。（#4531）
- 對話輸入框會在詳細資料檢視中顯示含糊的請求失敗，也會說明已排入佇列的訊息傳送失敗，預覽會說明檔案與來源載入失敗，對話歷程讀取失敗也會被說明，附件暫存與清理失敗會指出出了什麼問題。（#4565、#4583、#4571、#4548、#4539）
- Notebook 環境將其 manifest 保存在附帶檔案中，Shell 期限會延長並保留停止原因，歷程讀取與長輸出版面配置的成本更低，連接器錯誤也會顯示在主機的工具清單中。（#4547、#4544、#4533、#4551）
- 透過有界的文字分段作業，串流回覆在冗長對話中保持回應靈敏；影像編輯器在進入編輯時保持對話訊息靜止不動。（#4520、#4559）
- 應用程式會略過重新讀取未變更的內建技能文件，也會略過空網路核准的分支遍歷。（#4534、#4535）

## 🐛 錯誤修正

- 提供者錯誤詳細資訊會保留已分類的失敗代碼與請求 id，模型失敗在重新啟動後仍可據以處理。（#4590）
- 在 Windows 上，Notebook 記憶體閾值以已安裝的實體記憶體為上限，被阻止的執行會保留其記憶體讀數，並顯示 macOS 記憶體壓力與 Linux cgroup 限制。（#4593）
- 在 Windows 上，冷啟動時會重新檢查並清除先前工作階段遺留的過期檔案阻擋項，讓已預備的更新得以完成套用。（#4591）
- 當持久投影仍在追趕時，系統匣工作階段項目會以復原的摘要進行導覽。（#4582）
- PDF 翻譯修復：原生擷取在欄位中斷、說明文字或行內公式處切分句子的問題，現在使用字體、字形與幾何證據重新連接；翻譯後的文字不再擠開原生標記法、表單標籤或相鄰圖形。（#4560）
- 已停止的工作標示正確：使用者停止的提示會在清理後收斂，已停止的執行會與未獲回應的延續作業區分開，過期的診斷不再取代取消訊息，閒置工作階段會復原游離的執行標記。（#4552、#4545、#4537）
- 模型失敗分類更準確：上游失敗會與格式錯誤的回應及用戶端堆疊耗盡區分開，安全的診斷會被保留，Responses 串流生命週期也不再過早回報完成。（#4540、#4511）
- 在 Windows 上，Notebook kernel 會在重新啟動後復原其執行階段狀態，設定檔索引鍵也會在檢查快取更新之前初始化。（#4529、#4569）
- 回覆檔名會解析為已儲存的成品，記憶體類別刪除會繫結到已確認的筆記，工作階段套件會讓 Notebook 讀取收斂後再說明匯出失敗。（#4562、#4512、#4564）
- 影像編輯預覽保持穩定，影像詳細資料會顯示產生編輯的 Notebook kernel，當運算裝置已準備就緒時，更新動作會隱藏。（#4553、#4557、#4558）
- 專案檔案讀取會說明失敗並檢查不確定的修復，GitHub 技能匯入會說明連線失敗，排程工作階段與認證的回歸問題也已修復。（#4541、#4532、#4530）
