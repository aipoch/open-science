## ✨ Highlights

- **邪魔にならないアップデート。** macOS では、条件を満たすアップデートがアプリ終了時に自動でインストールでき、Windows と Linux では、作業中に次回起動向けのアップデートを準備できます。バックグラウンドでのダウンロードは、制限のないネットワークと十分なストレージがある場合にのみ実行され、手動のダウンロードと再起動の手段は常に利用可能です。また、Linux では AppImage のパスがアップデートをまたいで維持されます。アップデートのダウンロードサイズも小さくなり、Windows の安定版アップデートはコンパクトな差分適用が可能になりました。(#4542, #4518, #4586, #4510)
- **組み込みの Agent がすべての場所でデフォルトに。** 新規のプロジェクトとセッションは組み込みの Open-Science Agent で開始されます。クリーンな CLI や SDK のインストールでも、外部のエージェント SDK が存在しない場合に起動に失敗しなくなりました。外部ランタイムのインストールは、必要な場合にのみ行う明示的な選択のままです。(#4531)
- **より軽量なアプリ。** macOS と Windows でインストール済みのデスクトップが小さくなり、バンドルされるオフライン npm ランタイムは 1,000 を超える個別のパッケージファイルを同梱する代わりに Node 22 向けにコンパイルされるようになりました。(#4555, #4572, #4563, #4592, #4587)
- **画像編集が統一。** 編集の指示は会話のコンポーザーに置かれ、ホバーやキーボード操作でどのプレビューからでも編集に入れ、バージョンのナビゲーションと比較は常に利用可能です。(#4481)
- **失敗は説明されるようになりました。** アプリ全体で、内容の見えなかったエラーが実際に何が起きたかを示すようになりました。リクエストの失敗、ファイルやソースの読み込みの問題、Notebook の実行エラー、ユーザーが停止した作業と応答がなかった作業の区別が含まれます。(#4565, #4571, #4548, #4549, #4545, #4540, #4583, #4593)

## ⚠️ 適用範囲と安全性

- **自動アップデートはバックグラウンドでダウンロードされます。** macOS は終了時にのみアップデートをインストールし、Windows と Linux はデスクトップがバックグラウンドでアイドル状態の場合のみアップデートを準備します。いずれも、制限のなく従量制でないネットワークと、Linux では書き込み可能なアップデートキャッシュを含む十分なローカルストレージがあることの確かな証拠を必要とします。従量制や制限のある接続では、完全に手動の方法が維持されます。(#4542, #4518, #4586)
- **外部エージェントランタイムのインストールは npm レジストリからダウンロードします。** 外部フレームワークを選択すると、アプリの管理インストーラーが npm レジストリ、または文書化されたミラーのフォールバックからランタイムをダウンロードし、使用前にダウンロードを検証します。管理されたランタイムの中には最新の公開バージョンを解決するものもありますが、固定バージョンやリポジトリに登録されたロックファイルを同梱し、アプリのリリース時にのみ更新されるものもあります。組み込みの Agent にはこのようなダウンロードは必要ありません。[データの受領者](https://github.com/aipoch/open-science/blob/v1.3.3/docs/security.md#data-recipients)を参照してください。(#4531)

## 🚀 New Features

- 公式にパッケージされた macOS の安定版ビルドでは、条件を満たすアップデートがアプリ終了時に自動でインストールできます。読み取り専用ボリューム、App Translocation、書き込み不能なインストール環境では手動の方法が維持されます。(#4542)
- パッケージされた Windows の安定版インストールでは、既定で有効な設定により、ワークスペースの準備が完了し、デスクトップがバックグラウンドにあり、接続が制限なく、ストレージに空きがある場合に、起動時に次回起動向けのアップデートを準備します。手動でのダウンロードも引き続き利用可能です。(#4518)
- パッケージされた Linux のインストールでは、既定で有効な設定により、デスクトップがバックグラウンドでアイドル状態の間に、接続の制限とアップデートキャッシュの空きを条件に、次回起動向けの AppImage アップデートを準備します。AppImage のパスはアップデートをまたいで維持され、手動でのダウンロードも引き続き利用可能です。(#4586)
- Bailian プロバイダーのカタログに qwen4 モデルファミリーが追加され、プランは qwen4 プレビューを既定とします。(#4594)
- 設定に Skills、Specialists、Connectors のショートカットが復元され、それぞれインストール済みのカテゴリーを開き、設定画面の元の位置に戻ります。(#4538)
- Windows の安定版アップデートは、コンパクトで独立して再現可能なインストーラーの差分として適用できるようになり、本番デスクトップのソースマップは元のソーステキストを埋め込まなくなりました。(#4510)

## 🔧 Improvements

- インストール済みのデスクトップアプリが小さくなりました。macOS と Windows で監査済みの Electron 側の依存関係コピーが除去され、サードパーティのバックエンド依存関係が削減され、内部のバックエンドパッケージモジュールがバンドルされ、オフライン npm ランタイムは Node 22 向けの単一のバンドルにコンパイルされ、フィルムコンパイラーや Web アセットも圧縮されました。(#4555, #4572, #4563, #4554, #4592, #4587)
- 新規のプロジェクトとセッションは組み込みの Open-Science Agent が既定になり、外部エージェントランタイムは管理された検証済みのインストーラーによって必要に応じてインストールされます。(#4531)
- コンポーザーは内容の見えないリクエストの失敗を詳細ビューに表示し、キューに入ったメッセージの配信失敗を説明し、プレビューはファイルやソースの読み込み失敗を説明し、会話履歴の読み込み失敗も説明されるようになり、添付ファイルのステージングとクリーンアップの失敗では何が問題だったかが示されます。(#4565, #4583, #4571, #4548, #4539)
- Notebook 環境はマニフェストをサイドカーファイルに保持し、シェルのデッドラインは停止の原因を保持したまま延長され、履歴の読み込みや長い出力のレイアウトのコストが削減され、コネクターのエラーがホストのツール一覧に表示されるようになりました。(#4547, #4544, #4533, #4551)
- ストリーミングの応答は、テキスト分割処理に上限を設けることで長い会話でも応答性が維持され、画像エディターは編集の入力中に会話メッセージを固定したままにします。(#4520, #4559)
- アプリは変更されていないバンドル済みスキルドキュメントの再読み込みをスキップし、空のネットワーク承認に対するブランチの走査もスキップします。(#4534, #4535)

## 🐛 Bug Fixes

- プロバイダーのエラー詳細は分類済みの失敗コードとリクエスト ID を保持するため、モデルの失敗は再起動をまたいで対処可能なままです。(#4590)
- Windows では、Notebook のメモリしきい値がインストール済みの物理メモリに上限が設けられ、ブロックされた実行はメモリの読み取り値を保持し、macOS のメモリプレッシャーと Linux の cgroup 制限が表示されます。(#4593)
- Windows では、以前のセッションが残した古いファイルブロッカーが再起動時に再確認され期限切れとなるため、準備済みのアップデートの適用を完了できます。(#4591)
- トレイのセッション項目は、永続化された投影が追いつくまでの間、回復されたサマリーでナビゲートします。(#4582)
- PDF 翻訳の修復: カラムの区切り、キャプション、インライン数式で文を分割していたネイティブな抽出結果が、フォント、グリフ、ジオメトリの証拠を用いて再接続され、翻訳後のテキストがネイティブな表記、フォームのラベル、隣接する図をずらさなくなりました。(#4560)
- 停止した作業が正しく表示されます。ユーザーが停止したプロンプトはクリーンアップの後で確定し、停止した実行は応答のない継続と区別され、古い診断がキャンセルメッセージを置き換えることはなくなり、アイドル状態のセッションは切り離された実行マーカーを回復します。(#4552, #4545, #4537)
- モデルの失敗が正確に分類されます。アップストリームの失敗が不正な形式の応答やクライアント側のスタック枯渇と区別され、安全な診断が保持され、Responses のストリームライフサイクルが早期に完了を報告しなくなりました。(#4540, #4511)
- Windows では、Notebook カーネルが再起動後にランタイムの状態を回復し、プロファイルキーがキャッシュ済みアップデートの確認より前に初期化されます。(#4529, #4569)
- 返信のファイル名は保存されたアーティファクトに解決され、メモリーカテゴリの削除は確認済みのノートに紐付けられ、セッションパッケージはエクスポート失敗の説明の前に Notebook の読み込みが確定するのを待ちます。(#4562, #4512, #4564)
- 画像編集のプレビューが安定し、画像の詳細に編集を行った Notebook カーネルが表示され、コンピューティングデバイスの準備が完了している場合はアップデートアクションが非表示になります。(#4553, #4557, #4558)
- プロジェクトファイルの読み込みは失敗を説明し不確実な修復を確認し、GitHub スキルのインポートは接続の失敗を説明し、スケジュールされたセッションと認証の回帰が修復されました。(#4541, #4532, #4530)
