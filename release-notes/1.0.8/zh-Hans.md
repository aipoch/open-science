## ✨ 亮点

- **设置被重新组织为专注的标签页。** 通用偏好设置拆分为多个专属标签页：外观与通知移入系统设置，而“通用”现在直接展示应用信息、诊断、命令行工具和帮助资源——包括手动安装与更新指南的直达链接——无需层层翻找。(#4022)
- **从 DOI、arXiv 或 PubMed 批量导入参考文献。** “从 DOI 或链接添加”现在每次导入最多接受 100 个混合标识符——DOI、arXiv ID、PMID、PMCID 或官方文章链接——并在常规的预览与事务化保存之前对其进行规范化和去重。(#4039)
- **文献的 AI 研究快照。** 文献详情视图新增 AI 快照卡片，可将一篇论文总结为五个结构化部分——研究问题、研究人群、方法、主要发现和局限性——由你所配置的主模型基于全文或摘要生成，并标注实际使用了哪一种。(#4037)
- **已结束的会话释放其智能体进程。** 全部五个智能体框架中已完成的会话不再让服务商和工具进程在内存中累积：共享的审查运行时、被取代的交接租约以及失败的清理尝试都会被释放或重试直至确认，因此长时间、多会话的工作日也能保持响应。(#4046, #4054, #4061)

## 🚀 新功能

- Tencent TokenHub 新增 Hy4 推理模型和当前带 1,000,000 token 上下文窗口的 DeepSeek V4.1 Flash 路由，并为 GLM-5.3-Flash、Kimi K3 和 MiniMax M3 提供图像输入。(#4060)

## 🔧 改进

- 上游 REST API 停用后，eQTL Catalogue 查询改用索引文件重新恢复，并会校验坐标使用 GRCh38 基因组组装，而不是静默返回误导性的匹配结果。(#4036)
- PDF 的阅读顺序与提取更加可靠：自动排序使用带位置信息的文本证据来区分正文栏与表格行；裁剪边界会与原生来源核对；存在歧义的表格单元格会保留原始文本并给出可靠性警告；Windows PDF 工作进程在拆卸时不再崩溃。(#3994, #4056)
- 更新对话框现在会指出阻塞进程，而不是打印完整的系统路径；桌面恢复失败会在诊断包和日志中保留真实的错误证据，而不是只报告笼统的失败。(#4047, #4045)
- R 分析的复现覆盖更加诚实：可以强制参数或派发方法的科学调用现在会使过期的文件证据失效，下游验证不再夸大结果实际依赖哪些文件。(#4052)

## 🐛 问题修复

- macOS 更新不再被 StoreKit 代理等普通的只读文件占用者阻塞，Windows 在更新准备时也不再把应用自身的后端进程误判为外来进程。(#4028)
- 当系统工具缺失于 PATH 或扫描耗时过长时，Windows 更新检查不再报告未知的占用情况；进程 ID 被复用后，过期的 Notebook 回执也不再阻塞恢复。(#4042)
- 当目标目录本身不可读时，已完成的下载不再以权限错误告终；文件保持完整。(#4053)
- 当 PATH 中的 Node 版本过旧、无法使用所配置的代理时，沙箱化的 Notebook 命令行工具会回退到应用自带的 Node 运行时，从而修复沙箱内的网络访问。(#4058)
- Windows 保护检查不再在探测之间关闭健康的共享网关，也不再误报运行时失败。(#4029)
- 重新搜索一篇论文时，一旦新搜索成功，会清除之前的“PDF 无法添加”提示。(#4041)
- Pi 现在在打包后的桌面应用中可正确安装，而不再在定位其引导文件时失败。(#4027)
- 输入区不再在模型选择器状态旁显示重复的不可用模型提示。(#4051)
- 产物下载在完成之后、释放其能力时失败的情况，不再逃逸为可导致后端终止的未处理错误。(#4055)
- Markdown 产物在打开时会修复旧版本遗留的过期溯源头部，溯源面板也会明确解释不完整的执行证据。(#4021)
