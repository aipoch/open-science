## ✨ 亮點

- **設定重新整理為專屬分頁。** 一般偏好設定拆分為專用分頁：外觀與通知移至系統設定，而「一般」現在直接顯示應用程式資訊、診斷、命令列工具與說明資源——包括手動安裝與更新指南的直接連結——無需層層翻找。(#4022)
- **從 DOI、arXiv 或 PubMed 識別碼批次匯入參考文獻。** 「從 DOI 或連結新增」現在每次匯入最多接受 100 個混合識別碼——DOI、arXiv ID、PMID、PMCID 或官方文章連結——在慣用的檢視與交易式儲存之前先正規化並去除重複。(#4039)
- **文獻資料庫的 AI 研究快照。** 文獻資料庫詳細檢視新增 AI 快照卡片，將論文摘要整理為五個結構化區段——研究問題、研究對象、方法、主要發現與侷限——由你設定的主模型從全文或摘要產生，並標示使用了哪一種來源。(#4037)
- **已結束的工作階段會釋放智慧代理行程。** 五個智慧代理框架中已完成的工作階段不再讓提供者與工具行程累積在記憶體中：共用的檢閱執行階段、被取代的交接租約，以及失敗的清理嘗試都會被釋放或重試直到確認完成，讓歷經許多工作階段的漫長工作日依然保持回應。(#4046, #4054, #4061)

## 🚀 新功能

- Tencent TokenHub 新增 Hy4 推理模型與現行的 DeepSeek V4.1 Flash 路由（具 1,000,000-token 上下文視窗），並為 GLM-5.3-Flash、Kimi K3 與 MiniMax M3 提供圖片輸入。(#4060)

## 🔧 改進

- eQTL Catalogue 查詢在上游 REST API 停用後改用索引檔案恢復運作，並會驗證座標使用 GRCh38 組裝版本，而非靜默回傳具誤導性的比對結果。(#4036)
- PDF 閱讀順序與擷取更可靠：自動排序使用定位文字證據區分散文欄位與表格列，裁剪邊界會對照原始來源驗證，語意不明的表格儲存格保留原文並附上可靠性警告，Windows PDF 工作者在拆除階段不再當機。(#3994, #4056)
- 更新對話方塊現在會指出阻擋的行程名稱，而非印出完整系統路徑；桌面復原失敗會在診斷套件與記錄中保留實際錯誤證據，而非僅回報一般性失敗。(#4047, #4045)
- R 分析的再現涵蓋範圍更誠實：可強制引數或分派方法的科學呼叫現在會撤銷過期的檔案證明，因此下游驗證不再誇大結果實際依賴哪些檔案。(#4052)

## 🐛 錯誤修正

- macOS 更新不再被一般的唯讀檔案持有者（如 StoreKit 代理行程）阻擋，Windows 在更新準備期間也不再將應用程式自身的後端行程誤判為外部行程。(#4028)
- Windows 更新檢查在系統工具不在 PATH 或掃描時間過長時不再回報未知的佔用狀態，陳舊的 Notebook 收據也不再因行程 ID 重用而阻擋復原。(#4042)
- 當目的目錄本身不可讀時，已儲存的下載不再以權限錯誤收尾；已完成的檔案會保留下來。(#4053)
- 沙箱化 Notebook 命令列工具在 PATH 版本過舊而無法使用設定的代理時，會改以應用程式自身的 Node 執行階段執行，修復沙箱內的網路存取。(#4058)
- Windows 防護檢查不再在探測之間關閉運作正常的共用閘道並誤報執行階段失敗。(#4029)
- 新搜尋成功後，再次搜尋論文會清除先前的「無法加入 PDF」通知。(#4041)
- Pi 現在在封裝的桌面應用程式中正確安裝，不再因找不到其啟動檔案而失敗。(#4027)
- 撰寫器不再在模型選擇器狀態旁顯示重複的模型不可用通知。(#4051)
- 產物下載在完成後若於釋放其能力時失敗，不再逸出為可導致後端終止的未處理錯誤。(#4055)
- Markdown 產物開啟時會修復舊版遺留的過期來源鏈頭部，來源面板現在也會明確說明不完整的執行證據。(#4021)
