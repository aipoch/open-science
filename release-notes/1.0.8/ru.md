## ✨ Основные изменения

- **Настройки перестроены по тематическим вкладкам.** Общие параметры разделены на отдельные вкладки: оформление и уведомления переходят в настройки системы, а раздел «Общие» теперь показывает сведения о приложении, диагностику, инструменты командной строки и справочные материалы — включая прямую ссылку на руководство по установке и обновлению вручную — без рытья в меню. (#4022)
- **Импортируйте записи пакетно по DOI, arXiv или PubMed.** Пункт «Добавить по DOI или ссылке» теперь принимает до 100 смешанных идентификаторов за один импорт — DOI, ID arXiv, PMID, PMCID или официальные ссылки на статьи — нормализуя и удаляя дубликаты перед обычным просмотром и транзакционным сохранением. (#4039)
- **ИИ-снимки исследований для Literature.** Детальный просмотр Literature получил карточку ИИ-снимка, которая резюмирует статью в пять структурированных разделов — исследовательский вопрос, популяция исследования, методы, основные результаты и ограничения — генерируясь настроенной основной моделью по полному тексту или аннотации с пометкой, какой из них был использован. (#4037)
- **Завершённые сеансы освобождают процессы агентов.** Завершённые сеансы во всех пяти фреймворках агентов больше не накапливают процессы провайдера и инструментов в памяти: общие среды выполнения проверяющих, заменённые аренды передачи и неудачные попытки очистки освобождаются или повторяются до подтверждения, поэтому длинные рабочие дни с множеством сеансов остаются отзывчивыми. (#4046, #4054, #4061)

## 🚀 Новые возможности

- Tencent TokenHub получает модель рассуждений Hy4 и актуальные маршруты DeepSeek V4.1 Flash с контекстными окнами в 1 000 000 токенов, а также ввод изображений для GLM-5.3-Flash, Kimi K3 и MiniMax M3. (#4060)

## 🔧 Улучшения

- Запросы eQTL Catalogue снова работают после вывода из эксплуатации исходного REST API, используя индексированные файлы, и теперь проверяют, что координаты используют сборку GRCh38, вместо того чтобы молча возвращать вводящие в заблуждение совпадения. (#4036)
- Порядок чтения и извлечение данных из PDF стали надёжнее: автоматическое упорядочивание использует позиционные текстовые признаки, чтобы отличать прозаические колонки от строк таблиц, границы обрезки проверяются по исходному нативному представлению, неоднозначные ячейки таблиц сохраняют исходный текст с предупреждением о надёжности, а рабочий процесс PDF в Windows больше не падает при завершении. (#3994, #4056)
- Диалоги обновления теперь называют блокирующий процесс вместо вывода полных системных путей, а ошибки восстановления рабочего стола сохраняют реальные свидетельства в диагностических пакетах и журналах вместо сообщения только об общем сбое. (#4047, #4045)
- Охват воспроизведения для R-анализов стал честнее: научные вызовы, которые могут принудительно задать аргументы или выполнить диспетчеризацию методов, теперь отзывают устаревшие доказательства файлов, поэтому последующая верификация больше не завышает, от каких файлов зависел результат. (#4052)

## 🐛 Исправления ошибок

- Обновления в macOS больше не блокируются обычными держателями файлов с правом только на чтение, такими как агент StoreKit, а в Windows собственные процессы бэкенда приложения больше не ошибочно классифицируются как чужие при подготовке обновления. (#4028)
- Проверка занятости при обновлении в Windows больше не сообщает о неизвестной занятости, когда системные инструменты отсутствуют в PATH или проверки выполняются долго, а устаревшие квитанции Notebook больше не блокируют восстановление после повторного использования идентификатора процесса. (#4042)
- Сохранённая загрузка больше не заканчивается ошибкой разрешений, когда сам каталог назначения не читаем; завершённый файл остаётся на месте. (#4053)
- Изолированные инструменты командной строки Notebook переходят на собственную среду выполнения Node приложения, когда версия из PATH слишком старая для использования настроенного прокси, восстанавливая сетевой доступ внутри изолированной среды. (#4058)
- Проверки защиты в Windows больше не закрывают работающий общий шлюз между зондами и не сообщают о ложном сбое среды выполнения. (#4029)
- Повторный поиск статьи очищает прежнее уведомление «PDF не удалось добавить», когда новый поиск завершается успешно. (#4041)
- Pi теперь корректно устанавливается в упакованном десктопном приложении вместо сбоя при поиске своих загрузочных файлов. (#4027)
- Композитор больше не показывает дублирующее уведомление о недоступной модели рядом со статусом выбора модели. (#4051)
- Загрузка артефакта, которая завершилась и затем завершилась с ошибкой при освобождении своей возможности, больше не ускользает как необработанная ошибка, которая может завершить работу бэкенда. (#4055)
- Артефакты Markdown восстанавливают устаревшую голову происхождения, оставленную старыми версиями, при открытии, а панель происхождения теперь явно объясняет неполные свидетельства выполнения. (#4021)
