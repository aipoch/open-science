## ✨ 亮點

- **Windows 上的 R 再次可靠。**由 conda 管理的 R 在 Windows 上能可靠啟動，直譯器在環境實體化後再次可解析，已驗證的核心恢復會保留執行狀態，密封配方檢查也能復原已驗證的 Windows pip 進入點。(#2630, #2645, #2653, #2679)
- **Notebook 輪次可正確重播。**重播時會還原同一輪次的輸入與標準函式庫匯入，因此重新執行所看到的輸入與原始執行完全一致。(#2706)
- **審閱者修正保留其上下文。**關聯的回饋討論串不再於各輪之間丟失修正上下文，自動審查在開始新對話後也依然延續。(#2682, #2625)
- **更乾淨的文獻與連接器證據。**PubMed 匯入會區分作者姓氏與名字縮寫（也不再將「Jr.」這類後綴當成縮寫），透過 Crossref 更新浮現的撤稿鏈會受到檢查，Ensembl、VEP、Reactome、OLS、CellGuide、UCSC 與 gnomAD 的行為也更精確。(#2675, #2677, #2693, #2703, #2696, #2687, #2664, #2663, #2634)

## 🔧 改進

- DeepSeek V4.1 Flash 加入模型目錄，更新後舊有會話的模型仍會保留（#2660），Volcengine Ark 的模型陣容也已翻新（#2673）。
- 分頁選取指示器以平滑的動畫呈現。(#2638)
- 文獻工具卡統一，文獻詳細資訊也獲得擴充。(#2670)

## 🐛 問題修復

- **Notebook 與運算**——Windows 上的 conda R 在沙箱失敗可追蹤的情況下再次啟動（#2630）；R 可執行檔在環境實體化後能解析（#2645）；執行與已驗證的核心恢復均獲保留（#2653）；同一輪次的輸入與標準函式庫匯入可重播（#2706）；已驗證的 Windows pip 進入點可在可重現性檢查中復原（#2679）；排隊的 CLI 對話快照會正確核對（#2676）；被動載入對話時不再發生寫入（#2640）。
- **文獻**——PubMed 的作者姓氏與名字縮寫已分開（#2675），作者後綴也不再被視為縮寫（#2677）；Crossref 的 updated-by 撤稿關係會受到檢查（#2693）。
- **連接器**——Ensembl 查詢會回報解析出的物種（#2703）；VEP 區域查詢會標準化至正向股（#2696）；所要求的 Reactome 物種會被採用並驗證（#2687）；OLS 失敗會被保留、關係分頁也經驗證（#2664）；CellGuide 資料擷取失敗會正確浮現（#2663）；UCSC 邊界會經驗證、gnomAD 限制也更嚴格（#2634）。
- **會話與側聊**——側聊保有自身的應用程式掛載點（#2680），也不再為了准入而等待主輪次就緒（#2668）；受委派的 OpenCode 子智能體會在隔離的執行環境中執行（#2652）。
- **技能與市集**——綁定至專家的執行環境技能能正確準備（#2698）；缺少作者時市集會顯示其來源（#2672）；已配置的 OpenCode 技能參照可正常讀取（#2651）。
- **權限與設定**——原生網頁搜尋的核准會在對話其餘部分被記住（#2646）；關閉行動版導覽時設定保持開啟（#2658）；Go 會話身分已納入服務商探測（#2662）；Responses 橋接器中的原始圖片細節會被標準化（#2650）；復原保持在設定面板之上（#2641）；情境式行內訊息版面已還原（#2674）。
