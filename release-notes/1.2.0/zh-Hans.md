## ✨ 亮点

- **在云端后端运行任务。** Kubernetes、Hugging Face Jobs、Modal 和 Ray 与 SSH、Slurm 并肩加入：提交前可审批目标、命令、资源和输出，重启后可恢复任务，并可在 Compute Preview 中打开已发布的结果。(#4191)
- **内置 Open-Science 智能体。** 独立的内置智能体运行时，提供与服务商无关的轮次执行和经过验证的工具处理，现已成为新安装的默认选项（此前为 Claude）；Claude Code、OpenCode、Codex、CodeBuddy 和 Pi 仍然可用。(#4147, #4159)
- **更快的 macOS 更新。** 更新只下载应用镜像中发生变化的块，必要时回退为完整下载。(#4177)
- **在步骤处讨论导入的研究。** 从导入的 `.science` 包或回放步骤发起提问，会打开与该步骤关联的子会话；父会话保持原有身份，讨论在归档后仍可保留。(#4178)
- **更从容的工作区。** 侧边栏以置顶和导入的研究开头，并将较早的会话折叠进一个最近列表；导入的历史让“分叉以继续”成为明确的下一步；从较早轮次发送不再跳动阅读位置。(#4180, #4183, #4188)
- **更可靠的更新和文档。** macOS 在阻止安装前会验证正在运行的应用，Windows 更新会指出占用应用的文件，固定版式 PDF 翻译在某一页失败时保留完好的页面。(#4161, #4158, #4186)

## 🚀 新功能

- 可将已审批的任务提交到 Kubernetes、Hugging Face Jobs、Modal 或 Ray，逐任务审批目标、命令、资源和输出，并通过恢复记录在重启后继续收集。远程任务以你自己连接的账户权限运行：每个后端都需要各自的凭据，已审批的输入、命令和输出会离开本机前往所选服务商。(#4191)
- 可使用内置 Open-Science 智能体运行时，它为主流 API 协议提供流式适配器并配有持久化存储；它已成为新安装的默认智能体。(#4147, #4159)
- 可通过 blockmap 对 macOS 更新执行差量下载，并在需要时自动回退为完整下载。(#4177)
- 可从导入的研究或回放发起与步骤关联的子讨论；删除父会话后，讨论会转化为普通会话。(#4178)
- 可在悬停卡片中预览来源链接，显示目标域名；对于已审批的 HTTPS 来源，还会显示标题和描述元数据。(#4194)

## 🔧 改进

- 工作区侧边栏按置顶、导入的研究、活跃、最近分组排序，子会话能清晰地显示为父会话的分支。(#4180)
- 导入的研究历史保留全部四项操作，但将“分叉以继续”提升为唯一的主要操作。(#4183)
- 在阅读较早轮次时发送提示词，转录会保持当前锚定位置，不再跳转到末尾。(#4188)
- “模型”设置页签更名为“本地能力”，以一致的卡片形式涵盖 PDF 提取、OCR 语言包和研究讲解。(#4175)
- 回放中的提问会附着到所选步骤或 Notebook 运行，包括当前页面之外的单元格。(#4187, #4185)
- 工具错误消息现在会说明失败的调用和明确的下一步，不再读起来像是工具不可用。(#4184)
- Notebook 的大型源码分析在主线程之外运行，文件证据复用常驻 worker，自有进程退出以原生方式等待，使运行和关闭都保持响应。(#4166, #4174, #4169)
- 外部文献 PDF 提取只恢复经验证的原生正文、数学和表格片段，并拒绝外观相似的题注和引用尾部。(#4156, #4176)
- 手动“添加参考文献”表单接受仅含标识符的条目（如 PMID），并从第一个标识符生成标题。(#4150)
- 研究影片导出控件在进度运行期间保持紧凑，影片按钮在状态加载时不再闪烁错误的操作。(#4182, #4179)

## 🐛 问题修复

- DeepSeek 模型别名改经 chat completions 路由，修复了 Responses 路径上的验证和运行时失败。(#4192)
- Windows 托管 R 环境在启动 Rscript 时带上已激活的 Conda DLL 目录，修复了 STATUS_DLL_NOT_FOUND 退出。(#4195)
- 在 Windows 显示缩放下，主窗口会钳制到显示器工作区内，任务栏不再遮挡输入区域。(#4200)
- 固定版式 PDF 翻译在某一页版式不受支持时保留已独立翻译的页面，不再丢弃整个预览。(#4186)
- 更新安装检查会先验证正在运行的 macOS 捆绑包再报告“安装被占用”，会指出占用应用文件的 Windows 进程，并能解除阻塞而不卡住应用。(#4161, #4158, #4153)
- 共享的 macOS 后台服务脱离了桌面的崩溃处理程序，过期的处理程序不再占用文件或阻塞更新。(#4165)
- 启动诊断在后端退出后的自动重启中得以保留。(#4144)
- Windows Notebook 运行时恢复会先验证内核进程树已退出再清除启动栅栏，shell 任务优先使用应用托管的 Node 而非宿主 shim。(#4140, #4142, #4143)
- Codex 运行时清理在受限的 Windows 环境中可可靠地解析 taskkill。(#4199)
