## ✨ 亮點

- **在雲端後端執行任務。** Kubernetes、Hugging Face Jobs、Modal 與 Ray 加入 SSH 與 Slurm：送出前可核准目標、指令、資源與輸出，重新啟動後可復原任務，並可從 Compute Preview 開啟已發布的結果。(#4191)
- **內建 Open-Science 智慧代理。** 具備供應商中立回合執行與受驗證工具處理的獨立內建智慧代理執行階段，現在是新安裝的預設選項（原為 Claude）；Claude Code、OpenCode、Codex、CodeBuddy 與 Pi 仍可使用。(#4147, #4159)
- **更快的 macOS 更新。** 更新只下載應用程式映像中變更的區塊，必要時會退回完整下載。(#4177)
- **在特定步驟討論匯入的研究。** 從匯入的 `.science` 套件或重播步驟提問，會開啟連結到該步驟的子對話；父對話保持原有身分，討論在封存後仍然保留。(#4178)
- **更簡潔的工作區。** 側邊欄以釘選與匯入的研究開頭，並將較舊的工作階段收合為單一最近項目清單；匯入歷史將「分叉以繼續」明確標示為下一步；從較早回合送出訊息不再跳動閱讀位置。(#4180, #4183, #4188)
- **更可靠的更新與文件。** macOS 會在阻擋安裝前先驗證執行中的應用程式；Windows 更新會指出佔用應用程式檔案的程式；固定版式 PDF 翻譯在單頁失敗時保留正常的頁面。(#4161, #4158, #4186)

## 🚀 新功能

- 將已核准的任務送出至 Kubernetes、Hugging Face Jobs、Modal 或 Ray，逐項任務核准目標、指令、資源與輸出，並附復原記錄，在重新啟動後繼續收集。遠端任務會以你自己所連結帳戶的權限執行：每個後端都需要各自的憑證，而核准的輸入、指令與輸出會從本機傳送到所選的供應商。(#4191)
- 使用內建 Open-Science 智慧代理執行階段，具備主流 API 通訊協定的串流配接器與持久化儲存；它是新安裝的預設智慧代理。(#4147, #4159)
- 透過 blockmap 進行 macOS 更新的差異下載，並自動退回完整下載。(#4177)
- 從匯入的研究或重播開始連結到步驟的子討論；刪除父對話會將討論轉換為一般對話。(#4178)
- 在懸浮卡片中預覽來源連結，顯示目標網域，並為已核准的 HTTPS 來源顯示標題與描述詮釋資料。(#4194)

## 🔧 改進

- 工作區側邊欄將群組排序為釘選、匯入的研究、進行中與最近項目，子工作階段可清楚讀取為其父對話的分支。(#4180)
- 匯入研究歷史保留全部四個動作，但將「分叉以繼續」提升為單一主要動作。(#4183)
- 在閱讀較早回合時送出提示，會讓記錄保持原位，不再跳到結尾。(#4188)
- 「模型」設定分頁更名為「本機功能」，涵蓋 PDF 擷取、OCR 語言套件與研究旁白，並以一致的卡片呈現。(#4175)
- 重播中的提問會連結到選取的步驟或 Notebook 執行，包括目前頁面之外的儲存格。(#4187, #4185)
- 工具錯誤訊息現在會指出失敗的呼叫與明確的下一步，不再讀起來像工具無法使用。(#4184)
- Notebook 的大型來源分析移出主執行緒執行，檔案證據重用常駐的工作行程，自有行程的結束以原生方式等待，讓執行與關閉保持靈敏。(#4166, #4174, #4169)
- 外部文獻 PDF 擷取只復原可證實的原生散文、數學式與表格片段，並拒絕看起來相似的圖說與引用結尾。(#4156, #4176)
- 手動「新增參考文獻」表單接受僅含識別碼的項目（例如 PMID），並從第一個識別碼產生標題。(#4150)
- 研究影片匯出控制在進行期間保持精簡，影片按鈕在狀態載入時不再閃示錯誤的動作。(#4182, #4179)

## 🐛 錯誤修正

- DeepSeek 模型別名改走 chat completions 路由，修復 Responses 路徑上的驗證與執行階段失敗。(#4192)
- Windows 受管理的 R 環境會以已啟用的 Conda DLL 目錄啟動 Rscript，修復 STATUS_DLL_NOT_FOUND 結束。(#4195)
- 在 Windows 顯示縮放環境下，主視窗會被限制在顯示工作區內，工作列不再遮蓋輸入區域。(#4200)
- 固定版式 PDF 翻譯在單頁遇到不支援的版式時，保留各自翻譯過的頁面，不再捨棄整個預覽。(#4186)
- 更新安裝檢查在回報「安裝中」前先驗證執行中的 macOS 套件、指出佔用應用程式檔案的 Windows 行程，並在不阻擋應用程式的情況下排除阻礙。(#4161, #4158, #4153)
- 共用的 macOS 背景服務會與桌面的當機處理常式分離，過期的處理常式不再佔用檔案或阻擋更新。(#4165)
- 啟動診斷在後端結束後自動重新啟動的情況下仍然保留。(#4144)
- Windows Notebook 執行階段復原會先證明核心行程樹已結束，再清除啟動屏障；shell 任務優先使用應用程式管理的 Node，而非主機上的替代程式。(#4140, #4142, #4143)
- Codex 執行階段清理能在受限制的 Windows 環境中可靠地完成 taskkill。(#4199)
