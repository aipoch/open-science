## ✨ Основные изменения

- **Запуск заданий в облачных бэкендах.** Kubernetes, Hugging Face Jobs, Modal и Ray дополняют SSH и Slurm: перед отправкой подтвердите цель, команду, ресурсы и выходные данные, после перезапуска восстановите задание и откройте опубликованные результаты в Compute Preview. (#4191)
- **Встроенный агент Open-Science.** Автономная встроенная среда выполнения агента с провайдер-нейтральным выполнением ходов и проверенной обработкой инструментов стала используемой по умолчанию для новых установок (ранее — Claude); Claude Code, OpenCode, Codex, CodeBuddy и Pi остаются доступными. (#4147, #4159)
- **Более быстрые обновления macOS.** Обновления загружают только изменённые блоки образа приложения, при необходимости выполняя полную загрузку. (#4177)
- **Обсуждение импортированных исследований на шаге.** Вопрос из импортированного пакета `.science` или из шага воспроизведения открывает дочерний диалог, связанный с этим шагом; родительский диалог сохраняет свою идентичность, а обсуждения переживают архивацию. (#4178)
- **Более спокойная рабочая область.** Боковая панель начинается с закреплённых и импортированных исследований и сворачивает старые сеансы в один список недавних, импортированная история делает «отделить ветку для продолжения» очевидным следующим шагом, а отправка сообщения из более раннего хода больше не сдвигает позицию чтения. (#4180, #4183, #4188)
- **Более надёжные обновления и документы.** macOS проверяет запущенное приложение перед блокировкой установки, обновления Windows называют файлы, удерживающие приложение открытым, а перевод PDF с фиксированной вёрсткой сохраняет исправные страницы, когда одна страница не удалась. (#4161, #4158, #4186)

## 🚀 Новые возможности

- Отправляйте утверждённые задания в Kubernetes, Hugging Face Jobs, Modal или Ray с подтверждением для каждого задания цели, команды, ресурсов и выходных данных, а также с записями восстановления, которые возобновляют сбор после перезапуска. Удалённые задания выполняются с полномочиями подключённой учётной записи: каждому бэкенду нужны собственные учётные данные, а утверждённые входные данные, команда и результаты покидают эту машину для выбранного провайдера. (#4191)
- Используйте встроенную среду выполнения агента Open-Science со стриминговыми адаптерами для основных протоколов API и долговечными хранилищами; она является агентом по умолчанию для новых установок. (#4147, #4159)
- Загружайте обновления macOS дифференциально через blockmaps с автоматическим запасным вариантом полной загрузки. (#4177)
- Начинайте дочернее обсуждение, связанное с шагом, из импортированного исследования или воспроизведения; удаление родительского диалога преобразует обсуждения в обычные разговоры. (#4178)
- Просматривайте ссылки на источники в карточке при наведении, показывающей домен назначения, а для утверждённых HTTPS-источников — метаданные заголовка и описания. (#4194)

## 🔧 Улучшения

- Боковая панель рабочей области упорядочивает группы как «Закреплённые», «Импортированные исследования», «Активные» и «Недавние», а дочерние сеансы чётко читаются как ветви родительского. (#4180)
- История импортированных исследований сохраняет все четыре действия, но выделяет «Отделить для продолжения» как единственное основное действие. (#4183)
- Отправка запроса во время чтения более раннего хода сохраняет положение транскрипта вместо прыжка к концу. (#4188)
- Вкладка настроек «Модель» становится «Локальные возможности», охватывая извлечение PDF, языковые пакеты OCR и озвучку исследований с выровненными карточками. (#4175)
- Вопрос в воспроизведении привязывается к выбранному шагу или запуску Notebook, включая ячейки за пределами текущей страницы. (#4187, #4185)
- Сообщения об ошибках инструментов теперь указывают неудавшийся вызов и явный следующий шаг вместо того, чтобы читаться так, будто инструмент недоступен. (#4184)
- Анализ больших источников в Notebook выполняется вне основного потока, свидетельства файлов переиспользуют резидентный воркер, а завершение принадлежащих процессов ожидается нативно, сохраняя отзывчивость запусков и завершений. (#4166, #4174, #4169)
- Извлечение внешних литературных PDF восстанавливает только доказанные нативные фрагменты прозы, формул и таблиц и отклоняет похожие подписи к рисункам и хвосты цитирований. (#4156, #4176)
- Ручная форма «Добавить ссылку» принимает записи только с идентификатором, например PMID, генерируя заголовок из первого идентификатора. (#4150)
- Элементы управления экспортом исследовательского видео остаются компактными во время выполнения, а кнопка фильма больше не показывает мерцание неправильного действия, пока загружается её статус. (#4182, #4179)

## 🐛 Исправления ошибок

- Псевдонимы моделей DeepSeek маршрутизируются через chat completions, устраняя ошибки валидации и выполнения на пути Responses. (#4192)
- Управляемые среды R в Windows запускают Rscript с активированными каталогами DLL Conda, устраняя выходы STATUS_DLL_NOT_FOUND. (#4195)
- В Windows при масштабировании экрана главное окно ограничивается рабочей областью дисплея, поэтому панель задач больше не может перекрывать область ввода. (#4200)
- Перевод PDF с фиксированной вёрсткой сохраняет независимо переведённые страницы, когда одна страница имеет неподдерживаемую вёрстку, вместо отбрасывания всего предпросмотра. (#4186)
- Проверки установки обновлений проверяют запущенный пакет macOS перед сообщением «установка занята», называют процессы Windows, удерживающие файлы приложения, и разрешают блокировки без остановки приложения. (#4161, #4158, #4153)
- Общая фоновая служба macOS отсоединяется от обработчика сбоев рабочего стола, поэтому устаревший обработчик больше не удерживает файлы и не блокирует обновления. (#4165)
- Диагностика запуска переживает автоматический перезапуск после выхода бэкенда. (#4144)
- Восстановление среды выполнения Notebook в Windows доказывает завершение дерева процессов ядра перед снятием барьеров запуска, а задачи оболочки предпочитают управляемый приложением Node вместо системных обходных ссылок. (#4140, #4142, #4143)
- Очистка среды выполнения Codex надёжно разрешает taskkill в ограниченных средах Windows. (#4199)
