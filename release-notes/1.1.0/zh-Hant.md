## ✨ 亮點

- **可攜式研究影片。** 將工作階段匯出為可分享、附旁白的可攜式研究影片：旁白資產優先從應用程式內建 CDN 下載，並有固定的上游後備，產生前會執行預檢並從失敗中復原，終端機時序已凍結以確保輸出穩定，而可用模型不再需要事先通過通訊協定驗證。(#4077, #4102, #4104, #4106, #4114)
- **CLI 與 MCP 的文獻工具。** 從命令列與 MCP 用戶端搜尋並管理文獻資料庫，除了唯讀瀏覽外，還提供寫入工具讓參考文獻保持最新。(#4120, #4122)
- **可續接的批次論文概覽。** 批次概覽產生在中斷後可從上次停下的地方繼續，無需重新產生已完成的結果。(#4095；thanks [@nasus2002](https://github.com/nasus2002))
- **資源中心重新設計。** 資源中心已更名並調整案例庫版面，設定中的外部資源連結更為精簡，運算設定則移入連線群組。(#4018, #4090, #4087)
- **選擇加入的資源記錄（Windows）。** 診斷功能可在工作時記錄資源使用狀況——行程身分、工作階段活動與系統提交記憶體——並將證據納入匯出的診斷封存檔，且取樣會在電腦閒置或休眠時暫停。(#4062)
- **連接行動裝置。** 掃描 QR 圖碼配對手機或平板，即可在其上開啟目前的工作區；可透過本機 WiFi 或 Pinggy 通道（具自動重新連線與區域選擇），網際網路通道會明示流量經過 Pinggy 的伺服器。(#4129)

## 🚀 新功能

- 將任何工作階段匯出為附終端機播放與語音旁白的可攜式研究影片。(#4077)
- 從 CLI 與 MCP 使用文獻資料庫工具：唯讀搜尋與瀏覽，以及管理參考文獻的寫入工具。(#4120, #4122)
- 在 Windows 上從診斷功能記錄資源使用狀況，以診斷資源耗盡問題，提供開始與停止控制，並將證據納入匯出的封存檔。(#4062)
- 掃描 QR 圖碼配對行動裝置，並在其上開啟目前的工作區，可透過本機 WiFi 或 Pinggy 通道。(#4129)

## 🔧 改進

- 對話在中斷與儲存失敗後會復原，不再遺失當下的交流內容。(#4097)
- 診斷匯出保留 Notebook 執行證據、記錄匯出快照診斷、允許選取歷史後端記錄，並將一般的記錄篩選視為匯出成功。(#4083, #4086, #4063, #4108)
- PDF 結構擷取會從可搜尋的掃描檔中復原圖表與表格，不再直接捨棄，並保留原生裁剪邊界與文字出處。(#4078, #4132)
- 受限制的 OpenCode 推理呼叫不再強制產生摘要，且受限制推理的輸出在各智慧代理框架間保持一致。(#4119, #4115)
- 閒置 ACP 連線的重用受到限制，減少長時間工作天中的記憶體增長。(#4103)
- Windows 更新準備改以原生方式查詢行程身分與佔用狀況，不再依賴外部系統工具。(#4069)
- 啟動會在第一個用戶端逾時前等待探索完成，並在執行階段清理過程中保留失敗狀態。(#4082, #4070)
- 匯入市集預先選取目前的專案，並改用簡化的標籤。(#4109, #4105)
- 文獻功能釐清識別碼匯入標籤，並在產生失敗後保留部分的 PDF。(#4072, #4113)
- 分子匯出可在 molfile 中保留大型結構。(#4075)
- CodeBuddy 技能可為原生與 WSL 工具解析其資源。(#4076)
- 工作區面板具備跟隨指標的調整大小把手。(#4131, #4133)

## 🐛 錯誤修正

- Notebook 優先選擇就緒的受管理預設執行階段，失敗的 shell 執行會以 MCP 錯誤回報，且單次執行失敗不再意味著所有執行都失敗。(#4101, #4112, #4093)
- 渲染器復原不再在執行階段作業期間停滯。(#3972)
- 工作區面板維持在檢視範圍內，待處理的提問互動也更為簡化。(#4107, #4094)
- ACP 不再過早復原 ask-user 的後續流程。(#4096)
- Notebook 的網路存取遵循單一 HTTPS 政策，對不安全端點需明確核准；程式碼審查不再對純量回呼誤報風險。(#4098, #4130)
- 原生影像可在 Codex Chat 橋接上顯示。(#4128)
- 工作階段儲存證據在精簡欄位復原後仍會保留，刪除工作階段不再等待框架重新連線。(#4123, #4121)
- 從已連線的桌面將研究影片匯出為 MP4 時，會重新開啟儲存對話方塊，不再失敗。(#4126)
