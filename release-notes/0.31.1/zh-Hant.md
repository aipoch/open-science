## ✨ 亮點

- **透過登錄號取得定序資料。**新增的 ENA 工具可將公開的 ENA/INSDC study、experiment、sample 或 run 登錄號解析為對應的定序資料——一併回傳研究、樣本、實驗、生物體、定序平台與文庫中繼資料，以及由封存產生、可直接用於後續分析的 FASTQ 檔案。(#2813)
- **由 g:Profiler 驅動的基因集富集分析。**Genes 連接器現在可對差異表現或 marker 基因集執行 GO 與路徑（pathway）富集分析，支援限定物種、選擇證據來源，並可指定明確的統計背景，讓富集結果更可控。(#2802)
- **NCBI 參考基因體查詢。**獨立的 NCBI 工具可解析分類群名稱並回報歧義、檢視帶版本的基因體組裝，以及查詢序列別名——歷史組裝登錄號仍可查詢，不會被最新修訂版取代。(#2796)
- **可選的分類模型。**設定可連接專責的分類服務，讓技能與連接器的能力選擇在專為此用途挑選的模型上執行，而非使用對話模型；在新增服務之前此功能維持關閉，已儲存的憑證也會先驗證成功才保留。(#2799)

## 🚀 新功能

- 遠端存取配對請求現在會顯示在受信任瀏覽器清單之前，並附帶倒數計時、緊急徽章與配對碼核對指引——即使由目前的瀏覽器撤銷自身，撤銷受信任瀏覽器仍然安全。(#2812)
- 受 Notebook 網路保護而受阻的 R 執行會顯示內嵌警告卡，連結至可解除限制的網路設定，並說明該儲存格並未執行。(#2790)

## 🔧 改進項目

- 長篇對話保持流暢：逐字稿歷史版面與串流訊息解析均設有上限，註解與調整大小的訂閱處理也更加穩定。(#2801, #2807)
- Notebook 執行歷史會追蹤 REPL 相依項，並記錄工作階段交接所產生的檔案譜系。(#2808)
- 分類執行會記錄每次呼叫的診斷資訊，讓默默發生的模型失敗變得可見。(#2806)

## 🐛 問題修復

- **Notebook 與運算**——Windows 上持續存在的核心行程樹會受到監督，讓執行乾淨地結束 (#2770)；過期的 Windows R 套件清查會重試而非直接失敗 (#2789)；來自 micromamba 環境的套件清查報告會被接受 (#2774)；REPL 終止會記錄診斷資訊 (#2777)；shell 指令可存取經 GUI 授權的外部資料夾 (#2797)；封裝的 Notebook 指令碼不再誤取無關的模組定義 (#2781)。
- **工作階段與智能體執行環境**——遺失的 OpenCode 工作階段會在啟動時復原 (#2805)；重複的工作階段恢復擁有權會受到防護 (#2810)；取消狀態會被保留，未回收的委派會被隔離 (#2518)；缺少 Codex rollout 檔案的工作階段會被收養 (#2779)；來自家訊息的可靠延續會被接受 (#2803)；委派擁有權記錄可在應用程式重新啟動後復原 (#2785)；工作階段身分會在框架切換時保留 (#2778)。
- **連接器**——GTEx 基因參考結果改為分頁呈現而非截斷 (#2768)；Open Targets GraphQL 的部分錯誤會被呈現出來，而非默默捨棄 (#2760)；hg19 保守性分析會選取正確的預設軌道 (#2796)。
- **介面與儲存**——核准卡不再重新開啟或搶走輸入框焦點 (#2654)；重複的待處理訊息預覽已移除 (#2655)；最近工作階段清單在工作階段更新時仍保持排序 (#2769)；鍵盤存取的退化問題已處理 (#2786)；被動的執行環境觀察器不再與工作階段儲存衝突 (#2649)；OpenCode 發佈在檔案權限錯誤中斷後可復原 (#2780)；技能建立器的輔助工具不再與無關的模組定義混淆 (#2804)；文獻圖片與表格結構可正確地從 PDF 復原 (#2794)。
