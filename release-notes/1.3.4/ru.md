## ✨ Основные изменения

- **Загляните внутрь встроенного Agent.** Проекты могут включить трассировку Agent, экспортирующую связанные спаны для ходов, запросов модели и выполнений инструментов в принимающий OTLP/HTTP-концентратор, который вы разворачиваете сами, — поддерживаются универсальные коллекторы и Langfuse, — при этом уровень детализации захвата вы контролируете. (#4514)
- **Обновления Windows без блокировок и меньшего размера.** Обновление внутри приложения больше не зависает, пока работает встроенный Agent: установщик обновлений теперь распознаёт собственные процессы Agent приложения вместо отказа безопасным образом. Стабильные обновления Windows также снова применяются как компактные дельты установщика — в v1.3.3 происходил откат к полному установщику. (#4602, #4606, #4611, #4605)
- **Длинные истории Notebook остаются быстрыми.** Запуск и завершение запусков, выбор результатов и открытие предпросмотров больше не перечитывают всю историю, а подходящие переходы запусков объединяются в долговечные контрольные точки. (#4615, #4617)
- **Показания памяти, которым можно доверять.** На macOS сводка Compute теперь совпадает с Activity Monitor за счёт исключения кэшированной памяти; на Windows рядом с физической памятью показывается выделенная память относительно её лимита. (#4599, #4600)

## ⚠️ Область применения и безопасность

- **Трассировка Agent отправляет данные в настроенный вами приёмник.** Трассировка отключена, пока её не включит проект, и спаны — структура ходов, запросы модели и выполнения инструментов на выбранном вами уровне детализации — попадают только в конечную точку OTLP/HTTP из конфигурации запуска приложения и никогда не отправляются в обслуживаемую приложением службу. Выбирайте приёмник, которым вы управляете, и проверяйте переключатели захвата перед включением трассировки на общих машинах. См. [получателей данных](https://github.com/aipoch/open-science/blob/v1.3.4/docs/security.md#data-recipients). (#4514)

## 🚀 Новые возможности

- Проекты получают опциональный переключатель **трассировки Agent**: при включении и настроенном приёмнике встроенный Agent экспортирует связанные спаны OTLP/HTTP в формате JSON для ходов, запросов модели и выполнений инструментов MCP в универсальные коллекторы или Langfuse. Четыре переключателя детализации настраивают, что захватывается, а локальный переключатель статуса отправки сообщает о состоянии доставки. (#4514)
- Подключения CodeBuddy определяют поддерживаемые каждой моделью уровни рассуждений при входе и обновлении каталога; затем средство выбора уровня предлагает только те уровни, которые действительно поддерживает выбранная модель. (#4619)

## 🔧 Улучшения

- Длинные истории Notebook стоят дешевле: ограниченное, проверенное представление истории заменяет повторные полные чтения при запуске или завершении запуска, выборе результатов или открытии предпросмотров, а подходящие переходы запусков записываются в долговечные слоты для каждой дорожки, которые сворачиваются в контрольные точки. (#4615, #4617)
- Сводка системы Compute приводится в соответствие с нативным учётом каждой платформы: на macOS использование совпадает с Activity Monitor (исключена кэшированная память), а на Windows показывается выделенная память относительно её лимита с настроенными порогами по умолчанию. (#4599, #4600)

## 🐛 Исправления ошибок

- На Windows обновление внутри приложения больше не зависает, пока работает встроенный Agent или помощник изображений, — оба теперь распознаются как собственные помощники установки приложения, а регистрация помощников принудительно обеспечивается автоматически, чтобы новый помощник больше никогда не пропускался. (#4602, #4606, #4611)
- Стабильные выпуски Windows снова публикуют компактную дельту установщика, используемую для дельта-обновлений; отсутствующую дельту для уже опубликованного выпуска можно восстановить без повторной поставки версии. (#4605)
- Подписки CodeBuddy на фильмы теперь корректно готовят свой первый запрос модели, а боковые чаты встроенного Agent сохраняют свои контрольные точки в собственном профиле чата. (#4616)
- Сгенерированные версии редактирования изображения надёжно открываются в полном предпросмотре, пока их версия ещё публикуется. (#4603)
- Явные HTTP-статусы вышестоящего уровня отображаются как сведения поставщика: статус 402 вроде «Insufficient Balance» теперь показывает применимое к оплате объяснение с сохранением статуса и безопасных сведений о поставщике. (#4601)
- На Windows первый поток построения графиков Python больше не зависает из-за остаточного барьера восстановления ядра от посторонней дорожки. (#4620)
