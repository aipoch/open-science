## ✨ 亮點

- **看見內建 Agent 的內部。** 專案可選擇啟用 Agent 追蹤，將對話回合、模型請求與工具執行的相關 span 匯出至你自行託管的 OTLP/HTTP 接收端——支援通用收集器與 Langfuse——擷取細節由你掌控。（#4514）
- **Windows 更新不再卡住，而且更小。** 內建 Agent 執行時，應用程式內更新不再停滯：更新器現在會辨識應用程式自身的 Agent 程序，不再以防呆方式失敗。穩定版 Windows 更新也恢復以精簡的安裝程式差量套用——v1.3.3 曾退回完整安裝程式。（#4602、#4606、#4611、#4605）
- **長 Notebook 歷程保持快速。** 啟動與完成 Run、選取結果、開啟預覽時，不再重新讀取整個歷程，符合條件的 Run 轉換會批次寫入持久檢查點。（#4615、#4617）
- **可信賴的記憶體讀數。** 在 macOS 上，Compute 摘要現在透過排除快取記憶體而與活動監視器一致；在 Windows 上，則會在實體記憶體之外顯示認可記憶體相對於其上限的情況。（#4599、#4600）

## ⚠️ 範圍與安全

- **Agent 追蹤會將資料傳送到你設定的接收端。** 專案追蹤預設為關閉，僅在專案啟用後才開始；若是單次 CLI Run，`--otel-traces`（或在 SDK 中設為 `otelTraces: true`）則是明確的逐次執行選擇加入，不需要專案開關。兩種情況下，span——依你所選擷取細節記錄的對話回合結構、模型請求與工具執行——都只會傳送至應用程式啟動設定中設定的 OTLP/HTTP 端點，絕不送往應用程式營運的服務。請選擇你掌控的接收端，並在共用機器上啟用追蹤之前檢視擷取開關。請參閱[資料接收方](https://github.com/aipoch/open-science/blob/v1.3.4/docs/security.md#data-recipients)。（#4514）

## 🚀 新功能

- 專案新增可選擇啟用的 **Agent 追蹤**開關：啟用且已設定接收端時，內建 Agent 會將對話回合、模型請求與 MCP 工具執行的相關 OTLP/HTTP JSON span 匯出至通用收集器或 Langfuse。四個細節開關可調整擷取內容，另有一個本機上傳狀態開關會回報傳送健康狀況。（#4514）
- CodeBuddy 連線會在登入與目錄重新整理時探索每個模型支援的推理強度；強度選擇器隨後只提供所選模型實際支援的層級。（#4619）
- 智譜（Zhipu）模型目錄現在列出 GLM-5.4，可直接在智譜連線上使用。（#4637）

## 🔧 改進

- 長 Notebook 歷程的成本更低：啟動或完成 Run、選取結果或開啟預覽時，改以有界且經驗證的歷程檢視取代重複的完整讀取，符合條件的 Run 轉換會寫入持久的每通道槽位，再合併為檢查點。（#4615、#4617）
- Compute 系統摘要與各平台的原生統計方式對齊：macOS 的使用量與活動監視器一致（排除快取記憶體），Windows 則顯示認可記憶體相對於其上限，並採用調校過的預設閾值。（#4599、#4600）

## 🐛 錯誤修正

- 在 Windows 上，內建 Agent 或影像協助程式執行時，應用程式內更新不再停滯——兩者現在都會被辨識為應用程式自身的安裝協助程式，且協助程式註冊會自動強制執行，不再遺漏新安裝的協助程式。（#4602、#4606、#4611）
- 穩定版 Windows 版本再次發布用於差量更新的精簡安裝程式差量；已發布版本缺少差量時，可在不重發該版本的情況下修復。（#4605）
- CodeBuddy 影片訂閱現在會正確備妥其首次模型請求，內建 Agent 的側邊對話會將檢查點保留在該對話自己的設定檔之下。（#4616）
- 產生的編輯影像版本在其版本仍在發布時，也能可靠地在完整影像預覽中開啟。（#4603）
- 明確的上游 HTTP 狀態會以提供者事實呈現：像「Insufficient Balance」這類 402 現在會顯示可採取行動的帳務說明，並保留狀態與安全的提供者詳細資訊。（#4601）
- 在 Windows 上，第一個 Python 繪圖流程不再因來自無關通道遺留的 kernel 復原阻擋而停滯。（#4620）
- 工具動作被拒絕時，對話回合現在會以持久的說明結束，不再無聲消失，且拒絕次數與已完成的工作分開計算。（#4517）
- CodeBuddy 連線在恢復帶有歷程的工作階段時，會還原先前選取的模型，讓 token 用量更新持續流動。（#4631）
- 研究影片生成保持可見：對話會留在「進行中」並顯示其影片狀態，被阻擋的影片對話框也能開啟擁有該生成的對話。（#4633）
- 內建 Agent 現在接受帶有 null 身分欄位的工具延續，不再因此失敗整個回合。（#4638）
