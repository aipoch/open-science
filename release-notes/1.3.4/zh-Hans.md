## ✨ 亮点

- **看清内置 Agent 的内部。** 项目可选择开启 Agent 追踪，将回合、模型请求与工具执行彼此关联的 span 导出到你自行托管的 OTLP/HTTP 接收端——支持通用采集器与 Langfuse——捕获细节由你掌控。(#4514)
- **Windows 更新不再受阻，且体积更小。** 内置 Agent 运行时，应用内更新不再停滞：更新器现在能识别应用自身的 Agent 进程，而不是直接失败。Windows 稳定版更新也重新以紧凑的安装器增量包形式应用——v1.3.3 曾回退为完整安装包。(#4602, #4606, #4611, #4605)
- **长 Notebook 历史保持快速。** 启动与结束 Run、选择结果、打开预览都不再重新读取整个历史，符合条件的 Run 状态转换会被批量写入持久检查点。(#4615, #4617)
- **值得信赖的内存读数。** 在 macOS 上，Compute 摘要现在与活动监视器一致，排除了缓存内存；在 Windows 上，已提交内存相对其上限的用量会与物理内存一并显示。(#4599, #4600)

## ⚠️ 范围与安全

- **Agent 追踪会将数据发送到你配置的接收端。** 追踪默认关闭，直到项目主动启用；span——回合结构、模型请求与你所选捕获细节下的工具执行——只发往应用启动配置中设置的 OTLP/HTTP 端点，绝不发往应用运营的服务。请选择你掌控的接收端，并在共享机器上启用追踪前检查各捕获开关。参见[数据接收方](https://github.com/aipoch/open-science/blob/v1.3.4/docs/security.md#data-recipients)。(#4514)

## 🚀 新功能

- 项目新增可选开启的 **Agent 追踪**开关：启用并配置接收端后，内置 Agent 会将回合、模型请求与 MCP 工具执行彼此关联的 OTLP/HTTP JSON span 导出到通用采集器或 Langfuse。四个细节开关调节捕获内容，另有一个本地上传状态开关报告投递健康状况。(#4514)
- CodeBuddy 连接会在登录与目录刷新时发现每个模型支持的推理档位；档位选择器随后只提供所选模型实际支持的级别。(#4619)

## 🔧 改进

- 长 Notebook 历史的开销更低：启动或结束 Run、选择结果、打开预览时，以有界且经过校验的历史视图取代反复的全量读取，符合条件的 Run 状态转换写入持久的按通道槽位，并合并进检查点。(#4615, #4617)
- Compute 系统摘要与各平台原生计数方式对齐：macOS 的占用量与活动监视器一致（排除缓存内存），Windows 显示已提交内存相对其上限，并调整了默认阈值。(#4599, #4600)

## 🐛 问题修复

- 在 Windows 上，内置 Agent 或图像助手运行时，应用内更新不再停滞——两者现在都被识别为应用自身的安装助手，且助手注册会自动强制执行，再也不会遗漏新的助手。(#4602, #4606, #4611)
- Windows 稳定版重新发布用于增量更新的紧凑安装器增量包；已发布版本缺失的增量包可以在不重新发布该版本的情况下修复。(#4605)
- CodeBuddy 影片订阅现在能正确准备首个模型请求，内置 Agent 的侧聊会将检查点保存在该聊天自身的 profile 下。(#4616)
- 生成的图像编辑版本在版本仍在发布时也能可靠地在完整图像预览中打开。(#4603)
- 显式的上游 HTTP 状态会作为提供商事实呈现：402（例如“余额不足”）现在会显示可操作的计费说明，并保留该状态与安全的提供商详情。(#4601)
- 在 Windows 上，首次 Python 绘图流程不再因无关通道遗留的内核恢复栅栏而停滞。(#4620)
