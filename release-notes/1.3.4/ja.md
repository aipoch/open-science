## ✨ Highlights

- **組み込み Agent の内部が見えるようになりました。** プロジェクトは Agent トレーシングをオプトインでき、ターン、モデルリクエスト、ツール実行の相関スパンを、自分がホストする OTLP/HTTP レシーバーに — 汎用コレクターや Langfuse に対応 — 捕捉の詳細度を自分で制御しながらエクスポートできます。(#4514)
- **Windows のアップデートが阻害されなくなり、さらに小さく。** アプリ内アップデートは、組み込み Agent が実行中でも停止しなくなりました。アップデーターはアプリ自身の Agent プロセスを認識するため、閉じて失敗することがなくなります。Windows の安定版アップデートも再びコンパクトなインストーラーの差分として適用されるようになりました — v1.3.3 では完全なインストーラーへのフォールバックが発生していました。(#4602, #4606, #4611, #4605)
- **長い Notebook の履歴も快適なまま。** Run の開始と終了、結果の選択、プレビューのオープンで履歴全体の再読み込みが行われなくなり、対象となる Run の遷移は耐久性のあるチェックポイントにバッチ処理されるようになりました。(#4615, #4617)
- **信頼できるメモリの読み値。** macOS では、Compute サマリーがキャッシュ済みメモリを除外することでアクティビティモニターと一致するようになり、Windows では物理メモリに加えて、上限に対するコミット済みメモリが表示されます。(#4599, #4600)

## ⚠️ 適用範囲と安全性

- **Agent トレーシングは設定したレシーバーにデータを送信します。** プロジェクトのトレーシングは既定でオフのままで、プロジェクトが有効にした場合にのみ開始されます。単一の CLI Run では、`--otel-traces`（または SDK での `otelTraces: true`）が明示的な実行単位ごとのオプトインであり、プロジェクトのスイッチは必要ありません。いずれの場合も、スパン — ターンの構造、モデルリクエスト、選択した捕捉詳細度でのツール実行 — はアプリの起動設定で指定された OTLP/HTTP エンドポイントにのみ送信され、アプリが運用するサービスには送信されません。自分が管理するレシーバーを選び、共有マシンでトレーシングを有効にする前に捕捉スイッチを確認してください。[データの受領者](https://github.com/aipoch/open-science/blob/v1.3.4/docs/security.md#data-recipients)を参照してください。(#4514)

## 🚀 New Features

- プロジェクトにはオプトインの **Agent トレーシング** スイッチが追加されます。有効化され、レシーバーが設定されている場合、組み込み Agent はターン、モデルリクエスト、MCP ツール実行の相関する OTLP/HTTP JSON スパンを汎用コレクターや Langfuse にエクスポートします。4 つの詳細度スイッチで捕捉内容を調整でき、ローカルの送信状態スイッチが配信の健全性を報告します。(#4514)
- CodeBuddy 接続は、サインインとカタログ更新の際に各モデルがサポートする reasoning effort を検出するようになり、effort ピッカーは選択したモデルが実際にサポートするレベルのみを提示します。(#4619)
- Zhipu のモデルカタログに GLM-5.4 が追加され、Zhipu 接続で直接利用できるようになりました。(#4637)

## 🔧 Improvements

- 長い Notebook の履歴のコストが削減されました。Run の開始や終了、結果の選択、プレビューのオープンで繰り返されていた全体の読み込みに代わり、上限の決まった検証済みの履歴ビューが使われるようになり、対象となる Run の遷移は、チェックポイントにまとめられる耐久性のあるレーンごとのスロットに書き込まれます。(#4615, #4617)
- Compute のシステムサマリーは各プラットフォームのネイティブな計測と一致するようになりました。macOS の使用率はアクティビティモニターと一致し（キャッシュ済みメモリを除外）、Windows では調整済みの既定のしきい値とともに上限に対するコミット済みメモリが表示されます。(#4599, #4600)

## 🐛 Bug Fixes

- Windows では、組み込み Agent や画像ヘルパーの実行中にアプリ内アップデートが停止しなくなりました — 両方ともアプリ自身のインストールヘルパーとして認識され、ヘルパーの登録は自動的に強制されるため、新しいヘルパーが見落とされることは二度とありません。(#4602, #4606, #4611)
- Windows の安定版リリースは、差分アップデートで使われるコンパクトなインストーラーの差分を再び公開するようになり、既に公開済みのリリースで差分が欠けている場合は、そのバージョンを再出荷せずに修復できます。(#4605)
- CodeBuddy のフィルムサブスクリプションは最初のモデルリクエストを正しく準備するようになり、組み込み Agent のサイドチャットはチャット自身のプロファイルの下でチェックポイントを維持するようになりました。(#4616)
- 生成された画像編集バージョンは、バージョンの公開処理が進んでいる間も完全な画像プレビューで確実に開けるようになりました。(#4603)
- 明示的なアップストリームの HTTP ステータスはプロバイダーの事実として表示されるようになりました。「Insufficient Balance」のような 402 では、ステータスと安全なプロバイダー詳細が保持された、実行可能な課金の説明が表示されるようになりました。(#4601)
- Windows では、最初の Python プロットのフローが、無関係なレーンに残ったカーネル復旧のフェンスで停止しなくなりました。(#4620)
- ツールアクションが拒否された場合、ターンは黙って終わる代わりに耐久性のある説明で終了するようになり、拒否のカウントは完了した作業と区別されたままになります。(#4517)
- CodeBuddy 接続は、履歴を持つセッションを再開する際に選択したモデルを復元するようになり、トークン使用量の更新が途切れなく流れ続けます。(#4631)
- リサーチフィルムの生成物は表示されたままになります。会話はフィルムのステータスとともにアクティブなまま残り、ブロックされたフィルムのダイアログはその生成物を所有する会話を開くことができます。(#4633)
- 組み込み Agent は、null の ID フィールドを持つツールの継続も受け入れるようになり、ターンが失敗しなくなりました。(#4638)
