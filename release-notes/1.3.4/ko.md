## ✨ Highlights

- **내장 Agent 안을 들여다보기.** 프로젝트는 Agent 추적을 선택할 수 있고, 턴과 모델 요청, 도구 실행에 대한 연관된 스팬을 직접 호스팅하는 OTLP/HTTP 수신자로 내보낼 수 있습니다 — 일반 수집기와 Langfuse가 지원됩니다 — 캡처 수준은 직접 조절합니다. (#4514)
- **막히지 않고 더 작아진 Windows 업데이트.** 내장 Agent가 실행 중일 때도 앱 내 업데이트가 더 이상 멈추지 않습니다. 업데이트 프로그램이 이제 앱 자체의 Agent 프로세스를 인식해 폐쇄적으로 실패하지 않습니다. 안정 Windows 업데이트는 또한 다시 작은 설치 프로그램 델타로 적용됩니다 — v1.3.3에서는 전체 설치 프로그램으로 대체되었습니다. (#4602, #4606, #4611, #4605)
- **긴 Notebook 기록도 빠르게 유지됩니다.** Run 시작과 완료, 결과 선택, 미리보기 열기가 더 이상 전체 기록을 다시 읽지 않으며, 자격을 갖춘 Run 전환은 지속 가능한 체크포인트로 묶여 기록됩니다. (#4615, #4617)
- **믿을 수 있는 메모리 읽기.** macOS에서는 Compute 요약이 캐시된 메모리를 제외해 활성 상태 보기와 일치하고, Windows에서는 한도 대비 확정 메모리가 물리 메모리와 함께 표시됩니다. (#4599, #4600)

## ⚠️ 범위와 안전

- **Agent 추적은 설정한 수신자로 데이터를 보냅니다.** 프로젝트 추적은 기본적으로 비활성화되어 있고 프로젝트가 켜야만 시작되며, 단일 CLI Run의 경우 `--otel-traces`(또는 SDK에서 `otelTraces: true`)는 프로젝트 스위치 없이도 작동하는 명시적인 실행 단위 옵트인입니다. 두 경우 모두 스팬 — 턴 구조, 모델 요청, 선택한 캡처 수준의 도구 실행 — 은 앱이 운영하는 서비스가 아니라 앱의 시작 설정에 지정된 OTLP/HTTP 엔드포인트로만 전달됩니다. 직접 제어하는 수신자를 선택하고, 공유 기기에서 추적을 켜기 전에 캡처 설정을 검토하세요. [데이터 수신자](https://github.com/aipoch/open-science/blob/v1.3.4/docs/security.md#data-recipients)를 참조하세요. (#4514)

## 🚀 New Features

- 프로젝트에 선택형 **Agent 추적** 스위치가 생깁니다. 켜져 있고 수신자가 설정되어 있으면 내장 Agent가 턴과 모델 요청, MCP 도구 실행에 대한 연관된 OTLP/HTTP JSON 스팬을 일반 수집기나 Langfuse로 내보냅니다. 네 개의 세부 스위치가 무엇을 캡처할지 조절하고, 로컬 업로드 상태 스위치가 전달 상태를 보고합니다. (#4514)
- CodeBuddy 연결은 로그인과 카탈로그 새로 고침 때 각 모델이 지원하는 추론 수준을 확인하고, 수준 선택기는 이후 선택한 모델이 실제로 지원하는 수준만 제공합니다. (#4619)
- Zhipu 모델 카탈로그에 GLM-5.4가 추가되어 Zhipu 연결에서 바로 사용할 수 있습니다. (#4637)

## 🔧 Improvements

- 긴 Notebook 기록 비용이 줄었습니다. Run 시작과 완료, 결과 선택, 미리보기 열기 때 반복적인 전체 읽기를 대체하는 경계가 있고 검증된 기록 보기가 사용되며, 자격을 갖춘 Run 전환은 체크포인트로 합쳐지는 지속 가능한 레인별 슬롯에 기록됩니다. (#4615, #4617)
- Compute 시스템 요약이 각 플랫폼의 기본 계산 방식과 맞춰집니다. macOS 사용량은 활성 상태 보기와 일치하고(캐시된 메모리 제외), Windows는 조정된 기본 임계값과 함께 한도 대비 확정 메모리를 표시합니다. (#4599, #4600)

## 🐛 Bug Fixes

- Windows에서는 내장 Agent나 이미지 도우미가 실행 중일 때도 앱 내 업데이트가 더 이상 멈추지 않습니다 — 둘 다 이제 앱 자체의 설치 도우미로 인식되며, 도우미 등록이 자동으로 강제되어 새 도우미가 다시 누락되지 않습니다. (#4602, #4606, #4611)
- 안정 Windows 릴리스는 델타 업데이트에 사용되는 작은 설치 프로그램 델타를 다시 게시합니다. 이미 게시된 릴리스의 누락된 델타는 해당 버전을 다시 배송하지 않고도 복구할 수 있습니다. (#4605)
- CodeBuddy 필름 구독이 이제 첫 모델 요청을 올바르게 준비하고, 내장 Agent 사이드 채팅은 채팅 자체 프로필 아래에 체크포인트를 유지합니다. (#4616)
- 생성된 이미지 편집 버전은 버전이 아직 게시되는 동안에도 전체 이미지 미리보기에서 안정적으로 열립니다. (#4603)
- 명시적인 업스트림 HTTP 상태는 제공자 사실로 표시됩니다. "Insufficient Balance" 같은 402는 이제 상태와 안전한 제공자 세부 정보를 유지한 채 조치 가능한 결제 설명과 함께 표시됩니다. (#4601)
- Windows에서는 첫 Python 플로팅 흐름이 더 이상 관련 없는 레인에 남은 커널 복구 장벽에서 멈추지 않습니다. (#4620)
- 도구 작업이 거부되면 이제 턴이 침묵하는 대신 지속 가능한 설명으로 끝나고, 거부 횟수는 완료된 작업과 구분된 상태로 유지됩니다. (#4517)
- CodeBuddy 연결은 기록이 있는 세션을 재개할 때 선택한 모델을 복원하므로, 토큰 사용량 업데이트가 계속 이어집니다. (#4631)
- 리서치 필름 생성은 계속 보이는 상태를 유지합니다. 대화는 필름 상태와 함께 활성 상태로 남고, 차단된 필름 대화 상자는 해당 생성을 소유한 대화를 열 수 있습니다. (#4633)
- 내장 Agent는 턴을 실패시키는 대신 null 식별 필드를 가진 도구 연속 동작을 받아들입니다. (#4638)
