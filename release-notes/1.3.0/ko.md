## ✨ Highlights

- **예약된 연구 작업.** 반복 또는 1회 일정을 설정하면 세션과 Notebook 작업이 스스로 시작됩니다. 각 실행은 작업 공간에 별도의 기록으로 열리고, 명확한 실행 기록 덕분에 언제든 제어권을 유지합니다. (#4380)
- **이미지 생성과 편집.** 구성된 제공업체로 프롬프트에서 이미지를 생성한 뒤 이어서 다듬으세요. 각 편집은 새 버전으로 저장되어 프로젝트 전체에서 이전 변형을 비교하고, 다시 보고, 재사용할 수 있습니다. (#4424)
- **편집 가능한 프레젠테이션.** PowerPoint 파일이 편집을 위해 열립니다. 글꼴, 크기, 색상, 정렬 등의 서식을 갖춘 텍스트를 수정하고 파일 구조는 그대로 유지한 채 앱 안에서 모두 처리됩니다. (#4392)
- **다시 재생하는 연구 영상.** 영상 작업을 새 브랜치에 독립적인 출력으로 재생할 수 있고, 영상은 세션 메뉴에서 바로 열리며, 영상 대화 상자는 생성 전에 토큰 사용량을 설명합니다. (#4389, #4414)
- **더 똑똑한 에이전트 질문.** 에이전트가 입력이 필요할 때 이제 제시하는 옵션들의 장단점을 정리해 보여 주므로, 결과를 함께 본 상태에서 결정할 수 있습니다. (#4357)

## ⚠️ 범위와 안전

- **예약된 작업은 프로젝트의 권한으로 실행됩니다.** 앱이 실행 중인 동안 예약 작업은 세션이나 Notebook 실행을 별도의 확인 없이 시작합니다. 실행은 프로젝트에 이미 부여된 폴더, 자격 증명, 네트워크 접근으로 작동하며, 구성된 제공업체의 할당량을 사용합니다. 사용을 시작하기 전에 예약 작업의 대상, 주기, 프로젝트 권한을 검토하고, 더 이상 필요 없는 예약 작업은 일시 중지하거나 삭제하세요. [알려진 제한사항 등록부의 예약 작업 경계](https://github.com/aipoch/open-science/blob/v1.3.0/docs/known-limitations.md)를 참조하세요. (#4380)
- **이미지 생성과 편집은 프롬프트와 원본 이미지를 구성한 제공업체에 전달합니다.** 생성 요청과 원본으로 사용된 이미지는 구성한 제공업체 연결을 통해 전송되며, 로컬에서 취소하거나 삭제해도 제공업체가 이미 받은 바이트는 회수할 수 없습니다. 민감한 자료로 생성하기 전에 제공업체의 데이터 조건을 검토하세요. [데이터 수신자](https://github.com/aipoch/open-science/blob/v1.3.0/docs/security.md#data-recipients)를 참조하세요. (#4424)

## 🚀 New Features

- 반복 또는 1회 주기로 세션을 시작하거나 Notebook을 실행하는 예약 작업을 만듭니다. 각 예약 실행은 작업 공간에 별도의 기록으로 열리며, 실행 기록은 일정별로 유지됩니다. (#4380)
- 구성된 제공업체를 통해 프롬프트에서 이미지를 생성하고 후속 지시로 편집합니다. 생성과 편집은 모두 새 아티팩트 버전을 저장하며, 이전 변형은 비교와 재사용을 위해 계속 사용할 수 있습니다. (#4424)
- PowerPoint 프레젠테이션을 그 자리에서 편집합니다. 슬라이드 구조가 유지되는 동안 글꼴, 크기, 색상, 정렬을 적용해 텍스트를 선택하고 수정합니다. (#4392)
- 연구 영상 작업을 다른 브랜치에 재생하고 원본 영상을 건드리지 않은 채 독립적인 출력을 얻습니다. (#4389)
- 생성된 연구 영상을 세션 메뉴에서 바로 열고, 영상 생성에 얼마나 많은 토큰이 사용되는지 미리 설명해 주는 안내를 확인합니다. (#4414)
- 앱에서 실행 중인 Notebook 프로세스를 모니터링하고, 더 이상 필요 없는 앱 소유 프로세스를 중지합니다. (#4399)
- 문서와 그림 스킬은 바로 사용할 수 있습니다. 지원 라이브러리가 작업 중간에 실패하는 대신 관리 환경에 처음 사용할 때 미리 설치됩니다. (#4411)

## 🔧 Improvements

- 긴 대화 기록이 점진적으로 저장되므로, 큰 세션도 계속 저장되고, 더 빠르게 다시 로드되며, 커져도 반응성을 유지합니다. (#4378)
- 앱이 시작 시 첫 화면을 막던 작업을 줄여 더 빨리 프로젝트 홈에 도달합니다. (#4398)
- 멈춘 영상 생성, 연구 패키지 전송, 백그라운드 전달은 재시작을 기다리지 않고 스스로 복구됩니다. (#4372)
- Windows 설치와 업데이트는 더 가볍고 안정적인 패키징 파이프라인을 사용하고, 업데이트 준비 확인에는 상한이 있어 흐름이 멈추지 않습니다. (#4420, #4417)
- 컴퓨팅 대상의 복구 예약이 고정 타이머 대신 필요할 때 실행되어 유휴 오버헤드를 줄입니다. (#4375)
- 스킬 참조가 공개 OpenCode 2.x 스킬 이름과 일치하므로, 가져온 스킬이 예상대로 해석됩니다. (#4355)
- 외부 PDF는 분석과 번역 중 기본 구조를 더 안정적으로 복구하고, 리더는 도구 모음을 정리하며, 이미지 지원 제한은 조용히 실패하는 대신 그 이유를 설명합니다. (#4361, #4360, #4435, #4407, #4394, #4400)
- composer는 좁은 레이아웃에서도 전송 컨트롤에 닿게 하고, 컨텍스트 사용량을 정확하게 표시하며, 대화에 마우스를 올리면 최신으로 이동하는 화살표를 보여 줍니다. (#4367, #4403)
- 긴 대화의 첫 화면은 상한이 정해져 있어 로드된 메시지가 많아도 창이 빠르게 열립니다. (#4376)

## 🐛 Bug Fixes

- 레코드가 복구될 때 세션이 올바른 번호를 유지하고, 저널 재생은 더 이상 작업을 반복하거나 기록을 불필요하게 다시 검색하지 않습니다. (#4368, #4432, #4428)
- 에이전트 런타임은 에이전트 수명 주기 전반에 걸쳐 리소스를 해제하므로, 반복 실행에서 오버헤드가 누적되지 않습니다. (#4396)
- 스킬 다시 로드가 더 이상 진행 중인 세션 생성을 중단시키지 않습니다. (#4427)
- 에이전트 핸드오프는 도구 결과가 잘려도 메타데이터를 유지합니다. (#4413)
- 로컬 CLI를 통한 아티팩트 다운로드는 데이터가 아직 도착 중일 때 시간 초과되지 않습니다. (#4430)
- 원격 작업 요청과 다운로드는 호출자의 수명을 존중하므로, 버려진 작업이 즉시 중지됩니다. (#4390)
- 터미널 Ray 작업은 수확 후 제거되어 대상에 남지 않습니다. (#4386)
- ACP 리소스 링크가 다시 허용됩니다. (#4381)
- 과학 패키지는 실패하는 대신 사용 가능한 가져온 영상 모드를 엽니다. (#4419)
- 미리 보기는 좁은 표면에서도 파일 이름을 유지하고, 실행 표시는 올바른 위치에 놓이며, 프로젝트 전환기는 목록 안에서 스크롤합니다. (#4401, #4350, #4405)
- Notebook 프레임 대본은 꾸준히 페이지로 나뉘고, Markdown 각주는 스크롤이 안쪽에 머무릅니다. (#4370, #4391)
