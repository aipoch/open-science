## ✨ Highlights

- **スケジュールされた研究タスク。** 定期的または一度限りのスケジュールを設定すると、セッションや Notebook タスクが自動で起動します。各実行はワークスペースで独自の記録として開かれ、明確な実行履歴で常に制御を維持できます。(#4380)
- **画像の生成と編集。** 設定済みのプロバイダーでプロンプトから画像を生成し、そのまま反復できます。各編集は新しいバージョンとして保持されるため、プロジェクト全体で以前のバリアントを比較、再訪、再利用できます。(#4424)
- **編集可能なプレゼンテーション。** PowerPoint ファイルが編集のために開きます。フォント、サイズ、色、配置を含む書式付きテキストの修正ができ、ファイルの構造はそのまま維持されます。すべてアプリ内で完結します。(#4392)
- **再現できる研究フィルム。** フィルム操作を新しいブランチに独立した出力で再現でき、フィルムはセッションメニューから直接開け、フィルムダイアログでは生成前にトークン使用量の説明が表示されます。(#4389, #4414)
- **より賢いエージェントの質問。** エージェントが入力を必要とする場合、提示する選択肢同士のトレードオフが示されるため、その結果を見ながら判断できます。(#4357)

## ⚠️ 適用範囲と安全性

- **スケジュールされたタスクは、プロジェクトの権限で実行されます。** アプリが起動している間、スケジュールは追加の確認なしでセッションや Notebook の実行を起動します。その実行は、プロジェクトにすでに付与されているフォルダー、資格情報、ネットワークアクセスを使って動作し、設定済みのプロバイダーのクォータを消費します。有効化する前に、スケジュールの対象、実行間隔、プロジェクトの付与内容を確認し、不要になったスケジュールは一時停止または削除してください。[既知の制限事項レジストリに記載されたスケジュールタスクの境界](https://github.com/aipoch/open-science/blob/v1.3.0/docs/known-limitations.md)を参照してください。(#4380)
- **画像の生成と編集は、プロンプトと元の画像を設定済みのプロバイダーに開示します。** 生成リクエストとソースとして使用される画像は、設定したプロバイダー接続経由で送信されます。キャンセルやローカルでの削除によっても、プロバイダーがすでに受け取ったデータを取り戻すことはできません。機密性の高い素材から生成する前に、プロバイダーのデータ規約を確認してください。[データの受領者](https://github.com/aipoch/open-science/blob/v1.3.0/docs/security.md#data-recipients)を参照してください。(#4424)

## 🚀 New Features

- セッションの起動や Notebook の実行を、定期的または一度限りのスケジュールで行うタスクを作成できます。各スケジュール済み実行はワークスペースで独自の記録として開かれ、実行履歴はスケジュールごとに保持されます。(#4380)
- 設定済みのプロバイダーでプロンプトから画像を生成し、追加の指示で編集できます。生成と編集のたびに新しいアーティファクトバージョンが保存され、以前のバリアントは比較と再利用のために利用可能なまま残ります。(#4424)
- PowerPoint プレゼンテーションをその場で編集できます。スライド構造を維持したまま、フォント、サイズ、色、配置を使ってテキストを選択して修正できます。(#4392)
- 研究フィルムの操作を別のブランチに再現し、元のフィルムに触れずに独立した出力を得られます。(#4389)
- 生成済みの研究フィルムをセッションメニューから直接開き、フィルム生成にどれだけのトークンが使われるかを事前に確認できます。(#4414)
- アプリから実行中の Notebook プロセスを監視し、アプリが所有するプロセスで不要になったものを停止できます。(#4399)
- ドキュメントと図版のスキルはそのまま使えます。必要なライブラリは、タスクの途中で失敗する代わりに、最初の使用時に管理環境へプリインストールされます。(#4411)

## 🔧 Improvements

- 長い会話履歴は増分で永続化されるため、大規模なセッションも継続的に保存され、より速く再読み込みされ、成長しながらも応答性が維持されます。(#4378)
- 初回画面をブロックしていた処理を削減し、アプリの起動時にプロジェクトホームへより早く到達するようになりました。(#4398)
- 停滞したフィルム生成、研究パッケージの転送、バックグラウンドの配信は、再起動を待つ代わりに自動で復旧します。(#4372)
- Windows のインストールと更新は、より軽量で信頼性の高いパッケージングパイプラインを使用し、更新準備の確認は上限が設けられ、フローをハングさせることがありません。(#4420, #4417)
- コンピュートターゲットの復旧スケジュールは、固定タイマーではなくオンデマンドで実行されるため、アイドル時のオーバーヘッドが削減されます。(#4375)
- スキル参照は公開されている OpenCode 2.x のスキル名と整合するため、インポートされたスキルは期待どおりに解決されます。(#4355)
- 外部 PDF は、分析と翻訳の間にネイティブな構造をより確実に復元し、リーダーのツールバーは集約され、画像対応の上限は静かに失敗する代わりに理由を説明するようになりました。(#4361, #4360, #4435, #4407, #4394, #4400)
- コンポーザーは、狭いレイアウトでも送信コントロールに届きやすく、コンテキスト使用量を正確に表示し、会話をホバーすると最新へスクロールする矢印を表示します。(#4367, #4403)
- 長い会話の最初の描画には上限が設けられ、大量のメッセージが読み込まれていてもウィンドウがすばやく開きます。(#4376)

## 🐛 Bug Fixes

- レコードが修復されてもセッションの番号付けが維持され、ジャーナルの再生は作業の繰り返しや履歴の不必要な再スキャンをしなくなりました。(#4368, #4432, #4428)
- エージェントランタイムはエージェントのライフサイクル全体でリソースを解放するため、繰り返し実行してもオーバーヘッドが蓄積しません。(#4396)
- スキルの再読み込みが、進行中のセッション作成を中断しなくなりました。(#4427)
- エージェントのハンドオフは、ツール結果が切り詰められてもメタデータを保持します。(#4413)
- ローカル CLI 経由のアーティファクトのダウンロードは、データがまだ到着している途中でもタイムアウトしなくなりました。(#4430)
- リモートタスクのリクエストとダウンロードは呼び出し側のライフタイムを尊重するため、放棄された操作はすみやかに停止します。(#4390)
- ターミナルの Ray ジョブは、ハーベスト後に削除され、ターゲット上に残らなくなりました。(#4386)
- ACP のリソースリンクが再び受け付けられるようになりました。(#4381)
- サイエンスパッケージは、利用可能なインポート済みフィルムモードを開くようになり、失敗しなくなりました。(#4419)
- プレビューは狭い表示領域でもファイル名を維持し、実行マークは正しい位置に付き、プロジェクト切り替えのスクロールはリスト内に収まります。(#4401, #4350, #4405)
- Notebook フレームのトランスクリプトは安定してページングされ、Markdown の脚注はスクロールが領域内に収まります。(#4370, #4391)
