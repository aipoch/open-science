## ✨ 亮點

- **將工作階段分岔為新的可寫副本。**本地或匯入的工作階段可連同完整研究歷史一併分岔——對話分支、Notebook 記錄、工件版本、文獻、註解與私人書籤都會取得全新身分。來源工作階段永不被更動，匯入的工作階段也維持唯讀。(#2719)
- **產品名稱統一為 Open-Science。**應用程式現在在介面、CLI 與封裝中一致地以 Open-Science 呈現。現有安裝保留其現有名稱與位置——研究資料、憑證與設定均原封不動。(#2567)
- **工作階段計畫可在上下文重建後保留。**智能體重建其上下文後，作用中的工作階段計畫會連同其身分、修訂與待核准項目一併復原，計畫工具在對話中仍可使用。(#2661)
- **服務商連線會先驗證才保留。**服務商編輯會先經過測試，僅在連線成功時才儲存；當已儲存的服務商在執行期間被拒絕時，其可用性會隨之更新，而非默默失敗。(#2746)

## 🚀 新功能

- 對話標頭中的工作階段資訊卡會顯示工作階段的編號、標題、描述、來源工作階段、時間戳記，以及訊息與工件數量，並提供釘選控制項，讓過長的標題保持精簡。(#2764)
- OpenAlex 與 NCBI 的憑證提示會直接連結至官方 API key 頁面。(#2761)
- gnomAD 變異查詢可選擇性地包含群體層級的對偶基因頻率與基因型計數。(#2741)
- 分岔至新對話的工作階段會顯示錨定於其來源輪次的「接續自」分隔線。(#2747)
- 設定統一了所有面板的面板標題、區段標題、儲存回饋與控制項對齊。(#2739)

## ⚠️ 破壞性變更

- 展開後的 STRING 網路現在會在 `nodes` 中回報完整的回傳圖譜：新增的鄰居帶有 `is_query=false`，且 `n_nodes` 不再等於輸入蛋白質的數量。將 `nodes` 視為輸入對映的 Notebook 腳本必須篩選 `is_query`。(#2737)

## 🐛 問題修復

- **Notebook 與運算**——Windows 上的 R 可在標準模式下執行，無需受保護模式設定 (#2708)；工件執行日誌不再顯示錯誤的環境證據缺口 (#2720)；每次執行的鎖定診斷會為可重現性檢查保留 (#2738)。
- **智能體執行環境**——Codex 對話在切換推理強度時仍可正常使用 (#2724)；停滯的停止、恢復與排隊中的後續指令都能可靠地完成 (#2745)；已取消的網路核准會被移除，而非以失效卡片的形式殘留 (#2744)。
- **工作階段與權限**——權限更新送達時，工作階段計畫的步驟進度仍保持可見 (#2759)；權限完成會與並行輪次核對，重複的傳送重試也不再附加未派送的訊息 (#2743)；分支歷史重播前即允許權限變更 (#2736)；分岔分隔線會錨定至被複製的輪次 (#2733)；未發布的工件 head 會在分岔後保留，且不會阻礙啟動 (#2730)。
- **連接器**——UniProt 次要登錄號會解析至其目前的主要條目 (#2762)；Ensembl 會在退回符號查詢前先解析 FlyBase、WormBase 與酵母識別碼，並保留序列請求的錯誤 (#2715, #2752)；cBioPortal 突變頻率會計入已建立基因圖譜的檢體 (#2721)；臨床試驗資格篩選會遵循年齡與性別邊界 (#2734)；分子渲染會保留 molfile 標頭並拒絕空白結構 (#2751)。
- **介面與儲存**——使用中的自訂模型會在其服務商儲存時同步 (#2712)；開啟附加檔案會保留父對話框 (#2735)；關閉對話框不再閃爍或重設內容 (#2723, #2742)；逐字稿跟隨意圖在版面變更後仍會保留 (#2732)；儲存清理與本機匯入會防範符號連結目錄與遭改寫的來源檔案 (#2711)；專家套件的匯入預設與匯出控制項已對齊 (#2756)；唯讀 OpenCode 技能會在委派後清理 (#2716)。
