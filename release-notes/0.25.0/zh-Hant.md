## ✨ 亮點

- **產物現在可以編輯。** Markdown、純文字、指令碼與原始碼產物及上傳檔案，現在都能以原始文字編輯——每次儲存都會發布保留來源沿襲的新版本，並提供與前一版本比較的動作。(#1204)
- **NVIDIA Build 加入內建服務商。** 精選的 NVIDIA 目錄提供六個支援智能體使用的模型，以 NVIDIA Nemotron 3.5 Lightning 為首。(#2055)
- **執行環境可以修復。** 應用程式管理的 Python 與 R 執行環境可從 Settings 安全地重新安裝，並新增開關決定智能體是否能自行建立執行環境。(#1984, #2058)
- **委派由你掌控。** 輸入框智能體控制項中的按會話開關，決定智能體是否可以委派工作。(#2029)

## 🚀 新功能

- **可編輯的產物版本**——文字產物與上傳檔案新增「編輯」與「比較」動作：可編輯 Markdown、純文字、指令碼與原始碼檔案的原始內容，每次儲存都會發布新的受管理版本，而原始沿襲與較早版本仍可瀏覽。(#1204)
- **NVIDIA Build 服務商**——官方 NVIDIA 服務商，附精選目錄，內含六個支援智能體使用的模型，包括 NVIDIA Nemotron 3.5 Lightning（預設）與 Kimi K3，並逐模型標示多模態支援。(#2055)
- **會話委派控制**——輸入框智能體控制項中的精簡「委派」開關；新會話與訊息分支會在第一個提示執行前確認該原則，無法確認時一律預設為不允許。(#2029)
- **專案切換器搜尋**——當作用中專案超過幾個時，工作區專案選單會提供模糊搜尋欄位，標題相符的排名高於僅描述相符的結果，並醒目提示相符文字。(#1964)
- **安全的受管理執行環境重新安裝**——可從 Settings → Runtimes 重新安裝狀態良好的應用程式管理 Python 與 R 執行環境：執行中的核心會先完成收尾，會話會在修復開始前持久地重新繫結，外部直譯器完全不會被更動。(#1984)
- **對智能體建立環境的控制**——全域 Settings 開關決定智能體是否可以建立執行環境；無論開關為何，明確的設定與重新安裝仍然可用。(#2058)
- **Settings → Runtimes 中的網路保護狀態**——具狀態感知的橫幅會顯示 Notebook 網路保護已啟用、需要設定或不支援，並提供前往網域設定的直接路徑——同時不誇大保護程度。(#2011)

## 🔧 改進

- 多版本升級變得更快：每次升級批次現在只建立一份復原快照，而不是每個遷移步驟各建一份，縮短擁有龐大研究歷史的安裝之升級時間與磁碟損耗。(#2039)
- 資料位置遷移會在你確認前顯示目標磁碟的容量與預估複製大小。(#1984)
- Settings 與 About 列改為在懸停或鍵盤聚焦時顯示輔助說明，而不是與主要標籤爭取空間。(#2023, #2026)

## 🐛 問題修復

- **委派與側邊對話**——Codex 訂閱驗證現在會傳播到委派的工作（#1953）；委派問題尚未解決時會封鎖封存（#2015）；結束偵測會計入作用中的側邊對話回覆（#2031）；委派輸入會保持穩定的識別。(#1974)
- **Notebook 與執行環境**——還原受保護的核心啟動（#1995）；移除具誤導性的沙箱警告（#1988）；核心不再循環重試復原（#1998）；注入的執行環境平台會被遵循（#1981）；閘控與重新啟動會遵循執行環境目標（#2046）；輸入與產物檔案工作流程已穩定（#2050）；會處理中斷的回應（#2063）；核准後才顯示環境準備（#2036）；受管理執行環境可在更新失敗後存活（#1994）；連線重設的影響會被控制在局部（#2053）；提示附件在 Notebook 中保持可讀。(#2045)
- **安全性與遠端存取**——原始憑證會從工具活動中遮蔽（#2001）；重播僅限於遠端授權（#1999）；外部存取資源設有上限（#2003）；傳輸邊界也已加固。(#2035)
- **會話與儲存**——資料遷移期間會閘控專案存取（#1996）；壓縮期間會封鎖封存（#2000）；保留的會話工作區會再次顯示（#2002）；專案刪除等待已限定範圍（#2038）；失敗後會停止沖刷寫入（#2040）；會話與專案狀態契約已對齊（#2044）；並保留受管理工作區的擁有權。(#2042)
- **技能、產物與運算**——技能目錄在變更期間不再死鎖（#2048）；永久性完成失敗會被正確分類（#2061）；大型 SSH 指令能可靠串流（#2062）；遠端運算範例會回傳值而不是列印。(#2018)
- **更新、平台與工作區**——乾淨地略過不支援的版本說明語言（#2009）；Windows 上會拒絕已鎖定的解除安裝目標（#2060）；UI 啟動失敗後應用程式會乾淨地結束（#2030）；持久化失敗後結束會要求明確同意（#2032）；小幅向上捲動會被尊重（#2007）；通知能在目標遭拒後存活（#2041）；生成的預覽會等待發布（#2054）；技能搜尋佔位文字也清晰可讀。(#2052)
