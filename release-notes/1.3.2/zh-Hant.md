## ✨ 亮點

- **冗長對話使用更少記憶體。** 串流回覆不再累積隱藏的效能項目，而未在檢視中的對話內容會在其安全儲存後被回收——大型工作階段保持流暢回應，同時不會遺失你的位置、待處理的編輯或進行中的工作。（#4500）
- **Kilo Gateway 成為官方供應商。** 可使用或不使用 API 金鑰新增：匿名目錄重新整理會顯示你的連線可使用的免費模型，引導流程中的供應商步驟也可跳過，稍後再決定。升級時會保留現有憑證與主要模型選擇。（#4465）
- **可檢查的影像模型目錄。** OpenAI、MiniMax、Bailian 與 Volcengine Ark 的官方影像服務可在儲存前向供應商重新整理其內建模型清單，並在模型仍可使用的情況下保留你目前使用的模型。（#4474）
- **智慧代理工作階段的首則訊息更可靠。** 全新的預設 Agent、Claude Code 與 Codex 對話不再於第一次模型請求前失敗，內建 Agent 也會以預期的提示啟動排程工作階段。（#4505、#4490）
- **保留原生版面的 PDF 翻譯。** 換行的標題、說明文字、定義與數學敘述會依閱讀順序還原，公式、連結與圖形也會留在翻譯後文件中的原本位置。（#4492）

## ⚠️ 範圍與安全

- **不使用金鑰新增 Kilo 會以匿名方式連線 Kilo。** 顯示可用免費模型的目錄重新整理是對 Kilo 伺服器的請求，不帶任何帳號身分。設定完成後的影像與模型請求會像其他供應商連線一樣傳送至 Kilo。請參閱[資料接收方](https://github.com/aipoch/open-science/blob/v1.3.2/docs/security.md#data-recipients)。（#4465）
- **檢查影像模型目錄會連線供應商。** 重新整理會將所設定連線的憑證傳送給該供應商以列出其影像模型，且檢查失敗也無法撤回已傳送的內容。請只對你自行設定的連線執行此操作。請參閱[資料接收方](https://github.com/aipoch/open-science/blob/v1.3.2/docs/security.md#data-recipients)。（#4474）

## 🚀 新功能

- 新增 Kilo Gateway 為官方供應商，API 金鑰為選用；匿名目錄重新整理會顯示可用的免費模型，不使用金鑰儲存時可保留模型選擇的彈性。（#4465）
- 桌面版引導流程的供應商步驟新增「跳過」動作，可在不使用金鑰的情況下新增 Kilo，並將模型決定留給你；升級時會補上缺少的 Kilo 設定，同時不影響現有的供應商憑證或主要模型選擇。（#4465）
- OpenAI、MiniMax、Bailian 與 Volcengine Ark 的官方影像服務可隨時檢查供應商的即時影像模型目錄：相符的內建模型會在儲存前顯示、目前使用的模型會被保留，而保留為預設但不存在於重新整理後目錄中的模型也會加以標示。（#4474）
- Bailian 的影像目錄請求限定於工作區區域，與中國相關的憑證僅能使用中國目錄。（#4474）

## 🔧 改進

- 冗長對話與工作階段使用更少記憶體：串流回覆不再累積隱藏的效能項目，未使用的對話內容會在其耐久副本一致後被回收，即時工作階段更新也會重複使用序列化副本進行傳送與重播。（#4500）
- Notebook 記憶體不足的提示改為可關閉且六秒後自動消失的通知，不再佔用工作區頂列或開啟對話框；拒絕啟動僅適用於實際執行決策，復原完成時也只會通知一次。（#4499）
- 首頁會指出使用案例下載失敗的具體原因——缺少清單、套件無法使用、逾時、網路、伺服器、驗證、磁碟空間不足或儲存問題——而非籠統的失敗訊息。（#4498）
- 重播會保持歷史對話的整潔：已完成步驟的提問與擷取動作會在滑鼠懸停或鍵盤聚焦時顯示，在觸控或混合指標裝置上則提供全尺寸觸控目標。（#4483）

## 🐛 錯誤修正

- 當 Notebook 授權準備作業恢復已附加或無歷程記錄的原生工作階段時，全新的預設 Agent、Claude Code 與 Codex 對話不再於第一次模型請求前失敗。（#4505）
- 在 Notebook 憑證重新整理期間，內建 Agent 會以第一則提示開啟排程工作階段，不再中斷已附加的寫入作業。（#4490）
- PDF 翻譯會還原原生擷取作業跨列或跨頁界線切分的文字——標題、說明文字、定義與數學敘述——並在寫回時將公式、參考文字、連結與內嵌圖形保留在原本位置。（#4492）
- Notebook 啟動時不再將已關閉的 WSL 命令管道誤判為失敗。（#4500）
